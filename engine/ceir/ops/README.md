# CEIR operation-definition schema (`*.ceirop.toml`) — CEIR-2, §8 + ADR-0110 §2.1

Ops are **DEFINED in TOML here, generated to C++** by `tools/ceir_opgen/ceir_opgen.py` — never hand-kept in parallel
(the §8 "avoid stringly-typed compiler code" rule; the `scripts/gen_fft_batched.py` checked-in-generator precedent).
One file per dialect: `engine/ceir/ops/<dialect>.ceirop.toml`. The generator emits, per dialect, committed
`engine/ceir/generated/crd/ceir/gen/<dialect>_ops.{hpp,cpp}` — a typed wrapper + builder + verifier scaffold +
reflection record + a `register_<dialect>_ops(Context&)` that self-registers through the CEIR-1d `Dialect::register_op`
path (mirrors `func::register_dialect`). **Adding an op is a TOML edit + a regen — zero central-enum / switch edits
(§7 open-world).**

The generated files carry `// GENERATED by ceir_opgen.py from <toml> — DO NOT EDIT` + the schema version (no timestamp);
output is **deterministic** (ops sorted by name, attribute keys sorted) so a regen is byte-identical — enforced by the
`crd-ceir-opgen-drift` ctest (`ceir_opgen.py --check`). Edit the TOML (or the generator templates), never the output.

## File header

```toml
schema_version = 1        # bumped when the schema/codegen shape changes (a mismatch is a validator error)
dialect = "arith"         # the dialect namespace; every op below is "<dialect>.<op.name>"
summary = "..."           # one-line dialect description (docs / reflection)
```

## `[[op]]` — one table per operation

| Field | Req | Type | Meaning (§8) |
|---|---|---|---|
| `name` | ✅ | string | op name; the full kind is `"<dialect>.<name>"` (e.g. `arith.const`) |
| `summary` | ✅ | string | one-line description (docs, editor hint, reflection) |
| `version` | ✅ | int | op schema version (§104 — old versions handled, not silently broken) |
| `operands` | | array of operand | positional SSA inputs; `{ name, type = "any", variadic = false, doc = "" }` (at most one variadic, last) |
| `results` | | array of result | SSA outputs; `{ name, type = "any", doc = "" }` |
| `attributes` | | array of attr | compile-time config; `{ name, kind, required = false, doc = "" }`, `kind ∈ {int,float,bool,string,symbol,type}` |
| `regions` | | int **or** array | region count, or named `[{ name, kind = "graph"|"ssacfg" }]` |
| `traits` | | array of string | from the `OpTrait` set: `Terminator`, `Symbol`, `SymbolTable`, `Pure`, `IsolatedFromAbove` |
| `docs` | | string | long-form documentation (doc-stub generation, CEIR-2d) |
| `deprecation` | | table | `{ since, replaced_by, note }` (§8 migration metadata) |

### Semantic-heavy fields — **schema-known now, codegen scaffolded until their band**

The schema **validates** these today; the generator emits a structured TODO scaffold + a reflection record for them,
because the machinery they need does not exist yet. This is NOT deferral — the schema contract is whole; the consuming
bands land later (documented at the CEIR-2a/2b close).

| Field | Type | Lands at |
|---|---|---|
| `effects` | array (§26 families + resource/range identity) | CEIR-4 |
| `domain` | string (§15 eval domain) + `realtime` class (§32) | CEIR-4 |
| `type_inference` / `shape_inference` | string (rule name) | CEIR-3 |
| `fold` | string (fold-rule name) | CEIR-6 |

### `[op.native]` — ADR-0110 §2.1 native-binding (optional; presence marks an INTRINSIC)

An intrinsic (`present`, a codec, an NPU call — §100) is an **ordinary op with a native binding**, defined through this
SAME generator (no parallel schema). Optional table; the `IntrinsicRegistry` that consumes it lands after CEIR-4
(ADR-0110 §2.2), so today the generator validates + reflects these and emits a scaffold.

| Field | Type | Meaning |
|---|---|---|
| `provider` | `host`\|`gpu`\|`npu`\|`media`\|`external` | which bridge implements the handler (§69) |
| `determinism` | `BitExact`\|`DeterministicWithinTarget`\|`DeterministicWithinBackend`\|`Nondeterministic`\|`External` | ADR-0098 tier (§27) |
| `thread_safe` | bool | may run off the main thread / concurrently |
| `hot_reload_safe` | bool | may the caller hot-swap while it is in flight (§108) |
| `lifetime` | string | ownership/borrow rules of resource operands (§19) |
| `cost` | string | cost-hint class for the §82 scheduler |
| `capabilities` | array of string | §99 host-granted capabilities required to call it |

## Validation

A schema error is a **cook-time diagnostic** in the `file:line: error: message` shape (the declared-contract rule):
unknown field, unknown trait/attr-kind, missing required key, duplicate op name, `variadic` not last, bad
`schema_version`. Run `python tools/ceir_opgen/ceir_opgen.py` (regenerate) or `--check` (validate + drift-compare,
nonzero on any error). The generator has NO third-party dependencies (stdlib `tomllib`, Python ≥ 3.11).
