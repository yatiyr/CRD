## The mission (why the IR must be frontier-complete)

Compute the best + most interesting things end to end — **ML/AI · FFT · simulations · skinning · particles · light
systems · rendering that out-beauties Unreal · ray tracing · beautiful + stylized (toon/NPR) effects · anything a GPU can
do** — portably across ALL backends, correct + performant + bit-exact. One IR (CKIR) is the single source; GLSL / HLSL /
WGSL / MSL / CUDA / HIP are derived OUTPUTS, never authored or stored. This detour hardens that IR + the device surface it
runs on; the actual render pipelines / physics / editor are built ON it in their own phases. **No compromises — the
frontier version of every capability, by construction.**

## The two invariants (grep-gated, not prose)

> **No module outside a backend names a shading language or a bytecode.**
> **I1** — GLSL/HLSL/WGSL/MSL/CUDA source lives only inside one backend TU, between our emitter and the vendor compiler.
> **I2** — SPIR-V/DXIL/PTX bytes never appear in a public header; a consumer holds an opaque `IGpuProgram`, nothing else.

Currency **in** = the IR (`KGraph` + `KEntry`). Currency **out** = `IGpuProgram`. **Both are CLOSED** (C0…C2): the
`crd-no-shader-language-leak` gate is green with an empty allowlist, and `ShaderModule`/raw-SPIR-V is gone from every public
header. One `VkDevice` — the `VulkanGpuContext` owns it; `rhi-vulkan` adopts, never creates.

## ⭐⭐ Legacy path vs CKIR path — where we are, where we LAND (user 2026-07-12, "very important")

The engine is **mid-migration**, and there are TWO shader/render paths in the tree right now. This is deliberate and temporary:

- **LEGACY path (the shipped runtime today):** the runtime renderer + the `runtime/examples/smoke_*.cpp` render through
  **rhi** pipelines with the **hand-authored GLSL Effect system** — `reflect_triangle.vert`/`.frag` source files → `crd::shader::EffectDesc`
  → `runtime->create_effect` → `device->create_program(cooked SPIR-V)`. GLSL is written BY HAND here.
- **CKIR path (this detour, built in `tests/gpu-context-*` first):** everything is authored in **backend-neutral CKIR**
  (`KGraph`+`KEntry`); GLSL/HLSL/WGSL/MSL/PTX appear ONLY as **emitter output inside a gpu-context backend** — never
  hand-written, never stored. `create_program(KGraph,KEntry)` → `IRasterContext`/`IComputeContext` → the GPU.

What is **already unified**: the **device seam** (C2/D-008). The runtime bootstraps a `create_vulkan_gpu_context(...)` and rhi
**adopts** its `VkDevice` — ONE device, gpu-context-owned. What is **not yet migrated**: the runtime's actual **rendering** still
runs on rhi pipelines + the GLSL Effect system; it does not yet route draws/dispatches through the gpu-context contexts + CKIR.

Two more "cook"-named things that are NOT the B8-k cook: **D1** serializes the CKIR/material graph into the versioned **`.crdr`**
resource (replacing stored GLSL/HLSL text); **D2** is the offline **cook** (IR → SPIR-V/DXIL/MSL/WGSL/PTX bytecode, content-hash
cached). The **B8-k "cook seam"** is the in-memory material→per-pass-program assembly that FEEDS D1/D2 — it touches no `.crdr` yet.

> **⛔ THE ENDGAME (non-negotiable): after this detour is FULLY over, the engine is 100% CKIR.** The runtime renderer migrates
> ENTIRELY onto CKIR → gpu-context (`IRasterContext`/`IComputeContext`) + the `.crdr` cook (D1–D5). The legacy GLSL Effect
> system (`crd::shader::EffectDesc`, `create_effect`, the hand-authored `.vert`/`.frag` files, the SPIR-V-source path) is
> **DELETED** — no dual path survives. GLSL/HLSL/etc. remain ONLY as machine-emitted backend outputs behind I1/I2. The
> transitional coexistence above exists solely so the shipped engine keeps rendering while the CKIR path is hardened; it is a
> bridge, not a destination. **Full CKIR, no exceptions, once the detour lands.**

## ▶ The locked order (user 2026-07-11): FULL visual frontier FIRST, then hesap-GPU

The compute substrate hesap-GPU needs is **already proven** (GEMM at cuBLAS parity, 6 backends, bit-exact) — so hesap is a
dependency-light return whenever wanted. The user chose to complete the **entire** visual frontier first anyway. hesap-GPU
is the LAST stop of this detour, not an early exit. Two side tracks per slice: **IR** = the shader/emitter side (was
D-007); **DEV** = the device/context side (was D-008).

> **⭐ Render→compute dependencies are built DURING this detour (user 2026-07-12).** CKIR *is* the GPU compute compiler, so
> the compute PRIMITIVES the frontier rendering needs — **FFT** (convolution/physically-accurate bloom + glare · FFT ocean),
> GPU **sort** (Gaussian-splat depth · OIT · light lists), **scan / stream-compaction** (clustered light-cull · Nanite
> cluster-cull · particle compaction), **reduction** (auto-exposure histogram · SDSM / Hi-Z depth min-max · luminance), small
> **GEMM / MLP** (neural radiance cache · neural materials, w/ B10 coop-vectors) — are implemented here as CKIR compute kernels
> (bit-exact CPU oracle + both backends) as part of the slice that needs them. This serves rendering now AND hesap-GPU later
> from one source. The BROADER hesap-GPU (dense/sparse LA, eigensolvers, ODE, stats — the parts rendering never calls) stays
> post-detour. Each gap slice below flags its compute dependency where one exists.

## Stage model — complete from day one (B3-a′ ✅)

`ShaderStage` = the 14 SPIR-V execution models: `Compute · Vertex · TessControl · TessEval · Geometry · Fragment · Task ·
Mesh · RayGen · Intersection · AnyHit · ClosestHit · Miss · Callable`. Mesh/task is the amplification path; **geometry is
supported-but-discouraged** (single-thread bottleneck). **Tessellation (`TessControl`/`TessEval`) is a REAL path, not
emulated** (B4-tess): it is the portable displacement/terrain path for platforms without mesh shaders (mobile/WebGPU/older
HW), and its builtins (`TessCoord`, `PatchVertexCount`, `InvocationId`) are already in the stage model. A backend that cannot
yet emit a stage **refuses loudly** — it never silently falls back to compute. (Declare the whole domain; refuse the
unimplemented part loudly.) *Candidate (not scheduled): single-pass stereo / multiview (`VK_KHR_multiview` + a `ViewIndex`
builtin) — the frontier replacement for GS-based stereo; parked until VR/XR is a committed target.*

## Escape hatch (ADR-0101 §4) — preserved and boxed

Hand-written per-backend kernels stay legal (geometry-bvh-gpu's LBVH `.comp`, imgui/draw overlay GLSL, third-party HLSL):
they cook to blobs and load through `create_program(cooked)` — explicitly non-portable, never re-entering the engine as
source. The asset cooker keeps its GLSL→SPIR-V path; it just calls the *Vulkan backend's* compiler, not `crd-shader`.
