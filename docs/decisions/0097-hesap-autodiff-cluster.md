## Context

v15+v16 give the engine its differentiation layer — the capability that turns *every solver in the suite* into a source of exact derivatives. Forward mode (v15) buys exact gradients/Jacobians for opt (FD→exact), exact and sparse-compressed Jacobians for the v9 BDF/Radau integrators, FEA residual Jacobians at chromatic-number cost, and the whole hesap surface (tensor/dense/FFT/DSP/interp) forward-differentiable. Reverse mode (v16) buys ∂(scalar loss)/∂(millions of params) in one backward pass — calibration, system-ID, PDE-constrained + topology + aero-shape design, differentiable MPC/physics, and in-engine training. Scope was locked 2026-07-02 (maximal, user-approved, re-scoped from the ~3000-LOC sketch): v15 ~11 KLOC / ~455 tests, v16 ~16.1 KLOC / ~605 tests.

The moat is timely and unique: **bit-identical `{1..16}` GRADIENTS** — deterministic training — which PyTorch and JAX cannot deliver because their reverse pass scatters gradients through atomic adds (non-associative float order). The 2025-26 verifiable-inference / verifiable-training literature is asking for exactly this; nobody ships it. Nine things had to be settled before line one — the architecture of a differentiation framework is decided by its ownership, determinism, and edge rules, not by its rule library.

1. **One module or two** — forward mode and reverse mode could each be a module (v15 `-forward`, v16 `-reverse`), or one `crd-hesap-autodiff` housing both.
2. **The `Dual<T>` migration** — v7-b already shipped a `Dual<T>` inside `crd-hesap-opt` (`opt/forward_ad.hpp` + `opt/dual.hpp`, consumed by the trust-region/LM gradient paths). The new module must own the canonical Dual without regressing opt.
3. **What "deterministic gradient" means, and whether it is reachable without atomics** — the reverse pass's scatter-add is the technical crux of the entire moat; if it cannot be made order-independent, the moat is a claim we cannot keep.
4. **Tape operand ownership** — backward runs *after* forward's stack frames have unwound, so saved-for-backward intermediates cannot be bare `TensorView`s (ADR-0096 §Consequences flagged this). Owning `Tensor<T>` vs a bump-arena of values is a lifetime contract with v14.
5. **Module edges / acyclicity** — autodiff must *consume* the computational modules (tensor/dense/fft/dsp/interp/special) to provide their derivative rules; but opt and ode want to *consume autodiff* for exact gradients, and v16-g differentiates *through* hesap-opt's QP/NLP. That is a cycle unless the direction is pinned.
6. **Enzyme — in or out** — Enzyme is the strongest AD-through-arbitrary-C++ tool, but it is an LLVM-plugin (MSVC-incompatible), which collides with the portability cornerstone (MSVC primary; WASM goal).
7. **The codegen dependency** — v16-h emits `.crds.cpp` hot-reload cells (ADR-0081), but ADR-0081's hot-reload *runtime* is Phase 4.0, not yet built.
8. **The correctness contract** — an AD framework that is subtly wrong is worse than none; what is the standing gate for every rule.
9. **The two-layer typed boundary** — where `Dual`/`Var` (raw-scalar carriers) meet the `Quantity<D,T>` API surface.

## Decision

1. **ONE module, `crd-hesap-autodiff`, housing forward (v15) and reverse (v16) with internal sub-headers** (`dual.hpp`/`jet.hpp` substrate · `rules_forward.hpp` · `hyperdual.hpp` · `drivers.hpp` · `sparsity.hpp` · `matrix_calculus.hpp` · `taylor.hpp` · `wirtinger.hpp` · then v16 `tape.hpp` · `rules_reverse.hpp` · `implicit.hpp` · `checkpoint.hpp` · `graph_codegen.hpp`). Forward and reverse share the SAME rule mathematics (a VJP is the transpose of a JVP), the SAME 3-oracle gate, the SAME `crd::math` surface, and the SAME suite bridges — splitting them would duplicate the rule library and the differentiability bridges. Namespaces `crd::hesap::autodiff::forward` and `::reverse` partition the surface; higher-order (v16-e forward-over-reverse) needs both in one TU, which a module split would force across a link edge. The lean-consumer lever is the ADR-0096 pattern: **header-only sub-headers with PRIVATE/TU-local heavy deps** — a consumer that only wants scalar forward `Dual` drags neither the tape nor the tensor VJPs nor the solver bridges (gated by a link-isolation smoke, the v14 precedent).

2. **`Dual<T>` MIGRATES into `crd-hesap-autodiff` as the canonical home; `crd-hesap-opt` re-exports it (SANITY #8).** The v7-b `Dual<T>` moves to `autodiff/dual.hpp`; `opt/forward_ad.hpp` becomes a thin re-export (`namespace crd::hesap::opt { using autodiff::forward::Dual; }`) so every existing opt consumer compiles unchanged — **zero regressions is a v15-a gate** (the full opt suite re-runs green before v15-a closes). This adds the acyclic edge **`hesap-opt → hesap-autodiff`** (opt was already the higher-level consumer; the Dual it shipped was a stopgap the framework now owns). The `gradient_check` harness v7-b shipped migrates likewise and becomes the seed of the 3-oracle gate (§8).

3. **The deterministic no-atomics tape is the moat, and it is reachable (Decision 3 is the crown).** The reverse pass accumulates ∂loss/∂(each intermediate) by *scattering* contributions from every consumer of a value back to that value. PyTorch/JAX do this with atomic float adds ⇒ the summation order depends on thread scheduling ⇒ run-to-run gradient drift. Cerid instead uses a **SoA tape (operator records, arena-allocated via `IAllocator`) with a fixed-order accumulation discipline**: (a) each tape node owns a **deterministic adjoint accumulator** written in **tape-index order**, never by racing threads; (b) the scatter is inverted into a **gather** — for parallel execution the tape is partitioned into deterministic index ranges (the crd-jobs deterministic `parallel_for` partition, block order = function of tape length only, never `num_workers`), and cross-partition contributions merge via a **fixed-order reduction tree** (the v14 Tier-D contract lifted to adjoints), **NO float atomics anywhere**. ⇒ gradients are **bit-identical across `{1..16}` workers**, per op class, gated (`[moat]` asserts convergence too — the vacuous-maxed-out guard). This is deterministic training; it is a world-first and the whole cluster's differentiator. Where an op's adjoint is a genuine scatter-add (embedding/segment ops, v17-j on GPU), the deterministic form is **sort + segmented-reduce**, never atomics (pinned for the GPU mirror; on CPU the fixed-order tree suffices).

4. **Tape operands are OWNING `Tensor<T>` / arena-owned values — never bare `TensorView` (the lifetime contract with v14).** Saved-for-backward intermediates are copied into tape-owned storage (a `Tensor<T>` allocated from the tape's `IAllocator*` arena, or a scalar slot for `Dual`/`Var`), because backward executes after forward's frames unwind. The tape arena is caller-provided (`IAllocator*`) and freed as one block; **revolve checkpointing (v16-f)** is the memory-bounded refinement (recompute-vs-store, Griewank-Walther optimal binomial schedules) for tapes too large to hold — O(log T) live memory, the WCET pillar applied to the tape. `EinsumPlan` (v14) is captured by value into the tape node (build-once; the backward einsum reuses the plan with a permuted spec — einsum VJP = einsum).

5. **Autodiff is LOWER than the solvers; solvers register their own differentiation rules via a `custom_jvp`/`custom_vjp` API — the edge is always solver→autodiff, never a cycle.** `crd-hesap-autodiff` depends on `{tensor, dense, fft, dsp, interp, special, math, containers, core, jobs}` to provide *their* derivative rules (matrix-calculus JVPs/VJPs, FFT dual = the transform, spline-eval derivatives). It does **not** depend on `opt` or `ode`. The **implicit-differentiation machinery (v16-g)** ships as a generic IFT engine in autodiff for the pieces it can own with its own deps (linear-solve differentiation over dense/sparse factors — *differentiate the solution, reuse the factor, never AD-through-LU*); the solver-specific rules that need a solver (argmin-via-KKT through hesap-opt QP/NLP, nonlinear/Newton fixed-point) are **registered from the solver's side** via autodiff's `custom_vjp` registration API (the module that owns the solve owns its adjoint), so the edge stays `opt→autodiff` / `ode→autodiff`. This mirrors the v6/v5f acyclic-edge discipline (hesap-eigen→hesap-direct). Exact bridge-module placement (a thin `hesap-opt-diff` seam vs in-module registration) is pinned per-slice at v16-g; the *direction rule* is fixed here.

6. **Enzyme is named OUT-OF-SCOPE (portability cornerstone).** Enzyme is an LLVM-plugin AD — MSVC-incompatible, and a hard collision with the MSVC-primary + WASM-reachable portability principle. Cerid's AD is **operator-overloading + expression-graph** (Dual/Jet forward, taped reverse), portable to every toolchain the engine targets. Enzyme is acknowledged as the strongest *AD-through-opaque-C++* tool and is **not** a peer we claim to beat on that axis; our axes are determinism + suite-integration + implicit-diff + codegen, which Enzyme does not carry. (Recorded so a future session does not re-litigate an LLVM-plugin dependency.)

7. **The tape→C++ codegen (v16-h) EMITS and INTERPRETS unconditionally; hot-reload *execution* is gated on ADR-0081 landing (graceful).** v16-h traces to an expression graph, runs fusion/CSE/DCE passes, and can (a) **interpret** the optimized graph directly (always available — no dependency) or (b) **emit `.crds.cpp` hot-reload cells** (text) per ADR-0081. The emitted text is a durable artifact regardless of whether the Phase-4.0 hot-reload runtime exists yet; only the *live-reload execution* of an emitted cell waits for ADR-0081. This keeps v16-h shippable now (interpret + emit + a golden-file test on the emitted source) with the JIT-class speedup arriving when the runtime lands. XLA-lite, unique to Cerid; no new infrastructure.

8. **The 3-oracle gate is the standing correctness contract for EVERY rule.** Every JVP/VJP is checked three independent ways: **analytic** (the closed-form derivative), **v13 complex-step** (`Im[f(x+ih)]/h` — machine-exact, zero subtractive cancellation; the `crd-hesap-diff` oracle, SANITY #8 reuse), and **finite differences** (the coarse cross-check that catches a wrong *sign* the other two might share). A rule ships only when all three agree to their respective tolerances (complex-step ≡ analytic to ~1e-15; FD to ~1e-6). This is the v13 reconstruct-verify doctrine applied to differentiation: **verify the rule in python/complex-step BEFORE porting the C++**, and the harness is the seed migrated from v7-b's `gradient_check`.

9. **Two-layer typed boundary (ADR-0078 §5): `Dual`/`Jet`/`Var` are lower-layer raw carriers.** They wrap raw `f32`/`f64`/`Complex<T>` and compose through the raw math kernels; the `Quantity<D,T>` typed surface bridges at the driver boundary (`gradient(f, x)` takes/returns typed vectors, strips to raw for the sweep, retags on return — the strip-compute-retag wrapper, one line + one comment naming the boundary). No dimensional tag rides through a `Dual`'s arithmetic. Complex/Wirtinger forward (v15-h) carries holomorphic duals with ∂/∂z, ∂/∂z̄ at the same lower layer.

## v15 forward-mode — SHIPPED (2026-07-06)

All forward slices (a–h + z) are shipped and crush-verified; scoreboard `docs/bench/2026-07-06-v15z-scoreboard.md`,
system doc `docs/systems/hesap-autodiff.md`. Decisions that held / were refined in the build:

- **Decision 2 held:** `Dual<T>` migrated to `autodiff/dual.hpp`, `hesap-opt` re-exports it, zero regressions.
- **Decision 5 (edge direction) held + extended:** the matrix-calculus JVPs (v15-f) are **self-contained** (take the
  caller's stored factor + inline gemm/trisolve) rather than calling the LA solvers — the cleanest way to keep
  autodiff below `hesap-dense`/`hesap-tensor`. A new acyclic edge `hesap-autodiff → crd-hesap` (v15-z) wires the
  `hesap.ad.*` CLI registry; `crd-hesap` depends only on core/math, so it does not invert the edge.
- **D-note (v15-g, honest scope):** the generic order-by-order Taylor ODE integrator is O(K³)/step; the shipped
  **taped integrator is O(K²)/step** (`taylor_tape.hpp`) and is what crushes adaptive RK on the high-precision
  frontier. Loose-tolerance wall-clock remains a simple stepper's regime (few-digit work) — a documented tool
  boundary, NOT a defect; Taylor is more accurate at every tolerance.
- **D-note (v15-h, convention):** the forward complex carrier is the **un-conjugated pushforward** (JAX `jvp`); the
  Wirtinger pair is reconstructed from two seeds (ż=1, ż=i). Gradient-conjugation for complex *optimization* is a v16
  reverse-mode concern, deferred by design.
- **Determinism moat present in every forward slice** (`{1..16}` per-direction-independent, single-rounded fma); the
  full 6-config DoD + `{1..16}` bit-identity sweep over the final v15 artifact is **batched with v16** per the close
  plan (v15-z shipped green on win-debug, 1249 asserts/72 cases).
