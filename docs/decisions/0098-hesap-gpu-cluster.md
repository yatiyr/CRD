## Context

v14–v16 gave the engine a crushing CPU compute + differentiation suite with the `{1..16}`-worker bit-identical determinism moat. v17 takes it to the GPU — but the user's mandate (2026-07-07) is not "port the suite to Vulkan." It is to build **the compute substrate every future Cerid project stands on** (physics/eylem, rendering, geometry, ML/AI, research), **API-agnostic to its core**, **both bit-identical and the fastest**, with **CUDA as a first-class backend** (toolkit to be installed). That forces four locked decisions (user, 2026-07-07):

1. **Kernel authoring = a Cerid kernel DSL/IR lowering to all backends** (not GLSL-per-hand, not Slang-only). We build the compiler.
2. **Backends = Vulkan + CUDA + WebGPU + Metal + DirectX 12 + ROCm/HIP** — all six shipped, not seamed.
3. **Perf bar = beat the VENDOR kernels** (cuBLAS/cuFFT/cuDNN, rocBLAS) at matched precision — not merely the portable peers.
4. **Determinism = a certified bit-exact core + reproducible everywhere else** — cross-vendor bit-exact where physically achievable (IEEE-only ops + our ported transcendentals), cross-architecture reproducible (binned/RFA) for the rest.

This is a **tensor/kernel compiler** (Triton/TVM/XLA/Mojo-class), not a kernel collection — sized honestly below. It is the largest hesap slice and the strategic keystone: once CKIR exists, *every* consumer authors kernels once and runs them, differentiably and deterministically, on every GPU.

**Kickoff-check (2026-07-07):** NVIDIA RTX 4070 Ti SUPER (Ada SM 8.9) · Vulkan SDK 1.4.341.1 · `glslc` present · **CUDA toolkit ABSENT — install `nvcc` + cuBLAS/cuFFT/cuDNN as a v17-a prerequisite** (the beat-vendor bar and the PTX backend both require it). Substrate (`crd-rhi`/`crd-rhi-vulkan`/`crd-shader`) proven via `geometry-bvh-gpu`.

## Decision

### 1. `crd-kir` — the Cerid Kernel IR: a TWO-LEVEL unified compute+autodiff tensor compiler
A new **foundational module** (a peer of `crd-math`/`crd-rhi`, *below* hesap-gpu so rendering/physics/geometry author kernels on it too — "rely on it to its core"). Two IR levels:
- **CKIR-Graph (high level):** a typed tensor/array op graph — **the v16-h `graph_ad` IR extended to the GPU** (device memory spaces, tensor dtypes from ADR-0096, elementwise/reduce/contraction/scan/gather-scatter ops). Because it IS the autodiff graph, **every CKIR kernel is differentiable by construction** — GPU forward + reverse in one IR (JAX/XLA-class, but deterministic + certified). Passes: const-fold → CSE (hash-cons) → DCE → **fusion** → layout/precision selection.
- **CKIR-Tile (low level):** an explicit tile/loop/schedule IR (Triton/TVM-TIR-class) — tiling, memory hierarchy (shared/registers), cooperative-matrix / tensor-core / wave intrinsics, **fixed-tree reductions (no float atomics)**. This is where vendor-beating perf is expressed.
CKIR-Graph **lowers to** CKIR-Tile via a **scheduler + autotuner** (§4). A **CPU reference lowering** (scalar/SIMD, rides crd-math) is the always-available oracle and the determinism ground truth.

**★ Minimal RISC primitive set (2026 research refinement — tinygrad/Luminal).** CKIR-Graph reduces to a **small primitive op set (~20–25 ops)**: unary transcendentals (the crd::math surface), binary arithmetic/compare, reduce (sum/max), movement (reshape/permute/broadcast/pad/stride), gather/scatter, cast, and one contraction primitive. The whole op library (GEMM/FFT/…) is **composed from primitives**, so it inherits all six backends + autodiff + determinism for free; each backend codegen stays **small (< 1–2 kLOC each — the tinygrad "< 1 kLOC/backend, new port in weeks" precedent)**; and the autotuner can be **search-based** (superoptimization / e-graph, Luminal's "search every decision" that rediscovers Flash-Attention), not just parametric. This is the lever that makes six backends + vendor-beating perf tractable rather than a nightmare.

**Codegen strategy (own the crown, borrow the periphery).** We **own the deterministic-core codegen** (Graph/Tile → each backend) because the entire differentiator — reduction-order + SPIR-V `NoContraction` + `float_controls` control *by construction* — is exactly what a third-party codegen (Slang, MLIR/IREE) will not give bit-exactly; the RISC op set keeps it small. **Slang** (which already lowers one source to D3D12/Vulkan/Metal/CUDA/WebGPU/CPU + is differentiable), **IREE/MLIR**, and **Enzyme-MLIR** are used as **references + cross-checks** (and an optional Slang fallback backend for non-determinism-critical breadth), not as the core. **CONFIRMED (user, 2026-07-07): own-the-core codegen (a).**

### 2. `crd-hesap-gpu` — the op library, authored in CKIR
GEMM · FFT · reduce/scan · the v14 tensor surface · sparse (SpMV/SpMM) · dense LA (Cholesky/LU/QR/solve) · NN (conv/attention/norm/softmax) · the v16 reverse tape on device — **each written once in CKIR-Graph**, so each is multi-backend + differentiable + deterministic for free. hesap-gpu never touches a GPU API; it emits CKIR (gated by a link-isolation smoke).

### 3. Six backends from ONE IR — CKIR-Tile → {SPIR-V, PTX, WGSL, DXIL, Metal, HIP}
- **Vulkan** (SPIR-V, via crd-shader) · **CUDA** (PTX/NVRTC — install required) · **WebGPU** (WGSL — the browser/WASM deployment goal) · **DirectX 12** (DXIL) · **Metal** (Apple Silicon MSL) · **ROCm/HIP** (AMD). A backend-neutral **runtime** unifies buffers/dispatch/sync over `crd-rhi-compute` (Vulkan/DX12/Metal/WebGPU) + thin CUDA/HIP driver layers. Adding a backend = one CKIR-Tile code generator + one runtime driver; the op library is untouched. Conformance: **every backend bit/ulp-matches the CPU reference** per op.

**Hardware coverage + cross-platform validation (user-decided 2026-07-07).** Develop everything on the local RTX 4070 Ti + Windows, where **4 of the 6 backends are fully testable** — Vulkan (SPIR-V), CUDA (PTX), DirectX 12 (DXIL), and **WebGPU (WGSL — native *and* in a real browser)** — and **HIP-on-NVIDIA** (the Windows HIP SDK targeting the NVIDIA GPU) exercises the ROCm *codegen + runtime path* locally. Only **Metal** (needs Apple silicon) and **real AMD** (perf + AMD FP behavior + the T3-on-AMD proof) require remote hardware. Those are handled by **dedicated Part C validation slices** — **v17-n** (macOS + Metal via **free, continuous GitHub Actions macOS/Apple-Silicon CI**; Scaleway Mac-mini burst for interactive debug) and **v17-o** (Linux + ROCm via **RunPod AMD-Instinct bursts**) — each of which builds the **whole engine** and runs the **full test suite** on that platform (cross-platform sanity, not just the GPU kernels), then confirms backend conformance (bit/ulp vs the CPU oracle) + the T3 cross-vendor bit-exactness. The CPU-reference oracle makes every remote run a cheap *confirmation*, not a debugging session. Coverage gaps are logged, never claimed as passing.

### 4. The scheduler + autotuner — to BEAT the vendor kernels
CKIR-Graph→Tile lowering carries a **schedule search** (tile sizes, unroll, vectorization, cooperative-matrix shapes, pipelining) with an **autotuner** (measured, cached per (op, shape, device) → a checked-in tuning DB; deterministic replay from the DB, no tuning at runtime). Hot ops (GEMM/FFT/attention/conv) get hand-seeded schedules + tensor-core/cooperative-matrix intrinsics; the autotuner refines. The bar is **cuBLAS/cuFFT/cuDNN/rocBLAS at matched precision** — named per board, with the honest note where a hand-tuned SASS kernel still wins.

### 5. Determinism baked into the IR — T1/T2/T3 + transcendentals + certificates
Determinism is a hot 2025–26 topic that VALIDATES this moat and hands us the peers to beat: Thinking Machines' **batch-invariant kernels** ("Defeating Nondeterminism in LLM Inference", Sep 2025 — 1000 runs 100% bit-identical, adopted by SGLang) patch a *few* LLM ops; **RepDL** (Microsoft, Oct 2025) is a cross-CPU/GPU reproducible-DL *library*; **TBIK** does reduction-order-invariant matmul. **We build batch/partition-invariance into the IR for the WHOLE suite, cross-vendor, differentiable, with certificates** — a generalization none of them have.
- **The rule: NO float atomics; every kernel is batch/partition-invariant.** CKIR-Tile reductions/scans/scatters are fixed trees whose order is a function of the IR, never the launch/batch/occupancy. A float-atomic or batch-dependent-reduction kernel is a compile error, not a choice.
- **T1 run-to-run** (fixed trees) · **T2 cross-architecture reproducible** (binned/RFA accumulators, block-size-invariant) · **T3 cross-VENDOR bit-exact** for IEEE-only ops via SPIR-V `NoContraction` + a `float_controls` (rounding/denorm/contraction) audit per backend.
- **crd::math deterministic transcendentals ARE CKIR ops** (exp/log/sin/cos/…), lowered identically to every backend from one polynomial definition ⇒ **cross-vendor deterministic transcendentals on the GPU** (publishable; the `geometry-shader-helpers` GLSL-emit precedent, generalized).
- **Certified core + reproducible rest (the honest frontier):** cross-vendor bit-exact for the IEEE-only + transcendental core where the `float_controls` audit passes; T2-reproducible elsewhere. Every result carries an optional **computation certificate** — a hash-chained transcript (IR hash, backend, dispatch dims, input/output digests) = the **cheap deterministic-replay tier** of verifiable compute (DO-178C evidence). We **reserve a ZK-proof hook** for the heavyweight cryptographic tier (ZKML, survey arXiv 2502.18535) — a later drop-in, not built now.

### 6. Gold standards + DoD
**Vendor (with CUDA installed):** cuBLAS · cuFFT · cuDNN · cuSPARSE · cuSOLVER · CUB (+ rocBLAS/rocFFT when an AMD host is available). **Portable:** vkFFT · CLBlast · MAGMA · ncnn · llama.cpp-Vulkan/ggml · CUTLASS (methodology). **DoD §6 every slice:** `ValidationCapture` 0 · bit/ulp vs the CPU reference · `gpu_determinism_check` ×3 (T1) · cross-backend conformance · `CRD_PERF_BUDGET_LE` · `-IncludeRelease`.

## Consequences

- **Positive:** one differentiable, deterministic, certified compute substrate under *all* of Cerid (physics/rendering/geometry/ML/research/WASM); author-once-run-everywhere across six backends; the determinism/verifiability column no compiler (XLA/Triton/TVM) or vendor library carries; CUDA + WebGPU unlock both peak-NVIDIA and browser deployment.
- **Negative / risks (named, not hidden):** this is a **compiler project** — the largest hesap slice by far (honest estimate **~55–75 KLOC / ~18–26 weeks**, revised from the 23 KLOC Vulkan-only sketch); beating hand-tuned vendor SASS on every op is not guaranteed (per-op honest gap); T3 cross-vendor bit-exactness is bounded by driver `float_controls` support (audited, not assumed); six backends multiply the conformance surface (mitigated: the CPU reference is the single oracle, backends prove against it). hardware coverage is handled by the §3 strategy — 4/6 backends local + HIP-on-NVIDIA, Metal via free GH-Actions Apple-Silicon CI (v17-n), real AMD via RunPod bursts (v17-o); gaps logged, never silently claimed.
- **Calendar:** the strategic keystone of hesap; accepted at kickoff with full visibility that it is a multi-month compiler build, sliced a–z.

## Alternatives considered (and rejected per the user's locked choices)

- **GLSL/Slang single-source, no IR** — rejected: can't beat vendor kernels (no schedule control) and doesn't fuse with autodiff. **Hand-tuned-per-backend** — rejected: N× the whole suite, unmaintainable. **Vulkan-first, others seamed** — rejected: the mandate is all six shipped. **Portable-peer-only perf bar** — rejected: the bar is vendor kernels. **Same-device-only determinism** — rejected: the crown is cross-vendor certified.
