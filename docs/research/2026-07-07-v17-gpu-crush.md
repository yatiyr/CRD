# v17 GPU compute compiler — research + crush dossier (2026-07-07)

> **Outcome:** **adopted and outgrown** — v17 became CKIR + the D-007 GPU program system (ADR-0098→0106); the engine is 100% CKIR. *(stamped 2026-08-07, doc-hygiene pass)*

The reference map for building **CKIR** (`crd-kir`) — a compute+autodiff kernel compiler that beats vendor kernels and
carries certified cross-vendor determinism. Grounds ADR-0098 + `phase-3.1.6-v17.md`. Not a survey to admire — a list of
what to learn from and what to beat.

## 1. The IR — what CKIR learns from, and where it goes further

| system | the idea we take | where CKIR goes further |
|---|---|---|
| **XLA / HLO** | a typed tensor op-graph with fusion + layout assignment | CKIR-Graph = the same, but it IS the autodiff graph (v16-h) AND targets 6 backends, not just XLA runtimes |
| **TVM (Relay + TIR)** | two-level IR (graph → tensor/loop IR) + an autoscheduler | CKIR-Tile = TIR-class; our autotuner writes a **checked-in, deterministic-replay** DB (no runtime tuning) |
| **Triton** | tile-level programming + a block model that hits tensor cores | CKIR-Tile borrows the tile/block model; we add fixed-tree-reduction + `NoContraction` determinism as IR invariants |
| **MLIR** | dialects + progressive lowering | CKIR is a focused two-dialect design (Graph/Tile), not a general framework — WCET + determinism over generality |
| **Mojo / MAX** | one language, many accelerators, perf-portable | our answer to the same goal, but C++-native + differentiable + deterministic + certified |

**Key stance:** CKIR-Graph = the v16-h `graph_ad` IR extended with device memory spaces + ADR-0096 tensor dtypes ⇒
**every kernel is differentiable by construction** (forward + reverse in one IR). No compiler above (XLA/Triton/TVM)
ships determinism-by-construction or verifiable certificates — that is our column.

## 2. Beating the vendor kernels — the techniques

- **Tensor cores / cooperative matrix.** `VK_KHR_cooperative_matrix` (Vulkan, Ada-capable), `wmma`/`mma` PTX (CUDA),
  `simdgroup_matrix` (Metal), DXIL wave-matrix. CKIR-Tile must emit these; without them there is no cuBLAS-parity.
- **CUTLASS methodology** (not the code): the tile/warp/instruction hierarchy + software pipelining + swizzled shared
  memory — the recipe for GEMM at cuBLAS speed; our schedules encode it.
- **Autotuning that matters:** tile shape, split-K, pipeline depth, register/shared budget, cooperative-matrix fragment
  shape. Search once per (op, shape, device) → cache. Triton/TVM show ~vendor parity is reachable this way.
- **FFT:** vkFFT is the portable bar and is *near cuFFT* on many sizes — proof a portable kernel can be vendor-class;
  Stockham autosort + shared-memory radix + our deterministic twiddles.
- **The honest gap:** hand-tuned SASS (cuBLAS) can still win specific shapes; name it per board (ADR-0082-class), and
  let the autotuner + coop-matrix close as much as the API allows.

## 3. Determinism — the research crown

- **Fixed-tree reductions, no atomics** (the CPU moat lifted to GPU) = T1. Pairwise/segmented trees; the reduction
  order is a function of the IR, not the schedule.
- **Reproducible accumulation (T2):** ReproBLAS / binned FP (Demmel-Nguyen), RFA (reproducible floating-point
  accumulation), Kahan-tree — block-size- and occupancy-invariant sums. NVIDIA **CCCL** shipped reproducible reductions
  (2024-25) — the bench target for T2.
- **Cross-vendor bit-exact (T3):** SPIR-V `NoContraction` + `VK_KHR_shader_float_controls` (rounding mode, denorm
  flush, FMA contraction) audited per backend/driver; the same knobs exist as PTX `.rn`/`ftz`, DXIL flags, Metal fast-
  math off. **crd::math transcendentals as CKIR ops** (one min-max polynomial → identical lowering everywhere) is the
  piece nobody has — cross-vendor deterministic `exp/log/sin/…` on the GPU.
- **Computation certificates:** hash-chain (IR hash, backend id, dispatch dims, input digest, output digest) per
  kernel; a run's certificate is a verifiable-compute artifact. Pairs with the 2024-26 verifiable-training / bit-exact-
  inference-verification literature (proof-of-inference, trustless ML). DO-178C/ISO-26262 replay evidence.

## 5. The unique position (why this is frontier, not catch-up)

XLA/Triton/TVM/Mojo give perf-portability. Vendor libs give peak perf. **None give differentiable + deterministic +
cross-vendor-certified compute from one IR.** CKIR does: author once → 6 backends → forward+reverse AD → T1/T2/T3
determinism → a certificate. That is the substrate physics (eylem), rendering, geometry, ML/AI, and research all stand
on — and the WebGPU backend puts it in the browser (the WASM deployment goal). The crush axes: **vendor-parity-or-better
perf** + **the determinism/verifiability column no one else carries**.

## 7. 2026 landscape scan (web research 2026-07-07) — what changed our plan

**A. The RISC-primitive-op-set lesson (DECISIVE refinement).**
- **tinygrad** — every model reduces to **~12 primitive ops**; each backend port is **< 1 kLOC**; community WebGPU/Qualcomm/RISC-V ports landed "within weeks."
- **Luminal** — **15 primitive ops** (Log2/Exp2/Sin/Sqrt/Recip · Add/Mul/Mod/LessThan · SumReduce/MaxReduce/Iota/Gather/Scatter/Cast); graph-based AoT; **autodiff modelled at compile time**; the optimizer **"searches every possible decision"** (superoptimization, not rewrite heuristics) and rediscovers Flash-Attention automatically.
- ⇒ **CKIR-Graph should reduce to a minimal RISC primitive set (~20–25 ops).** Then: each of the 6 backends is a *small* codegen (< 1–2 kLOC, not ~2 kLOC each), the whole op library (GEMM/FFT/…) is *composed from primitives* (so it inherits all backends + autodiff + determinism), and the autotuner can be **search-based** (e-graph / superopt) not just parametric. This slashes the backend risk and the LOC — the honest estimate drops toward the low end of ~55 KLOC.

**B. Determinism is a HOT 2025–26 topic — it validates our moat and gives us references to beat.**
- **Thinking Machines, "Defeating Nondeterminism in LLM Inference"** (Sep 2025) — LLM inference is nondeterministic because kernels are **not batch-invariant** (matmul/RMSNorm/attention change output with batch size). Fix = batch-invariant kernels (fixed reduction strategy). **1000 runs, 100% bit-identical, 10–40% slowdown**; **LMSYS SGLang adopted it.** This is *exactly our moat* — but they patch a few LLM ops; **we build batch/partition-invariance into the IR for the WHOLE suite, cross-vendor, with certificates.**
- **RepDL** (Microsoft, Oct 2025, arXiv 2510.09180) — bit-level reproducible DL train+inference **across CPU/GPU** via correct rounding + order invariance. Our T2/T3 reference — bench against it, generalize past DL.
- **TBIK** — TP-invariant matmul (reduction-order control) for bit-identical on-policy RL. **LLM-42** (2026) — determinism via verified speculation.
- **ZKML** (survey arXiv 2502.18535) — zero-knowledge verifiable training/inference; heavyweight (crypto, hides weights). ⇒ **Position our computation certificates as the CHEAP deterministic-replay tier** (hash-chain, DO-178C evidence); leave a **ZK-proof hook** as the future heavyweight tier.

**C. The codegen build-vs-reuse fork (a NEW decision to weigh).**
- **Slang** (shader-slang.org) already lowers ONE source to **D3D12 / Vulkan / Metal / D3D11 / OpenGL / CUDA / WebGPU / CPU** AND has **Differentiable Slang** + cooperative-vector (tensor-core) support. It does much of what CKIR's backend layer would.
- **IREE / MLIR** — compiler-driven multi-backend ML (no hand kernels); **Enzyme-MLIR** does reverse-mode AD *at the dialect level* (keeps matmul-level info). The XLA/IREE model.
- **The fork:** (a) own minimal-op codegen per backend (tinygrad model — full determinism/`float_controls` control, small per backend) · (b) CKIR-Tile → **Slang** → all targets (reuse Slang's mature lowering + differentiability; less determinism control, heavy dep) · (c) lower to MLIR/IREE.
- **Recommendation:** **(a) own the deterministic core** — our whole differentiator is reduction-order + `NoContraction` + `float_controls` control *by construction*, which a third-party codegen won't give bit-exactly; the RISC op set keeps it small. Use **Slang/SPIRV-Tools/IREE as references + cross-checks**, and optionally a Slang *fallback* backend for breadth on non-critical ops. Own the crown, borrow the periphery.

**D. Agentic kernel optimization is the 2026 frontier** (ARGUS, AutoKernel, Xe-Forge, MusaCoder — arXiv 2026) — LLM-agent-driven schedule search. **Aligns with Cerid's agent-native direction:** the CKIR autotuner can be agent-driven (propose schedule → measure → iterate), a natural differentiator.

**E. WebGPU is real** — ships by default across Chrome/Firefox/Edge/Safari (~82.7% of traffic), backend-agnostic, ~80% of native LLM-inference perf (WebLLM). The WebGPU backend is high-value and validated — it *is* the WASM/browser deployment path.

## 8. Net refinements to ADR-0098 / the plan

1. **Minimal RISC primitive op set (~20–25) at CKIR-Graph** — the op library composes from it; backends are small; enables search-based autotuning. (Adopt; folds into v17-a.)
2. **Own the deterministic-core codegen; Slang/MLIR as references + optional periphery** — keep the determinism crown in-house. (Decision to confirm with the user.)
3. **Determinism moat framed as "batch/partition-invariant + cross-vendor, by IR construction, whole-suite"** — explicitly vs Thinking-Machines/RepDL/TBIK (patches/libraries for a few ops). Bench against them.
4. **Certificates = cheap deterministic-replay tier; reserve a ZK-proof hook** for the heavyweight verifiable tier.
5. **Agent-drivable autotuner** — aligns with agent-native; a differentiator, not just a copy.
