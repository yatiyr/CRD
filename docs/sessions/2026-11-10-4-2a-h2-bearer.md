## What landed

- `QmuxConfig::http2`: a TLS connection that agrees on `h2` becomes the bearer of HTTP/2 and its WebSocket tunnels
  (`Framing::Http2`, qmux_http2.cpp). One server context lists QMux, `http/1.1` and `h2` on one port.
- `QmuxHost`: each tunnel is a connection of the host with its own slot, handle and generation from the one pool,
  reported through the unchanged `QmuxHostEvents`; `open_tunnel()` for a client; a server tunnel with no slot left is
  closed with CONNECTION_REFUSED. Tunnels are reported closed before their bearer's last service.
- `Http2Connection::early_input()` and `Http2Event::early`: a request whose HEADERS starts in TLS early data is
  early, so an extended CONNECT there is answered 425 (RFC 8470). `Http2Connection::config_valid()` split from init.
- `WebSocketTunnels`: `tag()`, `bearer_ended()`, and a refused client tunnel now reports its connection Closed with
  the reason (UpgradeRefused with the status, Reset, Truncated or HandshakeTimeout).
- Other requests on the bearer: 404, the stream ended with NO_ERROR. GOAWAY with an error closes at once, without one
  once the last tunnel is gone; the bearer idles only without tunnels.
- Found while building it: a bearer's GOAWAY after the peer's close_notify made TLS refuse the send, which read as
  TlsFailed; the end path now ignores that refusal. The host fuzz oracle found the bearer's last service coming
  before its tunnels' reports; tunnels are now served first.
