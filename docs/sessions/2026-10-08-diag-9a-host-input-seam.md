## Goal

The sixth DIAG.9a batch: give programs a way to read values the host chooses at run time, record every such read in
a run record and feed them back on replay, so a seeded authored-runtime failure reproduces in a later process from the
record alone. DIAG.9a stays Partial.

## What was there (checked before coding)

- The replay-input walk already classified `random` (RandomRead), `clock` (TimeRead), `host-state` and
  `external-results` from each op's effects, but no executable op declared RandomRead or TimeRead; only the
  declare-only `scene.resolve_*` intrinsics declared host-state reads.
- No clock, time-step, input-event or external-completion read is specified anywhere: the `time` dialect defines
  time-domain types only, `frame` has no time read, and ADR-0116 names TimeRead only as an effect class. Inventing
  those ops (their units and domains) would be a language decision, so this batch adds random draws only.
- The interpreter's dispatch is an open `OpId → EvalFn` table with separate installers (async, task); the compiled
  plan is a closed dense op set. Both executors run a parallel body through the shared state-free pre-flight
  (`exec::region_state_free`), which also decides whether a launch body may pool.
- `HostObserver::attach` receives the submitting interpreter, but a production host also needs to set a source
  without an observer.
- The only seeded generator in foundation is the splitmix64 finalizer in `containers/hash.hpp`.

## What changed

- **Op**: `engine/execution/ceir/ops/input.ceirop.toml`, a new `input` dialect, generated by `ceir_opgen.py`.
  `input.random {stream, bound}`: RandomRead, `ExternalNondeterminism`, a native intrinsic of the `host` provider.
  The core dialect was not used: its ops declare no effects by contract.
- **Seam** (`crd/ceir/input.hpp`, crd-ceir): `InputKind` (stored in records), `InputSource` (one call per read on
  the executing thread, in program order; false when the host has no value), `read_input`, `reads_input`,
  `random_attrs` (stream in [0, 2^32), bound in [1, 2^32)), `reduce_draw` (unsigned remainder) and `SeededInputs`
  (stream `s`'s draw `n` is a splitmix64 mix of seed, `s` and `n`).
- **Executors**: `exec::install_input_semantics` and `Interpreter::set_input_source` (not copied to
  sub-interpreters); `plan::Op::Random` with the stream and bound packed in the immediate, and
  `plan::run(..., inputs)`. No value: `ExecError::InputUnavailable` / `RunError::InputUnavailable` at the op. A bad
  attribute: `UndefinedValue` / `BadConst`. `exec::region_state_free` refuses an input read as it refuses a §20 cell,
  so a parallel or map_reduce body that reads one (directly or through a callee) is refused in both tiers and a
  launch body that reads one runs inline. `HostProvider::set_input_source` hands the source to its submitting
  interpreter and installs the input semantics. `plan_perf.cpp`'s enum guard now names the new last op.
- **Records** (`replay_record.hpp`, schema 4): every host input read (kind, channel, delivered, raw value) after the
  cells, 65536 kept and all counted; the decoder bounds the count and refuses an unknown kind or an undelivered
  value; schema 3 is refused. `InputRecorder` wraps the live source while recording; `InputFeed` answers a replay from
  the record and never from a live source, refusing (and noting with the asking op's event) a read it cannot answer.
  `first_divergence` gains `input`: the events before the refused read are compared first, then the refusal, then the
  rest of the events, length, a different read count, outcome, results and cells.
- **Input states**: `random` is recorded only when the record holds every read and every op that itself declares
  RandomRead is an input op (a call is charged with its callee's effects but declares none itself); otherwise it is
  missing and a replay refuses the record. The `random` reason in `replay.prepare` now says that replay.record keeps
  the draws.
- **Commands and hosts**: `replay.record seed=` (u64; without it the host has no random source) answers
  `random_source`, `seed` and `input_reads`; `replay.run` answers `recorded_input_reads` and
  `replayed_input_reads`. The host executor takes the seed (`HostRecordRequest::has_seed`, `seed`) and
  `record_host_run` / `run_host_traced` take a live source; host replays feed the record's reads. The inspect host
  installs no source and records `random` missing. ceridc, crd-sandbox's diagnostic service and its inspect panel
  register the dialect.
- **Asset**: `assets/ceir/random_demo.ceir`: `main(n)` draws n values of stream 0 (bound 4) and switches on each
  (three cases, so a 3 fails `selector-out-of-range`), then returns a stream-1 draw (bound 100).
- **Manifest**: the four generated files (`input_ops.{hpp,cpp}`, `input.ops.md`, `test_input_gen_smoke.cpp`) are
  named in `scripts/generated-sources.json`.

## Tests

Which seed fails, and at which draw, is computed in each test from `SeededInputs::draw`, independently of both
executors; positions come from scanning the program text.

- `tests/execution/ceir/test_input_seam.cpp` (5 cases, `crd-ceir-tests`): seeded streams are independent and
  deterministic; both executors return the independently computed reduction of three interleaved draws for n = 0, 1
  and 5; without a source, or when the host has no value for stream 3, both fail `input-unavailable` at that op (the
  plan's fault resolves to its stable id); five bad attribute sets give `UndefinedValue` / `BadConst` at the op; a
  parallel body that draws, directly or through `@draw`, is refused by the pre-flight, the interpreter and the plan
  compile, all naming the draw. The generated `test_input_gen_smoke.cpp` adds 3 cases.
- `tests/execution/ceir-cook/test_replay_inputs.cpp` (6 cases, `crd-ceir-cook-tests`): a seeded failure of
  `main(4)` recorded with every draw, raw and in order, recording twice byte-identical, then reproduced by a fresh
  service after the file was edited, and replaying the same draws against the edit (stream 2) answers `input`
  divergence 0, recorded 0, observed 2, at the draw's scanned line and column; a passing seed returns the stream-1
  draw and reproduces; with no seed the first draw fails, the undelivered read is the record and it reproduces; a
  record that lost its last draw, names another stream, or holds a draw the replay never reads diverges `input` as
  expected, and a changed earlier draw is reported as a `value` divergence first; 65537 draws record `random` missing
  (65536 kept) and `replay.run` refuses it; a draw outside the seam (`rp.rng`) or an unheld stream is missing; the
  format's re-encode is byte-equal and schema 3, an unknown kind, an undelivered value, bad counts and a cut file are
  refused; the inspect host fails `input-unavailable` and records `random` missing.
- `tests/execution/ceir-host/test_host_inputs.cpp` (2 cases, `crd-ceir-host-tests`): a host record keeps every draw,
  the host executor's seeded record is byte-equal, replays reproduce on the recorded split and on 1 and 16 jobs, the
  edit's stream-2 read is named at its line, and a host without a source records and reproduces the failed read; a
  drawing launch runs inline (`pooled_count` 0, the independently computed draw) while a launch without a draw pools
  (`pooled_count` 1), it fails at its draw without a source, and a drawing parallel body is refused with nothing
  drawn.
- `tests/tools/ceridc/test_ceridc_diag.cpp` (1 new case): one `ceridc` process records a seeded failure (its record
  byte-equal to this process's native record), the file is edited, a second process reproduces the failure without the
  seed, a third names the stream-2 read at its line, and MCP stdio answers the native bytes.
- `test_replay_diag.cpp`: the expected `random` reason follows the new text. A longer first wording made the item
  exceed the service's item size (it was clipped), so the reason was shortened to the length of the others.

## Remaining for DIAG.9a

- State cells across invokes and a run spanning a reload: they need a host that keeps one interpreter across invokes.
- Clock and time-step inputs, input events and external I/O completions: their ops must be specified first (units
  and time domains for a clock); the seam, the record stream and the feed take another `InputKind` without a format
  change beyond its ordinal.
- A live input source at the inspect host (ceridc inspect, `program.inspect`, the sandbox panel); today a drawing
  program fails `input-unavailable` there and its record holds `random` missing.
- Backend-specific numeric replay of GPU dispatches with a declared tolerance or oracle.
- Network and physical effects stubbed only in an explicit test replay.
- Host records from crd-sandbox's panel: the request would have to run on a thread the pool enrolled.
