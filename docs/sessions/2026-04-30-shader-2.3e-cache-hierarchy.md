# Session — 2026-04-30 — `crd-shader` 2.3e cache hierarchy

## Goal

Make cache identity real before hot reload lands: explicit source/
preprocessed/SPIR-V keys, include-graph participation, and actual in-memory +
on-disk SPIR-V reuse.

## What we built / changed

- **Public diagnostics surface**
  - `SourceKey`
  - `PreprocessedKey`
  - `SpirvKey`
  - cache hit flags in `CompileDiagnostics`
- **Preprocess/include graph**
  - local `#include "..."` expansion
  - include paths participate in the preprocessed/SPIR-V identity path
  - cycle detection and non-fatal diagnostics
- **Runtime caches**
  - source text cache
  - preprocessed text cache
  - SPIR-V word cache
  - module reuse keyed by SPIR-V key
- **On-disk cache**
  - SPIR-V blobs written under `cache/shaders/`
  - reused across runtime requests without forcing recompilation
- **Tests**
  - repeated compile cache hit
  - include-content change invalidates preprocessed/SPIR-V keys
  - failed compile does not falsely report SPIR-V cache hits
- **Smoke**
  - `smoke_shader` now prints source/preprocessed/SPIR-V keys and cache-hit
    behavior across repeated requests

## Plain-English explanation

The shader system now has the first real cache hierarchy underneath it. It can
distinguish the raw source from the preprocessed source and from the compiled
SPIR-V artifact, and it can reuse those artifacts instead of recompiling on
every request.

That is the foundation hot reload needed. Without explicit keys and include
participation, reload and invalidation would have been hand-wavy and fragile.

## Decisions made

- Include graph participation is real in the cache path, not just documented.
- On-disk caching begins at SPIR-V in this slice; Vulkan pipeline cache remains
  a later layer.
- The cache stays conservative and explicit: no hidden global daemon, no
  timestamp-only invalidation shortcuts.
