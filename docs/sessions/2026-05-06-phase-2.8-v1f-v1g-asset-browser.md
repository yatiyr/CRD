### `cook-demo-assets` CMake target

In `sandbox/CMakeLists.txt`:

```cmake
file(GLOB DEMO_ASSETS_SOURCES CONFIGURE_DEPENDS
    "${DEMO_ASSETS_SRC_DIR}/*.glb" "${DEMO_ASSETS_SRC_DIR}/*.gltf"
    "${DEMO_ASSETS_SRC_DIR}/*.png" ...)

add_custom_command(
    OUTPUT  "${DEMO_ASSETS_PACK}"
    COMMAND $<TARGET_FILE:asset_cooker> cook --root "${DEMO_ASSETS_SRC_DIR}" --out "${DEMO_ASSETS_PACK}"
    DEPENDS asset_cooker ${DEMO_ASSETS_SOURCES})

add_custom_target(cook-demo-assets DEPENDS "${DEMO_ASSETS_PACK}")
add_dependencies(crd-sandbox cook-demo-assets)

target_compile_definitions(crd-sandbox PRIVATE
    CRD_DEMO_ASSETS_PACK="${DEMO_ASSETS_PACK}")
```

Building `crd-sandbox` triggers the cook automatically; `CRD_DEMO_ASSETS_PACK` carries the absolute path of the cooked file into the sandbox layer source.

`assets/cooked/.gitignore` ignores everything in the cooked directory (regenerated artifacts, not committed).
`assets/source/.gitignore` ignores `.cook_cache/`, `.gitignore.meta`, `*.md.meta`, `*.ps1.meta` (the cooker writes a `.meta` sidecar for every file it scans even when it can't cook the file; only the `.meta` files for cookable assets carry meaningful UUIDs and are committed).

Verified: `asset_cooker manifest_dump assets/cooked/demo_assets.crdr` reports 5 entries (3 MESH + 2 TXTR) with UUIDs matching the committed `.meta` sidecars.

## v1g — Unified Asset Browser

`sandbox/src/sandbox_layer.{hpp,cpp}` rewritten:

### Data model
A single `Array<AssetEntry>` replaces the former `Array<ShapeInfo>`. Each `AssetEntry` is tagged with `enum class AssetKind { Procedural, Imported }`; procedural entries carry an index 0..7 into the meshgen function table; imported entries carry a `crd::resources::ResourceId`.

### Bootstrap
`SandboxLayer::register_procedural_assets()` runs each meshgen with default params to capture vertex/index counts for the metadata display.

`SandboxLayer::try_register_imported_assets()` is best-effort:
1. Tries to mount `CRD_DEMO_ASSETS_PACK`. If absent, logs Warn and returns.
2. Constructs a `ResourceManager`, registers `MeshResourceLoader`.
3. For each of `{BoxTextured.glb, Duck.glb, BoomBox.glb}`: reads `<file>.meta`, parses the UUID, verifies `find_entry(id)` resolves, pushes an `AssetEntry`.
4. Sets `m_imported_available = true` only if mount succeeded.

Each failure mode (pack missing, meta missing, malformed meta, UUID not in pack) logs a Warn and skips that one entry — the panel still renders.

### Panel
Replaces "Meshgen Browser" with two collapsing-header sections inside an "Asset Browser" window:
- **Procedural Shapes (N)** — N Selectable rows, parameter sliders rendered for the chosen entry, mesh re-uploaded on `IsItemDeactivatedAfterEdit()`.
- **Imported Assets (N)** — N Selectable rows; on selection change the imported mesh is loaded and uploaded.

Per-selection metadata: name, source label, vertex count, index count, triangle count.

### Selection → upload
`SandboxLayer::upload_selected_asset()` switches on the entry's `kind`:
- Procedural: builds a `MeshResource` via `meshgen::make_*`, uploads via `GpuUploader::upload_mesh`.
- Imported: `ResourceManager::load_sync<MeshResource>(id)` → `GpuUploader::upload_mesh(*handle.get())`.

### API change pulled in
`GpuUploader::upload_texture` / `upload_mesh` were retyped from `T&` to `const T&`. Required because `ResourceHandle<T>::get()` returns `const T*`. Both callees only read the CPU resource, so this is purely a const-correctness widening. Smoke binaries (`smoke_asset_import`, `smoke_depth_prepass`) use mutable locals so the signature change binds without source edits — but their PCH-cached `.obj` files held the old mangled symbol and had to be rebuilt with `--clean-first`.

## Device-destroy crash on app close

### Symptom
User reported a crash during `Device` destruction when closing the sandbox.

### Root cause
`Application::detach_all_layers()` was a half-detach: it iterated `m_layer_stack` calling `on_detach()`, then `m_layer_stack.clear_all_layers()`. It did NOT clear `m_owned_layers`, which is the `Array<unique_ptr<Layer>>` that owns the layer instances. So the `Layer` destructors ran later, during `~Application`, after `m_owned_layers`'s implicit destructor sequence:

```
sandbox/src/main.cpp scope exit (reverse declaration order):
  cmds destructed         (device alive — fine)
  swapchain destructed    (device alive — fine)
  device destructed       ← VkDevice destroyed here
  instance destructed
  app destructed          ← ~Application runs, m_owned_layers
                            destructs, SandboxLayer dtor calls
                            VkDestroyImage etc. through the now-freed
                            VkDevice handle. Crash.
```

### Fix
Two-line semantic upgrade in `engine/app/src/application.cpp`: `detach_all_layers()` now also clears `m_owned_layers`. After the call returns, no layer instances remain alive — all GPU-resource-holding member objects have already been destroyed.

Two ordering fixes:
- `sandbox/src/main.cpp` shutdown order is now `device->wait_idle()` → `app.detach_all_layers()` → `crd::jobs::shutdown()`. Was previously `detach_all_layers()` first, which (even with the new semantics) would have freed GPU resources while frames were still in flight.
- `runtime/examples/smoke_imgui_overlay.cpp` reordered identically.

### Verification
`crd-sandbox --headless` exits 0 on win-debug, win-relwithdebinfo, win-release, win-asan, win-clang-cl. Headless mode goes through the full shutdown path (close after one frame, then device wait_idle → detach → jobs shutdown → scope exit). win-asan adds heap canary checks on every free; the previous use-after-free would have been caught immediately by ASan.

## Cooker bug fixes (post v1f/v1g — same day)

Two bugs surfaced during repeated incremental cook runs after v1f/v1g landed; both fixed in `tools/asset_cooker/src/cook_command.cpp`.

### Bug 1: `.meta.meta.meta...` chain growth

**Symptom:** After several cook runs the source directory contained `BoomBox.glb.meta`, `BoomBox.glb.meta.meta`, `BoomBox.glb.meta.meta.meta`, … one extra level per run.

**Root cause:** `scan_recursive` filtered with `path_extension(entry) != ".meta"`. `path_extension` uses **first-dot** semantics (intentional for compound extensions like `.mat.toml`, `.vert.glsl`), so for `BoomBox.glb.meta` it returned `.glb.meta` — not `.meta` — and the file was admitted as a "source." On the next pass the cooker then wrote a new `BoomBox.glb.meta.meta` sidecar for the recursed `.meta` file.

**Fix:** filter on the filename suffix (`name.ends_with(".meta")`) instead of `path_extension`. The filename comparison is robust to any number of leading dots in the asset name.

### Bug 2: `.meta` sidecars for non-cookable files

**Symptom:** `.gitignore.meta`, `LICENSES.md.meta`, `generate_textures.ps1.meta` appeared after each cook. These files are not assets and should not pollute the source tree.

**Root cause:** the cook loop wrote/read the `.meta` sidecar *before* looking up the cook handler. Files without a registered handler (`no_handler`) had already produced a stale sidecar by the time the loop discarded them.

**Fix:** moved the handler lookup ahead of the `.meta` resolution. `no_handler` files now log an entry with empty UUID and `continue` immediately; only files with a real handler get a sidecar minted.

### Cleanup

- Purged the chained `.meta.meta...` files and stray sidecars from `assets/source/`.
- Simplified `assets/source/.gitignore` to a single rule (`.cook_cache/`); the previous `*.md.meta` / `*.ps1.meta` / `.gitignore.meta` excludes were workarounds for bug 2 and are no longer needed.

### Verification

- `cook.log.toml` now correctly shows `.gitignore`, `LICENSES.md`, `generate_textures.ps1` with empty UUID and `status = "no_handler"`.
- After three consecutive cook runs the source dir contains exactly five `.meta` files (one per cookable asset). No chain growth.
- All six configurations re-tested: 473/473 win-debug, 473/473 win-relwithdebinfo, 470/470 win-release, 473/473 win-asan, 473/473 win-clang-cl, win-tidy build clean. 17/17 headless smokes pass on every non-tidy config. `crd-sandbox --headless` still mounts the pack and exits 0.
