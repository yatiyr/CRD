## Decisions locked at v0h

1. **Profiler bring-up + teardown order is documented in the sandbox**
   as the canonical example. Engine consumers (future audio, eylem,
   editor) follow the same pattern.
2. **`ProfilerPanelLayer` is a tiny local struct in main.cpp** —
   doesn't justify a dedicated module type. ~5 LOC. Owns the
   `ProfilerPanel`; overrides `on_render` to call `panel.draw()`.
3. **`resolve_gpu_frames()` is called BEFORE `frame_mark()`** so any
   GPU spans retired this frame land in this frame's history slot,
   not the next.
4. **Per-frame instrumentation footprint = 2 lines added**: one for
   GPU resolve, one for frame_mark. No other CRD_PERF_SCOPE calls
   added to the existing sandbox layer in v0h -- the substrate is
   ready for per-system instrumentation as those systems are
   refactored.
