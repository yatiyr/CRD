  — Wald 2007 binned SAH: per node, bucket centroids into `sah_bins` bins per
  axis, sweep the bin boundaries for the min-cost split (`Nₗ·halfArea(boxₗ) + Nᵣ·halfArea(boxᵣ)`),

  deterministic median-by-index fallback (so leaves stay capped, no infinite
  recursion); empty span ⇒ empty tree. Explicit-stack DFS, asserts depth
  `< k_max_bvh_depth=64`. Single-threaded — the jobs-parallel build (with a
  deterministic per-thread reduction tree) is scoped to v1f. Plus
  `bvh_sah_cost(tree)` — a build-quality metric (Σ leaf `prim_count·halfArea`,
  normalized by root half-area).
- **`bvh_raycast(tree, prims, ray, tmax=∞) → optional<BvhRayHit{prim_index, t}>`**
  — ordered traversal (the child the ray enters first per the node's recorded
  `split_axis` is visited first, so `best_t` prunes the far subtree); per-node
  and per-prim test via the v0f `precompute_ray_aabb` / `intersect_ray_aabb_robust`

  NaN/∞-direction-safe; the *entry* `t` it returns is exact). Returns the
  primitive's AABB hit (per-triangle ray-tri refinement inside a leaf is
  `crd-geometry-mesh`, v4).
- **`bvh_overlap(tree, prims, box, on_prim)`** — callback per overlapping
  primitive (in traversal order), + a `bvh_overlap(..., Array<u32>& out)`
  convenience.

## Plain-English explanation

A BVH is a tree of bounding boxes: each node's box encloses its children's, so
a ray (or a query box) that misses a node's box can skip the whole subtree —
that's how you turn an O(n) "test every object" loop into an O(log n) one. v1a
ships the *static* version: hand it N axis-aligned boxes, it builds a good tree
using the surface-area heuristic (it tries cutting along X, Y, Z at a handful of
candidate planes and keeps the cut that minimises expected ray-test work), and
then you can ask "what's the nearest box this ray hits?" or "which boxes overlap
this box?". The tree is deterministic — same input boxes ⇒ byte-for-byte the
same tree on every platform/config — which matters because eylem (physics) needs
replayable broadphase. The dynamic parts (updating the tree as objects move
without rebuilding) come in v1b/v1c.

## Decisions made

- **Functional API form** (ADR-0076 §11): `bvh_build(span, alloc) → BvhTree`,
  not `BvhTree::build`. The tree references prims by index and is handed back
  the span by the query helpers; consumers keep both alongside their own
  allocator.
- **Deterministic SAH split tiebreak** (ADR-0076 §5.2, realised): axis evaluated
  X → Y → Z, lower bin index wins a cost tie — implemented by replacing the
  running best only on a *strictly* lower cost. Leaf-order via a stable two-pass
  partition into scratch (no `std::sort`). Coincident centroids ⇒ deterministic
  median-by-index fallback.
- **Parallel SAH build deferred to v1f** (left to my discretion per the slice
  go-ahead): v1a's build is single-threaded — keeps the correctness/determinism
  story clean; the jobs-parallel build with its deterministic per-thread
  reduction tree gets its own focused slice alongside the Embree benchmark.
- **`-bvh` slice list expanded** in the phase doc from a single `v1a–v1f` row to
  7 rows: v1a (this) · v1b refit · v1c insert/erase via tree rotations · v1d
  quad-BVH variant · v1e closest-point · v1f Embree benchmark + jobs-parallel
  build · v1g BVH4-default + `Vec4f` SIMD ray-vs-4-AABB.
- **In-flight `-bvh` verification scope** (user directive): each `-bvh` slice is
  verified on win-debug + win-asan + win-shipping (+ win-tidy build for the
  clang-tidy gate); the full 17-config `scripts/full-sweep.ps1` runs once at
  `-bvh` close.
