# Session — 2026-04-29 — `crd-shader` 2.3a public envelope

## Goal

Start `crd-shader` with the smallest correct implementation slice: ship the
public envelope, opaque handles, and a backend-neutral runtime seam without
yet committing to GLSL/SPIR-V ingestion, reflection, or cache behavior.

## What we built / changed

- **`engine/shader/`** new module
- **Public envelope**
  - `types.hpp`
  - `effect.hpp`
  - `runtime.hpp`
  - `shader.hpp`
- **Opaque handles**
  - `ModuleHandle`
  - `EffectHandle`
  - `VariantHandle`
- **Backend-neutral metadata/value types**
  - stages, parameter classes, variant request axes, descriptor binding desc,
    push-constant desc, vertex attribute layout desc, diagnostics, reload event
- **Minimal runtime implementation**
  - in-memory effect registry
  - opaque variant issuance
  - reload observability
  - no frontend or backend coupling yet
- **Tests**
  - effect creation and metadata preservation
  - variant issuance
  - invalid-effect handling
  - reload observability
- **Smoke**
  - `smoke_shader` proves the envelope can create an effect and request a
    variant cleanly

## Plain-English explanation

This slice does not compile shaders yet. That is intentional. The first job of
`crd-shader` is to make the *shape* of shader ownership and shader-facing
runtime APIs stable before we plug in a real frontend.

After this session, the rest of the engine can speak in terms of effects,
variants, metadata, and reload events without depending on GLSL, SPIR-V, or
Vulkan types. That is exactly the boundary we wanted before opening 2.3b.

## Decisions made

- No public backend/frontend types leaked.
- The first runtime implementation is deliberately in-memory and simple.
- No ADR was promoted yet; the shader ADR set remains draft until later slices
  prove the seam with real ingestion/reflection/cache work.
