# 2026-07-15 — B16-a-2: FFT-ocean time-evolution + batched IFFT + assemble (D-007)

Detour D-007 (GPU program system / CKIR), phase B16 (water/ocean). Continued the FFT-ocean from a-1 (spectrum h₀(k),
already CPU-verified) through the full per-frame update, authored entirely in CKIR and validated on both runnable GPU
backends. Consumes our own portable bit-exact FFT (`ckir_fft.hpp`).

## Shipped (all green)

- **`build_ocean_evolve`** (`ckir_ocean.hpp`) — advance the frozen spectrum to time t: h̃(k,t) = h₀(k)e^{iωt} +
  conj(h₀(−k))e^{−iωt} (exactly Hermitian by a-1's mirror-pair storage ⇒ real inverse), then **Tessendorf's packing**:
  the 8 real fields an ocean needs (height, horizontal displacement Dx/Dz, slopes ∂h/∂x·∂h/∂z, displacement-gradients
  ∂Dx/∂x·∂Dz/∂z·∂Dx/∂z for foam) ride **4 exactly-Hermitian complex spectra** (X + i·Y ⇒ real→X's field, imag→Y's field
  after the IFFT). Written in standard FFT order (fftshift of the centered texel). Unnormalised (Tessendorf convention).
- **`build_fft2d_c2c_batched`** (`ckir_fft.hpp`, reusable) — a batched inverse 2-D C2C FFT as a **2-pass transpose-on-write
  strided** plan (batched row IFFT → batched strided+tiled column IFFT; no transpose scratch/kernel). Required extending
  `build_fft1d_radix16`'s strided path with the **per-image batch offset** (mirroring the proven `build_fft1d_convolution16_tiled`
  batching) — additive, only fires for the new `tiled && batched && col_stride>0` case.
- **`build_ocean_assemble`** (`ckir_ocean.hpp`) — unpack the 4 IFFT'd complex fields → displacement map [λ·Dx, h, λ·Dz, foam]
  + normal map [n, J]; foam = saturate((foam_bias − J)·foam_scale), J = folding Jacobian (1+λJxx)(1+λJzz) − (λJxz)².
- Config gained `choppiness` (λ), `foam_bias`, `foam_scale`.

## Honest bench — the bare IFFT is NOT a crush (board: `docs/bench/2026-07-15-fft-ocean-batched-ifft.md`)

Measured our batched inverse 2-D FFT vs a purpose-built cuFFT peer (`bench/gpu-fft/cufft_2d_c2c_batched_bench.cu`), RTX
4070 Ti SUPER, min-of-30, GPU-timed, unlocked. Per-image ms, ratio = cuFFT ÷ ours:

| N | B=4 | B=16 | B=64 |
|---|-----|------|------|
| 256 | 0.94× | 0.67× | 0.35× |
| 512 | 0.71× | 0.36× | **1.03×** |

The **bare** batched IFFT sits at the campaign's known no-FMA wall ([[feedback_bit_exact_fft_crushes_only_when_dram_bound]]):
bit-exactness forbids FMA, so in the L2-resident/compute-bound regime (48 MB L2 ⇒ everything but 512²·B=64) cuFFT wins;
we reach parity/edge only at the 128 MB DRAM spill. A plain inverse transform has **no fusion lever** (cuFFT's batched
inverse is already minimal-pass), unlike the batched *convolution* (fwd·×H·inv fused).

## FUSION CRUSH — the SOLVE, built + measured (same session)

`build_ocean_evolve_rowfft` folds the time-evolution INTO the row-IFFT's first global load: computes h̃(k,t) + the field-f
packed value inline as it reads each element into shared, then runs the radix-4 row IFFT (field selected by WorkgroupIndex/N).
The ocean update collapses **4 dispatches → 3**, deleting the evolve dispatch AND the whole packed-spectrum global round-trip.
Shared `detail::dispersion`/`evolve_pack` helpers (refactored out of the standalone evolve) + identical radix-4 stages ⇒
**bit-exact vs the un-fused pipeline** — CPU-oracle `[ocean][fusion]` bad==0, and on Vulkan (`[.ocean-fused-bench]`) fused res
== un-fused res BIT-EXACT. Measured (last_gpu_ms min-of-30, radix-4 both sides, batch=4): **N=256 1.13× · N=1024 1.10×** over
the un-fused ocean. This is the fewer-global-round-trips win a cuFFT-based ocean cannot match (cuFFT must run a separate
evolve kernel writing the spectrum we delete). Board: `docs/bench/2026-07-15-fft-ocean-batched-ifft.md`.
