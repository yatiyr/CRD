# Session — 2026-05-13 — Phase 3.1.7 v1d: `Bvh4Tree` (quad-BVH collapse + scalar ray-vs-4-AABB)

## Goal

Fourth `crd-geometry-bvh` slice: the 4-wide topology variant. Each interior
node holds up to 4 children, so a traversal step touches one node and tests up
to four boxes — fewer fetches, and a shape the v1g `Vec4f` ray-vs-4-AABB kernel
will fill in lockstep. v1d ships the *scalar* path; v1g promotes BVH4 to the
default and adds the SIMD kernel.

## What we built / changed

- **`include/crd/geometry/bvh/bvh4.hpp`** (new, public; added to the umbrella
  `bvh.hpp`): `Bvh4Child { AABB3<f32> bounds; u32 first; u16 count; }` (`count > 0`
  ⇒ leaf slot, `first` = start in `prim_indices()`; `count == 0` ⇒ node slot,
  `first` = child node index), `Bvh4Node { AABB3<f32> bounds; Bvh4Child children[4];
  u8 child_count; }`, `inline constexpr usize k_max_bvh4_stack = 256`, `class
  Bvh4Tree` (accessors mirror `BvhTree` — `nodes` / `prim_indices` / `root` /
  `bounds` / `is_empty` / `node_count` / `prim_count`), `bvh4_collapse`,
  `bvh4_raycast`, and `bvh4_overlap` (callback template inline + `Array<u32>&`
  out-of-line). Reuses `BvhRayHit` from `bvh_query.hpp`.
- **`src/bvh4.cpp`** (new): `bvh4_collapse(const BvhTree& binary, IAllocator*)`
  — copy the source's leaf-order permutation into the result, then a top-down
  collapse driven by an explicit job stack of `(binary interior node, bvh4 node
  to fill)`: for each job, build a worklist starting with the binary node's two
  children, then repeatedly find the worklist member that is a binary *interior*
  node with the largest `aabb_half_area` (tiebreak: lower source-node index —
  deterministic), and "open" it (replace it with its two children), stopping at
  4 children or when no member can be opened (`wc < 4` before each open ⇒
  `wc + 1 ≤ 4` after — never overshoots). Then fill the bvh4 node's children
  from the final worklist: leaf entries become leaf slots; interior entries get
  a freshly-allocated bvh4 node (queued as a new job) and become node slots.
  `nodes.reserve(binary.node_count())` up front ⇒ no realloc during the collapse
  (asserted); the node-children are allocated/queued before the `Bvh4Node&`
  reference is taken, so no dangling either way. Edge cases: empty source ⇒
  empty result; single-leaf source ⇒ one node with `child_count == 1`. Plus
  `bvh4_raycast` (per node: four sequential v0f `intersect_ray_aabb_robust`
  tests against the children's bounds, into the `[0, best_t]` window; leaf hits
  test the prims; node hits push) and `bvh4_overlap` (the `Array<u32>&` overload
  calls the header template), and `Bvh4Tree::bounds()`. Uses `detail::aabb_*`
  from `src/aabb_ops.hpp` (v1b).
- **`bvh.hpp`** — include `bvh4.hpp` + roadmap comment updated (v1d done; v1e/v1f/v1g
  remaining).
- **`tests/geometry-bvh/test_bvh4.cpp`** (new, 5 cases): structural invariants
  on random corpora (`child_count` ∈ {2,3,4} normally, {1} only for the
  single-leaf root; node-child refs point forward and `child.bounds ==
  nodes[child.first].bounds` exactly; each node's `bounds` = exact union of its
  children; every prim referenced exactly once; `node_count ≤
  binary.node_count()`; root encloses every prim); `bvh4_raycast` ==
  `bvh_raycast` over the source binary tree (parameter bit-match + the named
  prim is genuinely hit at that `t`, incl. `tmax`-clamped rays); `bvh4_overlap`
  == `bvh_overlap` (sorted prim-index sets; callback + `Array` forms agree);
  deterministic collapse (`memcmp` of node + index arrays across two collapses
  of the same binary tree); empty / single-leaf / two-prim edge cases.

## Plain-English explanation

A binary BVH branches 2 ways at each node; a quad BVH branches 4. Wider nodes
mean shallower trees and — more importantly for modern CPUs — you can test all
four child boxes against a ray with one SIMD instruction instead of four scalar
ones. v1d doesn't build a quad tree directly (the SAH builder naturally produces
binary); instead it *collapses* a finished binary tree: walk down, and at each
node, if a child is itself a small subtree, "open" it — pull its children up
into the parent — until the parent has four children. The result is a valid
4-wide tree with exactly the same primitives in the same leaf order, so queries
return identical answers; only the traversal pattern changes. v1d's queries do
the four box-tests in plain scalar code (one slab test after another); v1g will
swap that inner loop for a `Vec4f` kernel that does all four at once, and make
BVH4 the default fan-out.

## Decisions made

- **Collapse, not direct build.** The binary SAH build stays as-is; `bvh4_collapse`
  is a separate post-pass producing a separate `Bvh4Tree` type. (The vestigial
  `BvhBuildOptions::topology` field stays for now; v1g will wire it or remove it.)
- **"Open the biggest interior child" with a deterministic tiebreak** (largest
  `aabb_half_area`; ties → lower source-node index). The half-area comparison is
  exact/deterministic; the index tiebreak makes the whole collapse bit-stable
  across configs (verified by the deterministic-collapse test).
- **`Bvh4Tree` is self-contained re: leaf order** — it copies `binary.prim_indices()`
  in, like the binary side carries its own. The prims span is still the caller's.
- **Queries match the binary tree by construction** (the collapse changes only
  fan-out) — the tests assert this directly rather than re-deriving correctness.
- v1d ships the scalar four-slab path; the `Vec4f` SIMD kernel + BVH4-as-default
  is explicitly v1g (and the `crd-simd-emission-check` `.obj` for it lands then).
