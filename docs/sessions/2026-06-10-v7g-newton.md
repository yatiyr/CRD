## The bug the gates caught (and the diagnosis arc)

The dense Rosenbrock case failed with `LineSearchFailed` at iteration 4 — far from convergence, **zero
line-search evals**. Driver instrumentation (printf trace) showed the τ-retry loop failing 60× on a finite,
healthy-diagonal (but indefinite) Hessian: the escalation read `tau = tau > beta ? 2·tau : beta` — when
`tau == beta` the strict `>` keeps it AT β forever, so the needed τ (≈50, vs β≈0.33) was never reached. Fixed to
the literal N&W rule **τ ← max(2τ, β)** in `newton.hpp` + both retry sites in `newton_sparse.hpp`. The one-step
quadratic and saddle-escape gates pass through the fixed path.

## Two test-design lessons (recorded in test comments)

1. **Chained Rosenbrock n ≥ 4 has a second LOCAL minimizer** (f ≈ 3.98589 at n=8, x₀ ≈ −1 branch) and Newton — an
   honestly LOCAL method — converges there from the classic alternating start (measured; Newton-CG/L-BFGS reach
   all-ones by trajectory luck only). Newton correctness tests use n = 2 (single global minimizer).
2. **The f64 line-search resolution floor:** below ‖g‖∞ ≈ √(eps·|f*|), f-differences per step drop under eps·|f*|
   and NO line search can certify progress (measured: gnorm stalls at ~1e-9 with grad_tol 1e-10 at |f*| ≈ 26.5 ⇒
   `LineSearchFailed` at a tolerance the arithmetic cannot support). Tests on |f*|-large problems use
   grad_tol = 1e-8. The driver's `LineSearchFailed` is the honest report (scipy returns "precision loss" here).
