## What landed (D1)

`engine/kir/include/crd/kir/ckir_serialize.hpp` (`crd::kir`):
- `serialize_graph(KGraph, KEntry, alloc) → Array<u8>` and `deserialize_graph(bytes, KGraph&, KEntry&) → bool` — a versioned
  little-endian container: `FourCC 'KGPH'` + version + a **`sizeof` layout manifest** (KNode·KStmt·KType·KEntry) + `n_inputs` +
  the **five POD pools** (nodes · ext · struct-fields · struct-begins · stmts), each `[count][raw bytes]`, + the `KEntry` bytes.
- `KGraph` gained `serial_{nodes,ext,sfields,sbegin,stmts}()` (read) + `serial_restore(...)` (rebuild from deserialized pools).
- `reflect(KGraph, KEntry) → ShaderReflection` — the descriptor-set layout (`BufferDecl`/`UniformBlock`/`Texture`/`Sampler`/
  `AccelStructDecl` → bindings, deduped, `writable` from the decl), vertex attributes (`StageIn` in a vertex stage), and workgroup
  size / stage — **derived straight from the IR, no SPIRV-Cross**.

## Why a POD-pool container (the format decision)

A cooked shader is **regenerable from source**, so the correct + fast format is a raw copy of the (trivially-copyable) IR pools,
guarded by a version + a struct-layout (`sizeof`) manifest — a layout drift is **detected and cleanly rejected** (⇒ recook), never
silently mis-read. Field-by-field serialization earns its cost only for long-lived hand-edited files, not ephemeral cook artifacts.
This is exactly what the whole CKIR **append-at-END / cook-stable** enum discipline was preparing for: op/type/stmt enum values are
frozen, so the pools mean the same thing across builds at a given format version. `static_assert(is_trivially_copyable)` on all four.
Pinned in **ADR-0104** (extends ADR-0101 "the IR is the source of truth").

## Verification

`[kir][serialize][d1]` (20 assertions): build a compute kernel (2 storage bindings + a builtin + `subgroupAdd` + a store) →
serialize → deserialize into a FRESH graph → **re-emit is BYTE-IDENTICAL GLSL AND HLSL** (the load-bearing proof that the loaded IR

blobs cleanly rejected. clang-tidy (LLVM-20.1.8) clean; full kir regression green.

D1 is the foundation: a shader graph is now a serializable, versioned, self-reflecting resource. **D2 (next)** = the standalone
`crd-shader-cook` CLI: IR → SPIR-V/DXIL/MSL/WGSL/PTX at build time, cook-time validation, content-hash cache, parallel cook, writing
