# Session — 2026-04-29 — `crd-shader` 2.3d variant key + mechanism policy

## Goal

Lock in structural variant identity and make the hybrid mechanism policy real
in code before cache and hot-reload are built on top of it.

## What we built / changed

- **Variant key surface**
  - `VariantKey` is now a real structural identity artifact instead of a bare
    placeholder
  - `make_variant_key()` computes a deterministic structural key from
    `VariantRequest`
- **Mechanism policy surface**
  - `VariantAxis`
  - `Mechanism`
  - `MechanismDecision`
  - `decide_mechanism()`
- **Runtime integration**
  - every successful variant request now retains its structural `VariantKey`
  - `Runtime::variant_key()` exposes that structural identity
  - specialization values remain outside the structural key by design
- **Tests**
  - stable key for identical structural requests
  - changed structural axis changes the key
  - specialization changes do not change the structural key
  - mechanism policy matches the pinned shader decisions
- **Smoke**
  - `smoke_shader` now prints the structural variant key and mechanism-policy
    outcomes alongside the reflection metadata counts

## Plain-English explanation

The shader system now knows the difference between "this is a different shader
structure" and "this is the same structure with different numeric constants."

That is the point where the cache hierarchy becomes safe to design. Without a
stable structural key and a written mechanism rule, every future cache,
hot-reload, and pipeline policy would sit on moving sand.

## Decisions made

- Structural axes only go into the structural variant key.
- Specialization values are intentionally excluded from the structural key.
- Material parameters stay in binding/push-constant space, not in the
  structural key.
- The ADRs remain draft, but this slice now gives them a real implementation
  anchor.
