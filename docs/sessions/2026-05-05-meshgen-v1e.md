## What was built

### `engine/meshgen/` — new module

8 CPU-side procedural geometry generators, each returning a `crd::renderer::MeshResource`
with a single `MeshPrimitive`. All use the 48-byte interleaved vertex layout defined by
`kMeshVertexStride`:

| Bytes | Field          |
|-------|----------------|
| 0–11  | float3 position |
| 12–23 | float3 normal  |
| 24–31 | float2 uv0     |
| 32–47 | float4 tangent (w = bitangent sign, always +1 in v1e) |

**Generators:**

| Function         | Description |
|-----------------|-------------|
| `make_plane`    | Subdivided quad grid. `divs_x × divs_z` quads, CCW winding from +Y. |
| `make_box`      | 6 separate faces (24 verts / 36 indices), per-face flat normals. |
| `make_sphere`   | UV sphere, `lat_bands × lon_bands`. |
| `make_icosphere`| Icosahedron → midpoint subdivision. `HashMap<u64,u32>` edge-midpoint cache (key = `(min<<32)|max`) ensures shared edges produce a single midpoint vertex. |
| `make_cylinder` | Side quads + top/bottom triangle fans. |
| `make_cone`     | Side triangles + bottom fan. |
| `make_capsule`  | Hemisphere caps (upper/lower) + cylinder body. |
| `make_torus`    | `maj_segs × min_segs` quad ring. |

**Winding convention:** all shapes use CCW front-face (Vulkan default from +Y looking down).

**Key implementation detail:** `meshgen.cpp` uses a local `struct V` (48 bytes, static_assert'd)
with helpers `push_v()`, `push_i()`, `vcount()`, and `finalize()` to build the interleaved
buffers without polluting the public API.

### `runtime/examples/smoke_meshgen.cpp`

Headless smoke: generates all 8 shapes, checks per-shape:
- `primitives.size() == 1`
- `vertex_count > 0`, `index_count > 0`
- `vertices.size() == vertex_count * 48`
- All normals unit-length (tolerance 1e-4)

Exits 0 on all-pass. NOT registered with CTest (headless smoke protocol).

### `tests/meshgen/test_meshgen.cpp`

11 Catch2 test cases (17 265 assertions via parameterized loops):
- All 8 generators: primitives.size()==1, vertex/index counts non-zero
- All 8 generators: normals unit-length
- All 8 generators: tangent w == +1
- All 8 generators: all indices in `[0, vertex_count)`
- Sphere: all normals == normalized position (sphere-specific invariant)
- Icosphere: all vertices on unit sphere (distance from origin ≈ radius)
- Plane subdivision: `make_plane(a, 1, 1, 1, 1)` → 4 verts; `make_plane(a, 1, 1, 2, 3)` → 12 verts
- Box: exactly 24 verts / 36 indices

### `crd-sandbox` Meshgen Browser panel

`SandboxLayer` constructor generates all 8 shapes using a local `MallocAllocator tmp`,
extracts `{name, vertex_count, index_count}` into `Array<ShapeInfo>`, and discards the
mesh data (only metadata retained). No persistent mesh data held — these are CPU-side counts only.

New fixed-position ImGui window "Meshgen Browser" (320×280, at pos 8, 176 — just below the
existing "Sandbox" panel):
- Shows count of shapes
- Selectable list of shape names
- Per-selection detail: Name, Verts, Indices, Tris (indices/3)

`sandbox/CMakeLists.txt` updated: added `crd-meshgen` to `target_link_libraries`.

## Decisions made

- **Drop `find_id_by_name`** (YAGNI — resources live in packed artifacts; name→UUID lookup
  belongs in the asset cook pipeline, not ResourceManager).
- **Drop click-to-switch scene mesh** (no 3D renderer wired yet; deferred to Phase 2.8+).
- **Drop demo asset download/cook** (BoxTextured.glb, Duck.glb, Suzanne.glb deferred to
  Phase 2.8 when the material/GPU pipeline is complete).
- **Sandbox stores only metadata**, not the full `MeshResource` — shapes are discarded after
  count extraction, keeping sandbox memory footprint at zero for this panel.
- **`normalize3` removed** from `meshgen.cpp` anonymous namespace (was defined but never called;
  clang-cl `-Werror,-Wunused-function` caught it).

## Issues encountered

### clang-cl: unused-function error on `normalize3`

`normalize3` was defined in the anonymous namespace of `meshgen.cpp` but never called in the
final implementation. MSVC `/W4 /WX` doesn't flag unused statics; clang-cl's
`-Werror,-Wunused-function` does. Fix: removed the dead function entirely.

### CMakeCache `CMAKE_MAKE_PROGRAM-NOTFOUND` (win-debug)

Initial `cmake --preset win-debug` ran without Ninja in PATH, caching a broken build tool
path. Fix: deleted `build/win-debug/CMakeCache.txt`, used a batch file that calls `vcvars64.bat`
and adds Ninja to PATH before cmake — this ensures the cache is populated with the correct path.
