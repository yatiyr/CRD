## What we built / changed

- **`src/bvh_build_internal.hpp`** (new, internal) — the reusable binned-SAH
  kernels extracted from `bvh_build.cpp`: `BinHistogram` (per-axis bin
  populations + per-bin prim bounds), `clear_histogram` / `merge_histogram` /
  `accumulate_histogram` / `bin_index`, `sweep_for_split` (the X→Y→Z,
  lower-bin-tiebreak SAH sweep over a built histogram), `centroid_bounds_of`,
  `stable_partition_by_bin`, `SplitChoice`, `k_max_bins`, `k_sah_cost_epsilon`.
  `bvh_build.cpp` refactored onto them — no behaviour change to the serial
  builder (modulo the `aabb_merge` fix below).
- **`include/crd/geometry/bvh/bvh_build_parallel.hpp`** (new, public; in the
  umbrella) + **`src/bvh_build_parallel.cpp`** — `bvh_build_parallel(prims,
  alloc, opts, num_jobs = 0, parallel_threshold = 8192) → BvhTree`. Same
  explicit-stack DFS as `bvh_build`, but for a node with ≥ `parallel_threshold`
  primitives it fans the two O(count) per-node reductions — the centroid bounds,
  and the 3-axis bin histograms — out over `crd::jobs::parallel_for(num_jobs,
  num_jobs, fn)`. (`parallel_for(num_jobs, num_jobs, …)` calls `fn(i, i+1)` for
  each i, so `begin` *is* the chunk index; each worker reduces the element
  sub-range `idx[first + i·total/nj … first + (i+1)·total/nj)` into its own slot
  of a per-job partial array — on the *tree's allocator*, reused for every big
  node, never the frame arena, so a big build doesn't grow it — then the main
  thread folds the partials in fixed job order.) Because the reductions are
  min/max (componentwise box union) + integer adds — exact and commutative — the
  histograms, hence the SAH split, the partition, and the node layout, are
  byte-for-byte equal to the serial `bvh_build` *regardless of `num_jobs`*.
  `num_jobs == 0` ⇒ `jobs::num_workers()`; `num_jobs ≤ 1` or a sub-threshold
  input ⇒ falls back to `bvh_build`. Requires `jobs::init()` (it calls
  `parallel_for`, which uses `jobs::frame_alloc` only for the small per-call
  `JobDecl` arrays). `crd-geometry-bvh` gains `crd-jobs` PRIVATE (not in any
  public header).
- **Fixed a latent `aabb_merge` bug** (`src/aabb_ops.hpp`). It did
  `aabb_include_point(a, b.min); aabb_include_point(a, b.max);` — correct for two
  well-formed boxes, but the "empty" sentinel `aabb_empty() = {min = +∞,
  max = −∞}` has `min > max`, so including its `min` (`+∞`) as a *point* pushes
  `a.max` to `+∞` (and including its `max`, `−∞`, pushes `a.min` to `−∞`),
  turning `a` into the *universe* box instead of leaving it unchanged. This
  misbehaved on every merge of an empty bin: in the serial `sweep_for_split`,
  the prefix `left_bounds` got corrupted whenever a middle bin was empty (masked
  — the build still produced a *valid* tree, just suboptimally split, and the
  tests check invariants/brute-force-equivalence not specific splits); in the
  parallel histogram fold, `merge_histogram(result, partials[i], bins)` for a
  bin with no prims in chunk `i` corrupted `result.bounds[bin]` to the universe
  box → a wrong histogram → a divergent tree (this was the v1f failure that
  surfaced it). Fixed `aabb_merge` to a proper componentwise corner-min/max
  union — robust to the empty sentinel, bit-identical for well-formed boxes.
  **Side effect:** `bvh_build`'s trees are now *correctly* SAH-split — slightly
  different node arrays than before; all invariant / equivalence /
  deterministic-replay tests still pass.
- **`tests/bench/test_bench_bvh.cpp`** (new, `[bench][bench-bvh][!benchmark]` —
  not in ctest; `crd-bench` gains `crd-geometry-bvh` + `crd-jobs`) — Cerid's own
  numbers: `bvh_build` vs `bvh_build_parallel` on 100k/1M random AABBs;
  `bvh_raycast` (binary) vs `bvh4_raycast` over a 100k-AABB tree; `bvh4_collapse`
  time; `bvh_closest_point` throughput. The §4.1 reference targets ("within 2× of
  Embree", ~2 ns/ray-AABB, ~8 ns/node, build 100k ≤ 50 ms, …) are in the file's
  comments; no Embree dependency (a direct head-to-head can later build against a
  local Embree behind an opt-in CMake flag).
- **`tests/geometry-bvh/test_bvh_parallel.cpp`** (new, 4 cases) — hosts the
  binary's `BvhJobsListener` (Catch2 `EventListenerBase`: `jobs::init(Config{.num_threads=4, .frame_alloc_bytes=64<<20})`
  in `testRunStarting`, `jobs::frame_reset()` in `testCaseEnded`,
  `jobs::shutdown()` in `testRunEnded` — so the binary runs with the job system
  up, and not via `jobs::init()` at file scope, which would fire during
  `catch_discover_tests`' listing). Cases: `bvh_build_parallel` is bit-identical
  to `bvh_build` (`memcmp` of nodes + indices) on random corpora for
  `num_jobs ∈ {1, 2, 4, 8}` with `parallel_threshold = 64` (exercises the
  parallel path even on small inputs); a 20k-AABB corpus above the *default*
  threshold matches serial; degenerate inputs (empty / single / coincident
  centroids) match serial; `num_jobs = 1` and a sub-threshold input both take the
  serial fast path.

## Plain-English explanation

The serial BVH build walks the tree top-down, and at each node does an O(count)
pass over its primitives twice (computing the bounding box of the centroids, and
binning the centroids into buckets to evaluate the surface-area heuristic). For a
huge mesh, the top nodes have hundreds of thousands of primitives, so that pass
dominates. `bvh_build_parallel` splits *that pass* across worker threads — each
thread bins its slice of the primitives into a private histogram, then the main
thread adds the histograms together. Adding bin counts and merging bin boxes is
order-independent (min/max), so the combined histogram is exactly what the serial
build would have computed — which means the *whole tree* comes out identical,
bit for bit, no matter how many threads you use. (The tree-walking and the
primitive-reordering stay single-threaded; only the per-node heuristic evaluation
is parallel.) Finding bugs along the way: a long-standing `aabb_merge` quietly
mis-handled the "empty box" placeholder, which the serial build got away with
(it just made some splits suboptimal) but the parallel histogram fold did not —
fixing it makes the serial trees better too.

## Decisions made

- **Parallelize the per-node SAH-evaluation reductions, not subtrees.** A
  subtree-parallel build would produce a *different* node layout than the serial
  one (or need a compaction pass); the reduction-parallel form is bit-identical
  for free (min/max + integer adds are exact + commutative), which makes
  "parallel build == serial build" a guarantee, not a hope. The phase doc's
  "over subtrees" wording is updated accordingly. The stable partition stays
  serial in v1f (a parallel stable partition is a future optimization if
  benchmarks demand it).
- **Per-job partials on the tree allocator, reused per node — never the frame
  arena.** A `BinHistogram` is ~5 KB; one in the frame arena per big node would
  accumulate to megabytes for a million-primitive build. The reusable buffers on
  the build's own `IAllocator*` keep the frame-arena footprint to just the small
  `JobDecl` arrays `parallel_for` allocates.
- **The Embree comparison is comments + Cerid's own benchmark, not an Embree
  dependency.** Matches `tests/bench/test_bench_simd.cpp` — measure ours, write
  the goal-line. A direct head-to-head can opt into a local Embree later.
- **`aabb_merge` is now a proper componentwise box union** (robust to the empty
  sentinel) — the right shape, and the bug it fixes makes `bvh_build`'s trees
  correctly SAH-split.
