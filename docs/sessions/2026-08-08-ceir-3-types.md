# 2026-08-08 — CEIR-3a (interned structural type system, §16)

Band 2 (CEIR-2, op-definition generator) closed; opened band 3 (type/shape/unit/lifetime). CEIR-3a turns `TypeId` from
a raw opaque u32 (CEIR-1: 0=none, an un-interned handle) into a **real interned structural type** — scalars + the §16
aggregate family — carried on every value. Generics/interfaces/callables are 3b; resource/view 3c; shapes 3d; unit tags
3e; ownership 3f.

## Design (advisor-settled forks)

- **One slice, one gate** (tracker row 3a is not sub-divided; the CEIR-14 expansion directive is later). Staged
  internally: record+intern → print/parse → binary v2 → migration → hardening.
- **Scope** = the full §16 scalar + aggregate list, EXCEPT arbitrary/fixed-precision (roadmap self-defers, "where later
  useful") and callable/generic/interface types (3b). Option/Result are first-class kinds, not Variant sugar.
- **Full migration, no fallback.** `TypeId` is always an interned index; `Context::type_of` **asserts** out-of-range
  (programmer error), the printer/serializer route through it; parser/decoder **reject** with pointing / byte-offset
  diagnostics. Every `TypeId{n}` magic literal is gone.
- **Uniform C++ API, per-element v2 FORMAT.** The in-memory model stays uniform (one `result_type` per op, one arg type
  per block), but the binary form writes one type ref PER result and PER block-arg — so distinct per-result/arg typing
  lands later with NO v3 bump (honors 1f's "ONE bump at CEIR-3" promise).
- **⛔ `Type::kind` is a FIELD, not a method** — a jump table over the closed value-enum is I6-safe; a `kind()` accessor
  would trip the open-world grep (which scans `engine/ceir/{include,src}`). (The I6 grep also bit a *comment* in
  type.hpp that spelled the forbidden pattern while explaining the rule — reworded; the known scar.)

## What landed

**`engine/ceir/include/crd/ceir/type.hpp`** (new) — `TypeKind` (Bool/Int/Float/Index; Vector/Matrix/Complex/Quaternion;
Array/Tuple/Struct/Enum/Variant/Option/Result), `FloatKind` (F16/BF16/F32/F64/F8E4M3/F8E5M2), and a `Type` record
(kind field + scalar params + arena `ConstSpan<TypeId>` members + name/label `StringView`s) with structural `operator==`
(the name participates — two same-shaped structs with different names are different types).

**`Context`** — a `m_types` intern table (the AttrValue pattern: dedup by structural equality, `TypeId.value = index+1`).
`intern_type` DEEP-STABILIZES a borrowed `Type` (arena-copies the child span, arena-interns each label + the name), so a
caller may build a temp `Type` over stack data. Factories: `type_bool/index/int(w,signed)/float(fk)` + i32/i64/f32/f64
conveniences; `type_vector/matrix/complex/quaternion/array/tuple/struct/enum/variant/option/result`; `type_of`.

**Printer / parser** — one canonical `!`-sigil grammar, zero-space, nested types keep the sigil: `!bool !i32 !u16 !f32
!bf16 !f8e4m3 !index`, `!vec<4x!f32>`, `!mat<4x4x!f32>`, `!complex<!f32>`, `!quat<!f32>`, `!array<8x!i32>`,
`!tuple<!i32,!f32>`, `!struct<Point,x:!i32,y:!f32>`, `!enum<Color,red,green>`, `!variant<!i32,!f32>`, `!option<!i32>`,
`!result<!i32,!u32>`. The parser recurses on the head token after `!`, interns via the Context, and is **depth-guarded**
(a pathological `!vec<2x!vec<2x…` cannot blow the stack — the 1h OOM lesson, type edition).

**Binary v2 (`TYPE` chunk, version 1→2, chunk-count 4→5).** A `TYPE` pool of type records, **child-first** (every child
is interned + its record appended before the parent's index is assigned, so a record only references strictly-lower
indices — the decoder rejects a forward/self ref by construction, and in-memory cycles are impossible). Emitted
STRP→TYPE→SRCM→ATTR→BODY: TYPE references STRP (names/labels); the **ATTR chunk's `of_type` payloads remap through the
TYPE pool** (not a raw Context id) — the fix that keeps 1f content-purity for type attrs. BODY writes per-result /
per-arg 1-based type refs (0=none). Decoder rebuilds the pool child-first, re-interns each record into the load Context,
and bounds every ref/count.

## The migration + the scar the purity test caught

Turning `TypeId` from opaque-u32 to interned-index broke every `TypeId{n}` literal in the tests + the generator's smoke
emission. Migrated all of them to real factory calls (`ctx.type_i32()` etc.); evolved `ceir_opgen.py`
(`_ATTR_FACTORY["type"]` + smoke result-type literals → `ctx.type_i32()`, regenerated all dialects, drift clean).

**⭐ Scar (recorded in [[feedback_generator_needs_full_surface_reference_input]]):** three `TypeId{1U}` literals in
`rich_graph.hpp` (func/call/producer results) survived my first migration pass (a `head -40` truncation hid them). They
aliased to "whatever is interned at slot 1" — `i32` in a clean Context (correct by luck), a POLLUTION type in the
dirty-context purity test. It compiled, verified, and round-tripped consistently-wrong; only the **clean-vs-dirty
content-purity assertion** exposed it (the blobs differed by exactly one 23-byte scalar type record). The `type_of`
assert did NOT catch it — the aliased id is valid-but-wrong, not out-of-range. Lesson: a dirty-context purity test is
the real detector of magic-ID aliasing.

# CEIR-3b — generics: type params, traits, callables, verifier-checked substitution (§16/§98)

Extended the type system with the generic constructs §16 lists (generic params + specialization constraints,
interfaces/traits, function/callable types) — the CHIR headroom that must exist in the IR before any frontend emits it.

## Design (advisor-settled)

- **Three appended `TypeKind`s** (after `Result`, never renumbered — the binary encodes the ordinal): `TypeParam`
  (name + `members`=its constraint traits), `Trait` (name + `members`=its supertraits — **Trait, not Interface**, to
  avoid confusion with CEIR-1d's op `InterfaceId`), `Callable` (`count`=num params, `members`=params ++ results). All
  reuse the existing `Type` record fields → **NO binary version bump** (still v2; the decoder's kind range widened to
  `Callable`). A type param is **structurally identified by (name, constraints)** — two generics both using `T:Ord`
  share one interned param; substitution binds every occurrence by TypeId; alpha-scoping is a CHIR concern.
- **Trait conformance is live Context state** (`register_conformance`/`satisfies`), NOT serialized — the tracker demands
  verifier-checked *substitution*, which this delivers; serialized conformance *declarations* have no producer until an
  `impl` op exists (they'll rebuild from op attrs on load, exactly as symbols do — the CEIR-1b precedent). `satisfies`
  walks supertraits transitively (acyclic: a supertrait is interned before the trait naming it).
- **`substitute` returns a diagnostic-bearing `SubstResult`** `{ok, type, failed_param, failed_trait}` — the 3z gate
  wants a *pointing* "constraint violation," not a bool. Unbound params **remain** (result stays generic; `type_has_params`
  queries groundness); ground subtrees are **identity**; the walk is **memoized** (types are shared DAGs — `tuple<X,X>`
  with deep X must not re-substitute X twice). No depth guard needed: in-memory types are acyclic by construction (only
  the parser/decoder face untrusted nesting, both already guarded). `type_has_params` + conformance walks are iterative
  worklists + a seen-set for the same DAG-sharing reason.

## Grammar (extends the `!`-sigil form; byte-exact round-trip)

`!param<T>` / `!param<T,!trait<Ord>>`, `!trait<Eq>` / `!trait<Ord,!trait<Eq>>` (name-first, comma style — matches
struct/enum), `!fn<(!i32,!f32)->(!bool)>` (mandatory parens both sides), `!fn<()->()>` legal. `->` is the only new token
(a two-char expect).

## Trap 1 (advisor) — the decoder was admitting structurally-invalid types (latent since 3a; Callable makes it acute)

`decode_type` validated refs/counts against the *chunk* but never per-kind arity — a hand-crafted blob could deliver a
`Vector` with 0 children or (now) a `Callable` whose `count` **indexes past** `members`, an out-of-bounds recipe the
byte-flip sweep never caught (it deserializes but doesn't print). Added a free `type_is_well_formed(const Type&)` in
type.hpp — **memory-safety arity/parity only** (wrappers=1 member, Result=2, Struct label==member parity, scalar/Enum
members empty, Tuple/Variant/param/trait/Callable labels empty, Callable `count<=members`; NOT value semantics — `!i7`
still round-trips). Called from `decode_type` (reject with byte offset); unit-tested directly with hand-built invalid
records; plus a **patched-blob** decode-rejection test that walks the chunk headers to the `TYPE` fourcc and inflates a
record's child-count in place (offset-independent). This retroactively hardens 3a's kinds — the 1f "malformed REJECTED"
contract, now enforced for types.

# CEIR-3c — resource types + view types (§23)

Added the §23 resource type family + view types. Nine appended `TypeKind`s (after `Callable`, ordinal-stable) → 27
total; **no binary version bump** (all reuse the v2 record).

## The fork (advisor-settled): Interpretation B — view range VALUES are runtime

A view's TYPE carries the underlying resource + WHICH range dimensions it constrains (a `ViewRange` presence MASK in
`count`), NOT the runtime offsets/sizes. Four reasons: the 3z gate wants only "invalid view combinations rejected" (a
structural check); static-value view types have no producer until view-creation ops exist (CEIR-4+) — the same
no-producer argument used for 3b conformance; it's the SPIR-V/MLIR split (image type = dim+format, subresource range =
view-op parameter); and it fits v2 with no new record fields. The mask is append-friendly (§23's plane/tensor-slice/
sparse ranges become new bits later, zero record change). **Recorded here for user veto at review** — if static values
were intended, that's an append-compatible later extension, not a redesign.

## Kinds + field mapping

`Buffer` (`count`=BufferMode raw/plain/structured/typed; raw has no element, else `members[0]`), `Image` (`count`=
ImageDim, `members[0]`=format element — a TypeId, backend-agnostic; the engine's `FgImageFormat` stays out per §23),
`Sampler` (`is_signed`=comparison?), `ResourceTable` (`members[0]`=element), `AccelStruct`/`VideoFrame`/`AudioBuffer`/
`ExternalResource` (niladic), `View` (`members[0]`=underlying, `count`=ViewRange mask). **Scope: all of §23 EXCEPT
`tensor`/`sparse_tensor`** (Shape-dependent → 3d). §24 memory domains are value/allocation semantics, not types — out of
scope.

## Grammar

`!buffer<raw>` / `!buffer<plain,!f32>` / `structured` / `typed`; `!image<d2,!vec<4x!f32>>` (dim keywords are **ident-safe
`d1`/`d2`/`d3`/`cube`** — a digit-leading `2d` can't be parsed back through `parse_ident`, a bug the first round-trip
caught); `!sampler<plain>` / `!sampler<cmp>`; `!restable<!f32>`; `!accel`/`!video`/`!audio`/`!external`; `!view<RES,byte,
element>` / `!view<RES,mip,layer,aspect>` (range dims in canonical order). Byte-exact round-trip.

## The tri-split + Trap 1 realized

`view_combination_valid(underlying, mask)` — buffers admit byte+element, images admit mip+layer+aspect, only buffers/
images are viewable, only defined bits legal — is the tri-split: the **parser** `fail()`s (a pointing diagnostic, the
3z gate's "invalid view combination" delivered early — the FIRST semantic check the parser performs), the **decoder**
rejects with a byte offset, the **factory** asserts. **The corruption sweep caught exactly the advisor's Trap 1**: on an
already-failed parse (`m_ok==false`), the `if (m_ok && !valid)` guard short-circuited and fell through to the asserting
`type_view` — a corrupt-input ABORT. Fixed by bailing on the prior error BEFORE the asserting factory. (The sweep
deserializes+parses corrupted rich-graph bytes, which now include resource/view types — this is why it surfaced now.)
**The asymmetry is principled:** only factories that assert a SEMANTIC predicate (here `type_view`) need the
prior-error bail; the ~15 arity-only factories tolerate a failed parse harmlessly (they intern a well-formed-by-arity
type that is simply discarded). **Latent looseness, with its trigger:** a failed parse (or any direct caller) can
intern a type whose MEMBERS are `TypeId{0}` — `type_buffer(Plain, <failed>)`, `type_vector(<failed>, 4)` — latent since
3a; empirically safe today (the sweep runs thousands of failed parses: nothing enumerates the type table, the module is
discarded, and `type_of` asserts at first USE). ⛔ If a type-table enumerator or whole-table serializer is ever added,
FIRST harden `intern_type` to assert member validity AND add the `!m_ok` bail to EVERY parser factory branch — else the
failed-parse path becomes an abort.

## Trap 2 realized — decode bounds on keyword-mapped scalars

`decode_type` now bounds the scalars the printer maps through closed keyword tables (Buffer mode ≤ Typed, Image dim ≤
Cube, View mask ⊆ the 5 defined bits) — else a decoded out-of-range code would print as NOTHING (silently lossy text).
FREE numerics (int width, vector count) stay unbounded: `!i7` legitimately round-trips. These live in `decode_type`
beside the kind/fkind checks, NOT in `type_is_well_formed` (arity/parity-pure).

## Tests + gate

`test_type.cpp` +3: resource/view intern/dedup/round-trip of every kind incl. nested view-of-image; view-combination
accept (legal dims) + reject (mip-on-buffer, view-of-non-resource) via predicate AND parser diagnostic; well-formed
units for the new arities. `rich_graph` gains a `ty3` = `!view<!image<d2,!vec<4x!f32>>,mip,layer>` (resource/view under
round-trip + purity). `test_fuzz` `random_type` gains buffer/image/sampler/**valid**-view branches (an illegal combo
would trip the factory assert). `test_malformed` gains resource/view grammar + combination rejection. `test_binary`
gains a keyword-bounds patched-blob (inflate an image dim → rejected). **Gate:** crd-ceir-tests **73/73** on **win-debug
· win-asan · linux-gcc-debug · linux-gcc-asan** + LLVM-20 tidy (ViewRange → u8; isolate-declaration) + GCC
`-Werror=switch` (both switches cover all 27 kinds) + invariants + opgen ctests green both OSes. **No binary version
bump.** New surface: `TypeKind::{Buffer,Image,Sampler,ResourceTable,AccelStruct,VideoFrame,AudioBuffer,ExternalResource,
View}`, `BufferMode`/`ImageDim`/`ViewRange`, `Context::type_buffer/type_image/type_sampler/type_resource_table/
type_accel_struct/type_video_frame/type_audio_buffer/type_external_resource/type_view/view_combination_valid`.

# CEIR-3d — shapes + tensors: dims, shapes, tensor types + compat predicates (§21/§35)

Added the type-level shape/tensor foundation. Four appended `TypeKind`s (after `View`) → 31 total; **no binary version
bump** (all reuse the v2 record).

**⛔ Latent trigger (advisor):** `substitute` interns its rebuilds directly via `intern_type`, BYPASSING the composition
predicates — so binding a param to a Dim/Shape would yield an interned `tensor<!dim<4>,…>` whose printed text the parser
REJECTS (a form-agreement break reachable via the public API). Nonsense-only today (params range over value types;
nothing produces such a binding — same class as the 3c `TypeId{0}`-members note). ⛔ When kinded params land (the 3c
shape-generic-tensor note) OR substitution is exposed to untrusted bindings, `substitute` must re-validate the
composition predicates on rebuild.

## Boundary (the fourth type/impl split, advisor-ratified)

3d = shape/dim/tensor **TYPES** + compat **PREDICATES** only. The `ceir.shape`/`ceir.tensor` value-op DIALECTS (shape
assertion ops, shape functions, specialization-from-observed-shapes) AND **layout** (§22) land at CEIR-18 — the tracker
row for 18 explicitly owns `ceir.tensor`/`ceir.shape` + cites §21 §22. `tensor`/`sparse_tensor` RETURN here (the 3c
Shape-dependent scope boundary); §35/§36 are dialect sections (like §23's `ceir.resource` at 3c). Same schema/codegen
split as 2a — recorded so the user can veto scope at review.

## Kinds + representation

`Dim` (`cols`=DimKind Static/Symbolic/Dynamic; Static uses `count`=extent, Symbolic uses `name`=symbol — structural-by-
name like TypeParam, alpha-scoping is CHIR's), `Shape` (`members`=dims, rank=members.size(), `!shape<>`=rank-0), `Tensor`
/ `SparseTensor` (`members`=[element, shape]; the sparse ENCODING is CEIR-18, the kind distinction is CHIR headroom).
Grammar (byte-exact): `!dim<4>` (digit→parse_uint) / `!dim<dyn>` / `!dim<N>`, `!shape<!dim<4>,!dim<N>>`,
`!tensor<!f32,!shape<…>>`, `!stensor<!f32,!shape<>>`.

## Compat predicates — tri-state (§21)

`ShapeCompat {Compatible, Incompatible, Unknown}` — **Unknown is principled**: §21 lists "runtime shape checks" as its
own mechanism, and Unknown is exactly the deferral to a CEIR-18 assertion op. `shapes_broadcast` = numpy align-right with
rank padding, returns the **right-aligned position** of the first incompatible pair (0=innermost) for a pointing
diagnostic; per pair: `1` broadcasts with anything, two statics agree/clash, same-name symbolics agree, else Unknown.
`shapes_reshape` = structurally-identical shortcut, all-static product equality, else Unknown. ⛔ A broadcast-**result**

## Traps realized

## Dimension representation (advisor-settled: bit-pack)

`crd::units::Dim<L,M,T,I,Th,N,J,A>` is **compile-time-only** (8 signed-i32 exponents as TEMPLATE params) — there is no
runtime dimension value to reuse, so CEIR carries a runtime MIRROR. The 8 signed base exponents (ADR-0078 / mp-units
P1935 order, angle as a distinct 8th base) **bit-pack into `count`+`cols`** (8×i8 = 64 bits, fits, NO new record fields
— consistent with rejecting the params-span at 3c/3d). Exact encoding pinned in ONE `pack_dim`/`unpack_dim` pair (⛔ no
inline bit math elsewhere — sign-extension is the trap): each exponent two's-complement in its byte, `count`=L,M,T,I,
`cols`=K(temperature; crd-units `Th`),N,J,A. **"Reuse crd-units" is mechanically verified**: `#include <crd/units/dim.hpp>`
(link-legal per ADR-0109) + a `static_assert` pinning base 0 == `crd::units::Dim<1,…>::length`, base 2 == `::time`,
base 7 == `::angle` — a mirror that can't rot into a comment.

## Quantity kind + relations

`Quantity`: `members[0]`=underlying NUMERIC type, count+cols=packed dim. `quantity_composition_valid` (tri-split) accepts
Int/Float/Index/Vector/Matrix/Complex/Quaternion + **TypeParam** (generic quantities — the 3b×3d seam), rejects
Quantity-of-Quantity (nested tags are always a bug), Dim/Shape/resources/aggregates/callable/trait (§18 "don't
over-tag" — start strict). Grammar (byte-exact, ident-safe): `!qty<!f32,L1>`, `!qty<!f32,L1T-2>` (acceleration),
`!qty<!vec<3x!f32>,L1>`, `!qty<!param<T,!trait<Ord>>,M1>`, dimensionless `!qty<!f32,1>`. The dimension parses
character-wise (base-letter + mandatory signed exponent, canonical order, no dup; `-` rules out `parse_ident`); the
empty spelling `,>` is REJECTED (dimensionless is only `1`). (Note: the dimension letter `T`=Time and a type-param name
`T` do NOT collide — dimension terms appear ONLY inside `!qty<…,HERE>`, a distinct grammatical position from a param
name; don't "fix" it later.) Relations (the §17 "dimensional errors caught before

## CEIR-3f — ownership/lifetime qualifiers + the escape predicate (§19)

**Design (advisor fork).** ONE `Qualified` TypeKind APPENDED (→ 33 total; reuse v2 record, NO version bump):
`members[0]` = the qualified type, `count` = a mutually-exclusive **`OwnershipKind`** (9 §19 modes: `imm`, `mut`,
`borrow`, `own`, `shared`, `weak`, `state`, `ext`, `transient`). A wrapper — not nine kinds — because a value carries
**exactly one** ownership mode and the wrapper composes uniformly over both values and resource handles (a borrowed
buffer is the archetype). `qualified_composition_valid` (tri-split) accepts numerics/aggregates/generics/resources,
rejects qualifier-of-qualifier / `dim` / `shape` / `trait` (meta-types that are not runtime values). Grammar
`!qual<KIND,T>` byte-exact; **the printer `emit_ownership` switch and the parser if-chain are a hand-kept lockstep pair
— only `emit_ownership` gets `-Werror=switch`, so the round-trip test drives ALL NINE keywords** (a dropped/transposed
parser arm only surfaces as a broken round-trip). Unqualified `!f32` and `!qual<imm,!f32>` are **distinct interned types**
— intentional: an immutable-value qualifier is a real annotation, not a synonym for the bare type.

**The escape rule splits 3f/3z (advisor).** 3f ships the region-visible predicate
`Context::value_escapes_region(const Value*, const Region*)`: walk the value's def-use list; any use whose enclosing
region is **not contained by** the defining region ⇒ escape. Containment is a directional upward walk
(`region_contains`, terminating at the module-body region whose `parent_op()` is null). 3z composes this over every value
**typed** `Qualified<BorrowedView>` in a module walk. **Escape contract = direct-use only, type-directed**: a value is
checked against its own defining region purely from its uses; a leak through an untyped intermediate
(`%b = wrap(%a); return %b`) is caught only if the intermediate itself carries the borrowed type. That is the exact
semantics 3z's module walk must implement — written here so 3z is not built against a transitive rule the predicate does
not have.

## CEIR-3z — BAND-3 GATE (§16/§17/§19/§21)

**What the gate proves.** Band 3 built a family of interned types + tri-split predicates; 3z proves the four error checks
fire as **pointing diagnostics** whose pointing field **discriminates** (a second case moves it, a control does not fire):
(1) `Length+Time` via `quantity_dimensions_equal→DimMismatch.first_differing_base` (L-vs-T → base 0; **L-vs-LT → base 2**,
which rules out a hardcoded zero); (2) rank-mismatched broadcast via `shapes_broadcast→BroadcastResult.position`
(`[4,3]`vs`[5,3]` → position 1, + a Compatible control); (3) borrowed-view region escape via `find_borrowed_escape`; (4)
generic-constraint violation via `substitute→SubstResult.failed_param/failed_trait` (exact `(T,Ord)`, + an accept control
after `register_conformance`). Dedicated artifact `tests/ceir/test_band3_gate.cpp` (4 TEST_CASEs, `[gate3]`, 20 assertions).

**Scope boundary — honest (advisor).** 3z ships pointing **predicates** + ONE module walk (`find_borrowed_escape`). It is
**NOT** a module-level type verifier. Only the borrowed-view escape is a program property whose inputs (typed values,
regions, uses) all exist NOW; the op-level wiring of (1)/(2)/(4) onto an op's typed operands has **no producer op until
CEIR-4** and composes there (the 3e "predicate-now, wire-when-a-consumer-op-exists" precedent). The tracker row and
context.md state this in-place so band 3 never reads as "a verifier exists".

**The 3f pointing upgrade.** The gate demands *pointing* diagnostics and `value_escapes_region` returns a bool — a bool
cannot point. Added the companion `first_escaping_use(const Value*, const Region*) → const Operation*` (nullptr = no
escape) reusing `region_contains`; `value_escapes_region` now delegates (`!= nullptr`) — no 3f API break, no duplicated
loop. The returned `Operation` carries the SourceLoc (§1c) a diagnostic points at.

**`find_borrowed_escape` contract (three properties a CEIR-4 implementer must not have to infer from the code):**
- **First-offender.** Deterministic **pre-order** walk — block args before op results, recursing op regions, matching the
  printer's SSA numbering — returning ONE `BorrowEscape`. Fix-and-re-run, not collect-all (the house pattern: ParseResult
  / SubstResult / DimMismatch latch the first offender).
- **Structural, not dominance-aware.** It walks the def-use list; it does **not** validate SSA dominance. Correct now (no
  CFG/dominance verifier until CEIR-5b) — but stated so no one assumes it subsumes dominance checking.
- **Direct-use, type-directed.** Every value **typed** `!qual<borrow,_>` is checked against its own defining region from
  its uses; a leak through an untyped intermediate (`%b = wrap(%a); use %b outside`) is caught only if the intermediate
  itself carries the borrowed type. (Restated from 3f because the module walk now lives here.)
