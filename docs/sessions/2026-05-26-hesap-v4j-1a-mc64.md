# 2026-05-26 — hesap v4j-1a: MC64 max-weight matching + scaling

Phase 3.1.6 `crd-hesap` v4, slice **v4j-1a** — the first piece of the multilevel-ILU
(ILUPACK-class) mini-cluster. MC64 (Duff-Koster) is the matching + scaling robustness
front-end that makes ILUT / multilevel-ILU reliable on hard, badly-scaled, non-diagonally-
dominant matrices (the role it plays in ILUPACK / MUMPS / SuperLU).

## v4j re-split (advisor)

v4j (Multilevel ILU, ILUPACK-class) is research-grade. Re-split — MC64 is a focused ~300-LOC
algorithm with subtle determinism deserving its own DoD, separate from the multilevel scaffold:
- **v4j-1a** (this slice): MC64 matching + scaling as a standalone reorder primitive in
  `crd-hesap-ordering` (beside AMD/RCM/ND — it's a reordering). Reusable by the ILU family too.
- **v4j-1b**: `MultilevelIlu<T>` scaffold (consumes MC64; placeholder accept-all = single-level).
- **v4j-2**: inverse-based pivot test (‖L⁻¹‖,‖U⁻¹‖ ≤ κ) driving the real accept/defer split.
- **v4j-3**: quality tuning + the head-to-head.

**Peer (decided, user direction): ILUPACK** — the same-algorithm Bollhöfer-Saad gold standard
(the only true peer for inverse-based multilevel ILU; AMGCL is *algebraic multigrid*, a different
method, and Eigen has no multilevel ILU at all). Built on Linux/WSL (gfortran + SuiteSparse-AMD
+ METIS), matching the project's existing "Linux for fair-speed reference" posture
([[reference_lapack_via_openblas]]). AMGCL added as a secondary "vs the AMG frontier" data point.
This lands at v4j-3.

## What shipped

- **`crd-hesap-ordering/mc64.hpp` + `mc64.cpp`** — `mc64_match_and_scale`:
  - Max-PRODUCT matching `max_σ ∏|a_{i,σ(i)}|` reformulated as min-SUM LAP on
    `c_ij = log(maxⱼ|a_ij|) − log(|a_ij|) ≥ 0`, solved by a sparse shortest-augmenting-path
    (alternating Dijkstra over reduced costs, binary min-heap) + a greedy initial matching.
  - Dual potentials `uᵢ, vⱼ` → scaling `D_r[i] = exp(uᵢ)/maxⱼ|a_ij|`, `D_c[j] = exp(vⱼ)`.
    Complementary slackness ⇒ the matched entry scales to exactly 1, every other to ≤ 1
    (the **I-matrix property**).
  - **Determinism** (D(ord) discipline): the heap orders `(dist, col)` lexicographically
    (ascending-col tie-break); row adjacency walked in stored ascending order; pinned dual
    constant. No RNG → bit-reproducible. (To pin as `D(ord)-8` in ADR-0065 at v4j close.)
  - Heavy LAP core in `.cpp` (f64 magnitudes, compiled once) + a thin templated wrapper
    (f32 / f64 / Complex<f32> / Complex<f64> via overloaded `|·|` — no crd-hesap-dense dep).
  - Structurally-singular matrices: maximum (partial) matching, free rows assigned leftover
    columns, `full_rank=false` flagged.
- **CLI** `hesap.ordering.mc64` (value-aware — the first ordering op that reads real `values`,
  not just the structure; returns `[colperm(n), D_r(n), D_c(n)]` as a BinaryBlob f64).
- **+4 tests**: cyclic matching (finds the large off-diagonal entries), the I-matrix property on
  a badly-scaled matrix (validates the dual scaling directly), determinism (bit-identical across
  runs), complex (matches by magnitude). Ordering suite 40 cases / 7760 assertions.
