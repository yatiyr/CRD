# Session — 2026-05-01 — `crd-shader` 2.3g pipeline handoff / descriptor growth

## Goal

Finish the Phase 2.3 shader packet by making the handoff boundary to RHI and
later renderer code explicit and backend-neutral.

## What we built / changed

- **Public handoff surface**
  - `VariantPipelineDesc`
  - `ShaderModuleUsageDesc`
  - `Runtime::describe_variant()`
- **Descriptor growth**
  - variant handoff now normalizes descriptor bindings across shader stages
  - push-constant visibility is normalized across modules
  - vertex attribute requirements are exposed as part of the variant handoff
- **Tests**
  - new handoff test proves a compiled variant can be described for later RHI
    pipeline creation
- **Smoke**
  - `smoke_shader` prints handoff summary counts alongside compile/cache/reload
    observability

## Plain-English explanation

The shader system now has a clean answer to the question: "What exactly does
the backend need from a compiled shader variant?"

That answer is no longer implicit in internal runtime data structures. It is a
named handoff surface with normalized descriptor/push metadata and module usage
information. This is the boundary the future renderer and the current RHI can
both build around.

## Decisions made

- `crd-shader` owns effect/variant identity, reflection-derived metadata, and
  the shader-side inputs to PSO creation.
- `crd-rhi` / backend continue to own native pipeline objects.
- The public handoff surface stays backend-neutral and does not expose SPIR-V
  or Vulkan types.
