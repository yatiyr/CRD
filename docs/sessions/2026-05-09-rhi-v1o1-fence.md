## What shipped

### New header `engine/rhi/include/crd/rhi/fence.hpp`

```cpp
class Fence
{
public:
    virtual ~Fence() = default;

    [[nodiscard]] virtual bool is_signaled() const noexcept = 0;
    virtual void               wait()                      = 0;
    virtual void               reset()                     = 0;

    Fence(const Fence&)            = delete;
    Fence& operator=(const Fence&) = delete;
    // ... move-deleted ...
protected:
    Fence() noexcept = default;
};
```

Lifetime contract: created via `Device::create_fence()` (returns `unique_ptr<Fence>`); the device owns the underlying handle and the fence MUST NOT outlive its device.

Threading contract: not thread-safe. One fence ↔ one in-flight submission at a time.

### `Device::create_fence()` factory

```cpp
[[nodiscard]] virtual std::unique_ptr<Fence> create_fence() = 0;
```

Added to `crd::rhi::Device` alongside the existing `create_command_buffer()` etc. Vulkan implementation calls `vkCreateFence` with no flags (starts unsignalled).

### `Queue::submit(CommandBuffer&, Fence&)` non-waiting submit

```cpp
virtual void submit(CommandBuffer& command_buffer, Fence& fence) = 0;
```

Records the command buffer onto the queue, signals the fence on completion, returns immediately. No swapchain semaphores — this path is for off-frame work (asset upload, async compute, transfer). Fence MUST be unsignalled at submit time (newly created or `reset()` after the previous submission completed).

### Vulkan backend (`engine/rhi-vulkan/src/vulkan_backend.cpp`)

`VulkanFence` class (~50 LOC) wraps `(VkDevice, VkFence)`:
- `is_signaled()` → `vkGetFenceStatus` (VK_SUCCESS = signalled, VK_NOT_READY = not yet).
- `wait()` → `vkWaitForFences(handle, 1, &fence, VK_TRUE, UINT64_MAX)`.
- `reset()` → `vkResetFences`.
- Destructor → `vkDestroyFence`.

`VulkanDevice::create_fence()` constructs a `VulkanFence` via `vkCreateFence` with flags=0 (unsignalled).

`VulkanQueue::submit(cmd, fence)` builds a `VkSubmitInfo` with the command buffer and a fence handle, calls `vkQueueSubmit(queue, 1, &submit_info, fence_handle)` — no `vkQueueWaitIdle`. Fence flips when the GPU completes the work.

### Fake backend (test-only, in `tests/rhi/test_rhi.cpp`)

`FakeFence` class auto-signals on `submit(cmd, fence)` (the fake doesn't model GPU timing). Tracks `wait_count` / `reset_count` for assertions.

`FakeQueue::submit(cmd, fence)` casts the fence to `FakeFence` and flips the signal bit.

Other downstream fakes/smokes that derive from `Queue` or `Device` were updated to satisfy the new pure virtuals: `tests/renderer/test_renderer.cpp::FakeQueue/FakeDevice`, `runtime/examples/smoke_rhi_api.cpp::SmokeQueue/SmokeDevice`, `runtime/examples/smoke_renderer.cpp::FakeQueue/FakeDevice`.

### Tests

**`tests/rhi/test_rhi.cpp`** — 4 cases / 12 assertions on the fake backend:
1. `Fence: factory creates an unsignalled fence` — `Device::create_fence()` returns non-null; `is_signaled()` is false on a fresh fence; create-count incremented.
2. `Fence: wait() transitions to signalled state` — `wait()` flips the fake's signalled bit; `wait_count` increments.
3. `Fence: reset() re-arms the fence` — round-trip wait → signalled → reset → unsignalled, with multiple resets idempotent.
4. `Queue::submit(cmd, fence) signals the fence on completion` — submit increments `submit_with_fence_count`, fence flips signalled; reset + re-submit confirmed.

**`tests/rhi_vulkan/test_rhi_vulkan.cpp`** — 1 case (skipped on `CRD_PLATFORM_HEADLESS=1`):
- `Vulkan Fence: non-blocking submit signals fence on completion` — exercises the real `vkCreateFence` → `vkQueueSubmit(fence)` → `vkWaitForFences` → `vkResetFences` → `vkDestroyFence` round-trip on an empty-but-valid command buffer. Submits twice through the same fence to validate reset+reuse.

### Architectural pins

1. **Three queue submit paths now coexist.** Existing: `submit(cmd, swapchain)` (per-frame swapchain-aware), `submit_and_wait(cmd)` (one-shot blocking, used by current `GpuUploader::upload_*`). New: `submit(cmd, fence)` (non-blocking, signal-on-complete). The third path is purely additive — no existing callers needed to change.

2. **Binary fence, not timeline semaphore.** ADR-0061 §"Layer 1" pinned: binary fences are sufficient for the "is this single upload done?" question. Timeline semaphores are richer (multi-step ordering, batched waits) and can be added as a non-breaking RHI extension if a consumer needs them. Don't over-design at the first call site (UploadHandle in v1o2).

3. **Transfer queue NOT exposed.** ADR-0061 §"Layer 1" reserved `Device::transfer_queue()` for a follow-up — concurrent uploads serialise behind frame submissions on the graphics queue for now. Adding a dedicated transfer queue is a pure RHI extension and doesn't change the Fence/UploadHandle contract.

4. **`unique_ptr<Fence>` ownership matches the rest of RHI.** Same pattern as `Buffer`, `Image`, `Pipeline`, `CommandBuffer`. The Device owns the underlying VkFence; the unique_ptr keeps the dtor RAII-clean.

5. **No fence pool.** Each `create_fence()` call allocates a fresh VkFence. v1o2's `UploadHandle` uses one fence per in-flight upload. If frequent allocation becomes a hot path (Phase 3.5+ streaming with hundreds of concurrent uploads), a pool can layer on top — `Device::create_fence()` stays the public API and the pool becomes an implementation detail behind it.

## What's deliberately NOT in v1o1

- **No `UploadHandle` / `GpuUploader::upload_*_async` / `PendingMeshUpload` / `RenderUploadSystem`.** That's v1o2 — Layer 2 + Layer 3 of ADR-0061.
- **No transfer queue.** Reserved follow-up; concurrent uploads serialise on graphics queue.
- **No timeline semaphores.** Binary fences are sufficient for v1o1's contract.
- **No fence pool.** Plain `create_fence()` allocates a fresh `VkFence` per call; pooling can layer on later if a hot path appears.
- **No `vkResetFences` validation.** A fence reset while still in flight (signal not yet received) is undefined behaviour at the Vulkan layer; v1o1's fake backend doesn't model this either. The Fence contract documents that consumers must `wait()` (or `is_signaled() == true`) before `reset()`.
