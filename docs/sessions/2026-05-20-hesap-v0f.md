# 2026-05-20 — Phase 3.1.6 `crd-hesap` v0f (SLIMMED): property-based tests + bench-harness dedup

v0e closed the dense direct solvers cluster. The original v0f plan was a
~5-day, ~500-line slab: a new `crd-hesap-bench` sub-module + committed
LAPACK/SuiteSparse/FFTW reference binaries + a `RandomMatrix<T>` property
framework + the system doc. On review with the user, most of that is
speculative consumer-specific scaffolding for slices that don't exist yet.
We shrank v0f to the part that pays off now and deferred the rest with the
reason recorded.

## What v0f shipped

1. **`tests/hesap-dense/random_matrix.hpp` — seeded `RandomMatrix` factory.**
   Consolidates the three random-matrix generators that were copy-pasted
   across test files:
   - `build_spd` (test_cholesky.cpp) → `random_spd` (A = BᵀB + n·I)
   - `build_symmetric_indefinite` (test_ldlt.cpp) → `random_symmetric_indefinite`
   - `fill_matrix` (test_blas3_parallel.cpp) → `random_general`
   Plus new generators for property testing: `random_diag_dominant`
   (well-conditioned LU/QR input) and `random_spd_ill_conditioned`
   (stretched spectrum for condition-estimator / refinement exercise).
   A single LCG (`1664525` / `1013904223`, the constant used throughout
   hesap) backs `Rng`. **Value formulas match the prior inline generators
   bit-for-bit**, so every existing test tolerance is unchanged. SPD scratch
   B is allocated from `a.allocator()` (never `default_allocator()`).

2. **`test_random_property.cpp` — 4 property tests.** For a spread of seeds
   × sizes from the factory, assert the defining algebraic property:
   Cholesky reconstructs A (L·Lᵀ), and LU / LDLT / QR solves recover the
   planted x from b = A·x. LDLT skips singular random draws.

3. **`crd_add_hesap_vs_ref_bench()` CMake helper.** The 4 vs-reference
   benches each repeated ~25 lines of `add_executable` + Eigen/OpenBLAS
   link + the OpenBLAS generated-header include hack + OpenMP + the
   source-file `/WX-` suppression. Collapsed to a single function with
   `USE_JOBS` / `USE_OPENBLAS` flags; ~120 lines → ~30. Every future
   vs-reference bench (sparse, FFT) reuses it.

## What was de-scoped (recorded, not built)

- **`crd-hesap-bench` sub-module + committed LAPACK/SuiteSparse/FFTW
  reference binaries** → deferred to the FFT/sparse slices (v1, v5, v10)
  that actually consume them. No such binaries are committed today, so
  there is nothing to drop — the original plan would have *added* them
  speculatively. Per `feedback_ship_at_consumer_template_from_day_one`:
  substrate ships proactively, speculative consumer-specific paths defer
  until the consumer arrives.
- **`bench_common.hpp` C++ harness dedup** (shared `time_loop` / `fill` /
  P-core affinity / GFLOPS reporting) → deferred to the *third* vs-reference
  bench. The blocker is real, not cosmetic: `time_loop` calls
  `crd::jobs::frame_reset()` (frame-arena exhaustion fix), but 2 of the 4
  vs-reference benches (blas1, blas2) don't link `crd-jobs`. Abstracting
  over that now (templated reset callable) is premature with only a 2/2
  split; sparse/FFT will give the real data point. "Three similar lines is
  better than a premature abstraction."

- **Refactor safety**: the 3 refactored test files (cholesky / ldlt /
  blas3_parallel) pass unchanged — formula-preserving consolidation.
