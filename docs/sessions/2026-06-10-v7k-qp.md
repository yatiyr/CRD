## What was built

**One canonical problem form** (`QpProblem`: min ½xᵀPx + qᵀx s.t. l ≤ Ax ≤ u — the OSQP statement; equality =
l==u, ±inf one-sided) and **uniform OSQP-sign duals** (Px + q + Aᵀy = 0; y ≥ 0 at u, ≤ 0 at l) across all
three solvers, so a single KKT certificate adjudicates everything.

| Solver | Algorithm | Profile |
|---|---|---|
| `solve_qp_admm` | OSQP-class splitting (Stellato et al. 2020): quasi-definite KKT factored ONCE per ρ (Bunch-Kaufman), per-constraint ρ with the 1e3 equality boost, α=1.6 relaxation, OSQP residual termination, **certified primal/dual infeasibility** (δy/δx), **deterministic adaptive ρ** (residual-ratio, fixed interval — reproducible iteration counts), **active-set polish** via the v7-j equality-KKT solve (empty active set ⇒ exact unconstrained Newton) | embedded-MPC shape; P PSD |
| `solve_qp_mehrotra` | predictor-corrector IPM: affine predictor → σ=(μ_aff/μ)³ corrector, 0.995 fraction-to-boundary, the reduced saddle [P+GᵀDG, A_Eᵀ; A_E, 0] through the v7-j inertia-corrected Bunch-Kaufman; divergence guard (non-finite iterates ⇒ honest NumericalError instead of feeding NaN to the factor) | the accuracy reference |
| `solve_qp_goldfarb_idnani` | the 1983 dual active-set (quadprog's algorithm): G=LLᵀ, J=L⁻ᵀ, Givens-updated active factor R; equalities added first and never dropped; finite termination | P ≻ 0; exact active sets |

## The two real bugs the gates caught

1. **GI's `J` accessor returned L⁻¹ instead of L⁻ᵀ.** The step direction then lives in the (LᵀL)⁻¹ metric
   rather than P⁻¹ — and because the primal step length normalizes along the constraint, the iterate still
   lands EXACTLY FEASIBLE, just not optimal. Diagonal-P tests can never see it (L = Lᵀ). The cross-adjudication
   flagged the disagreement; shrinking to n=2 Philox instances produced a hand-checkable repro that identified
   the transpose in one look. The scanner is now a permanent test (SANITY #3: tiny adversarial instances
   localize what aggregate families only signal).
2. **The missing `u[iq−1] = u[iq]` incoming-dual carry** in the active-set drop (quadprog has it; without it
   the accumulated dual of the constraint being inserted goes stale after any drop — again invisible until
   instances actually drop constraints).

Also fixed en route: the IPM fed non-finite iterates into Bunch-Kaufman on infeasible problems (NaN pivot
search → out-of-range index); now guarded with an honest status.
