# 2026-06-14 — v10-g: NUFFT (type-1/type-2) vs FINUFFT

**Slice:** Phase 3.1.6 v10-g — Non-Uniform FFT, new `crd-hesap-fft` header `nufft.hpp`. Gold standard **FINUFFT** (Barnett-Magland-af Klinteberg). 1D complex f64/f32.

## What shipped

`NufftPlan<T>` (header-only, `engine/hesap-fft/include/crd/hesap/fft/nufft.hpp`):
- **type-1** (nonuniform→uniform, "spread") and **type-2** (uniform→nonuniform, "interp"), FINUFFT sign/mode conventions (`f_k = Σ_j c_j e^{isign·i·k·x_j}`, k=−N/2..N/2−1, CMCL mode order).
- **ES kernel** ("exponential of semicircle", φ(z)=exp(β(√(1−z²)−1)), β=2.30·w), **σ=2** upsampling, fine grid n = next-pow2(2N) so the v10-b `FftPlan` applies.
- The Greengard-Lee pipeline: spread → fine FFT → deconvolve+extract (type-1); deconvolve+zero-pad → fine iFFT → interp (type-2). Deconvolution table `d_k = 1/K(k)` with `K(k)` a Gauss-Legendre quadrature of the kernel FT (GL nodes via Newton on Legendre; precomputed once, shared → deterministic, the twiddle-table role).
- `set_points(x)` precomputes per-point base index `i1` + the w ES weights, shared by both types (repeated-geometry amortization, FINUFFT's setpts pattern).
- `direct_type1`/`direct_type2`: exact O(NM) nonuniform DFT, the correctness gate.

**Gate (`tests/hesap-fft/test_nufft.cpp`, 13 asserts / 5 cases):** type-1 and type-2 vs the **direct nonuniform DFT** (NOT round-trip — type1∘type2 cancels spreading errors like IFFT∘FFT hides a twiddle-sign bug; the odeint-d4 instinct) at the kernel tol, both isign, f32+f64; tol→accuracy monotonicity; the spreader run-twice **bit-identical** (the determinism foundation). Full suite **66/16**, green on **win-debug + win-asan (zero ASan errors) + win-tidy + win-shipping (LTCG)**.

## The FINUFFT shootout (the crush grind)

`runtime/examples/bench_nufft_vs_finufft.cpp` + `scripts/run_bench_nufft.sh`. FINUFFT built from source at `~/finufft` (`lib-static/libfinufft.a`, OpenMP). **Both pinned to 1 thread** (Cerid's spreader is serial in v10-g; FINUFFT `opts.nthreads=1`). **EXECUTE-only** (plan+setpts amortized — the repeated-geometry case, how FINUFFT's own benches report). Matched/superior accuracy: Cerid width formula `+2` (vs FINUFFT `+1`) so Cerid MEETS the requested tol with margin.

### The arc (measure → attack → measure)

| step | lever | result |
|---|---|---|
| 0 | naive substrate | **0.42–1.0× FINUFFT** (mostly losing) |
| 1 | `wrap_index` modulo per grid write → **wrap-split fast path** (contiguous, no modulo) + **memset** grid zero (was scalar loop) | small/mid flip to **win** (4096 0.50→2.15×, 16384 0.83→1.77×) |
| 2 | **bin-sort** for cache locality (FINUFFT lever) | **REGRESSED** (262144 0.79→0.63×) — the 14900K's 36MB L3 hides the scatter, so sort overhead (scrambled `c[j]` gather) dominates. **REVERTED.** |
| 3 | profile → losses are **FFT-bound** (62–91% FFT at n≥2^18) = the inherited v10-b FFT deficit | diagnosis: spread is done; large-n is the deferred scheduler project |
| 4 | accuracy: width `+1`→`+2` (Cerid was 3.5× *looser* than FINUFFT at equal width = a tol miss) | Cerid now **3× MORE accurate** than FINUFFT (~3e-10 vs ~1e-9), wins held |
| 5 | **multi-accumulator** the type-2 interp reduction (4 independent lanes break the serial FMA-latency chain) | T2 flips: 1M 1.00→**1.14×**, M≫N 0.78→**1.07×**, 16384 1.49→**1.73×** |

**Honest verdict:** Cerid NUFFT **beats FINUFFT at small-to-mid sizes (up to ~2×) at SUPERIOR accuracy**, **parity at 1M** (T2 wins), and **loses only the FFT-bound n=2^18 region** (262144 modes) — where 62–91% of the time is the fine-grid FFT, i.e. the *same* v10-b FFT-engine deficit already scoped as the deferred genfft-scheduler sub-project (and FINUFFT's FFT backend there is FFTW_ESTIMATE, not best-in-class). The NUFFT-specific work — the **spreader and interp** — is genuinely competitive-to-winning; that's the part a NUFFT adds on top of an FFT, and it's where we fought and won.

## Honesty scoping (no asterisks)

- **Determinism:** run-twice bit-identical TODAY (serial, verified). NOT a claimed {1..16} parallel moat — the parallel NUFFT isn't built. The owner-per-subgrid parallel spread is *designed* to preserve determinism (bin-sort + one-owner-per-subgrid, never atomic-add) but not implemented. Disclosed in the header + bench.
- **Timing:** EXECUTE-only (plan amortized). Single-shot (incl. set_points + GL table) is a different, unmeasured number.
- **Width:** Cerid runs w=11 vs FINUFFT w=10 at eps=1e-9 — Cerid does MORE spread work per point and still wins small/mid, at better accuracy (disclosed). At matched width w=10 (the `+1` formula) Cerid is even faster but 3.5× less accurate.

## Notes / follow-ons (NAMED, not silent)

- **The remaining large-n gap is the FFT, not the spread** — fixing it = the deferred 1D-FFT scheduler sub-project (v10-b residual), shared with the v10-b MKL story. Do NOT re-litigate inside NUFFT.
- type-2 zero-padded FFT pruning (~1 stage, ~5–9%) — measured-marginal, skipped.
- type-3 (nonuniform→nonuniform), 2D/3D NUFFT, and the **jobs-parallel owner-per-subgrid spread** ({1..16} moat) — the v10-g follow-ons.
- `CRD_NUFFT_PROFILE` compile-gate left in (the CRD_MF_PROFILE pattern) for the spread/fft/deconv phase split.

# 2026-06-14 — v10-f: DCT/DST vs scipy/PocketFFT/FFTW

**Slice:** Phase 3.1.6 v10-f — `dct.hpp` `DctPlan<T>`, DCT-II/III + DST-II/III (the JPEG/audio/MFCC workhorses), Makhoul O(N log N) over the FFT. (The MKL-1D-FFT fork: I reassessed — beating MKL/FFTW on single-thread 1D FFT throughput is a Spiral-class codegen project, person-weeks, still sub-parity; the cache-blocking lever is measured-dead 4× on this prefetcher box. So I re-selected the target to the **winnable** breadth that beats the common peers outright. Honest scoreboard, not surrender.)

## What shipped

`DctPlan<T>`: **DCT-II / DCT-III / DST-II / DST-III**, every formula **verified against scipy.fft in `scripts/dct_research.py` BEFORE porting** (correct-by-construction). Forward transforms (dct2/dst2) run on the **v10-d real FFT** (the shuffled Makhoul sequence is real ⇒ half the work of a complex FFT; W[k>N/2]=conj(W[N-k])). Inverse (dct3/dst3) on the complex FFT. One shared half-angle phase table θ_k=πk/2N ⇒ deterministic.

**Gate (`test_dct.cpp`, 43/4):** each transform vs its **direct O(N²) sum** (the brute-force analog, NOT forward∘inverse round-trip — the odeint-d4 trap), f32+f64; secondary dct3∘dct2 == 2N·x and dst3∘dst2 == 2N·x; run-twice determinism. Suite **109/20** on **4 configs (debug+asan+tidy+shipping)**.

## The shootout (`bench_dct_vs_refs.cpp` + `run_bench_dct.sh`, DCT-II f64, 1 thread, EXECUTE-only)

vs **PocketFFT** (numpy/scipy.fft.dct backend) and **FFTW** (REDFT10):

| N | vs PocketFFT | vs FFTW |
|---|---|---|
| 256–4096 | **1.0–1.6×** | 0.55–0.64× |
| 8192 | **1.50×** | 0.60× |
| 16384 | **1.30×** | 0.96× |
| 32768 | **1.69×** | **1.07×** |
| 65536–262144 | **1.5–1.7×** | 0.60–0.70× |
| 1048576 | **1.25×** | 0.64× |

⭐ The real-FFT path was the lever: it flipped **every** PocketFFT comparison to a win (the large-N losses 0.86×→1.25×) and closed FFTW from ~0.55× to ~0.65× (a win at 32768, parity at 16384). **Cerid DCT beats numpy/scipy/PocketFFT outright at all sizes.** FFTW stays ahead at most sizes via its tuned real-DCT codelets — the **same inherited FFT-engine kernel wall** as the raw complex FFT (FFTW's complex FFT is ~2× Cerid's; the DCT inherits it), NOT a DCT-specific gap. MKL's trig-transform DCT is the same kernel class (expected ahead, not separately benched).

**Honest verdict:** v10-f beats the **PocketFFT-backed peer (numpy/scipy)** — the most common one — outright; FFTW/MKL remain ahead on the shared FFT-kernel wall (the deferred Spiral-class scheduler item). DST-II shares the real-FFT path (same win expected; benched via DCT-II as the representative). Follow-ons (named): dct3/dst3 on the inverse real FFT, DCT-I/IV + DST-I/IV, FFT-convolution (overlap-add/save), the FHT.
