## What landed

- `http_fields.hpp`: prefix integers and the Huffman code (canonical, built at compile time from RFC 7541's 257 lengths), the one owner HPACK will share.
- `qpack.hpp`: `QpackDecoder` and `QpackEncoder` (RFC 9204) over one fixed-ring table. Everything S56 lists: blocked streams to the promise, references checked, the oversized section still acknowledged, the bounded decoder stream ending in `H3_EXCESSIVE_LOAD`; the encoder inserting on second sight, evicting only acknowledged unreferenced entries, duplicating fields about to fall out, never indexing credentials.
- `crd-fuzz-net-qpack` and `crd-net-qpack-interop-qifs`; the `qifs` pin on linux-gcc-public-checks (`CRD_BUILD_QPACK_VS_QIFS`). `http.qpack` implemented in the register.

## Evidence

- `crd-net-tests [qpack]` on win-debug and linux-gcc-debug: 36 cases, about 31,000 assertions: RFC 7541's integers and strings, RFC 9204 appendix B byte for byte with its table sizes. linux-gcc-release links clean.
- **Interop:** all 528 outputs of ls-qpack, nghttp3, proxygen, quinn, f5 and qthingey decode to the exact QIF text (qifs `encoded/qpack-06`, every table size and blocking mode); the corpus's refused inputs are refused, but `err9` and `err10`, which index the 61-entry table of early drafts and are valid today.
- **Compactness:** 0.3% above ls-qpack overall and smaller than the other five ([board](../bench/2026-11-09-4-2a-qpack-compression.md)).
- **Defects the first runs found, each now held by a test:** random traffic showed an entry evicted before its acknowledgement (section 2.1.1: a section could then exceed what the decoder's wrap can read); libFuzzer (UBSan) showed a Huffman value after a plain name decoded past the scratch buffer, a real overflow; the design of the duplicate first left a section referencing the original it had just evicted.
- `crd-fuzz-net-qpack` on linux-clang-fuzz after the fix: 846,954 and 734,552 executions, no finding; two artifacts in the corpus as regressions. One run in between stopped on an ASan report with the program counter on the stack, which did not replay (500 times in process, ten fresh processes): the host-misexecution class of [the lesson](../../MEMORY.md); its artifact (Base64 `AgOVlZWVQZWVVFRUVFRUVFRUVFRUVFRUVFRUVJWVlQEBBgEHAwUCAAYA//MBAwk=`) stays out of the corpus.
- Source mutations: 54, 53 failing a test; the one survivor (`index >= base` in `below_base`) is equivalent, as an unsigned wrap fails the liveness check that follows. Six first-round survivors each gained a test; one exposed dead logic in `may_block`, removed.
- Strict analysis clean on every touched file (`cerid_qpack_replay.cpp` is built only with the corpus option, under GCC `-Werror` here). The guards `crd-no-std-containers-check` and `crd-no-malloc-allocator` passed once the tests moved to the engine's containers (`text_fixture.hpp`).
