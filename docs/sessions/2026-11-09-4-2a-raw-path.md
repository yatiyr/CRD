## What landed

- `QuicConnection::open_keyed`: a QUIC connection started from a secret its session holds (a TLS exporter, or a launcher's random bytes), no TLS and no Initial or Handshake packet on the wire. `quic_keyed_traffic_secret` and `quic_keyed_connection_id` (crypto) derive per-side
  secrets and sequence 0 IDs; the transport parameters travel in 1-RTT CRYPTO frames with their grease and `version_information`; the server stays under 3x until its client acknowledges a packet; the policy generation can refuse the AEAD; the secret is zeroed.
- Retransmission and everything after the start stay the connection's: no second loss detector (one owner; ADR-0035 line amended, reasoning in S55).
- `QuicClient::open_keyed` and `QuicServer::open_keyed` beside TLS connections on one socket. A server opened with no peer takes the address of the first packet that opens, sends nothing before it, and a host can run with no TLS context at all (handshakes refused). `QuicHost` no longer tries to send to an unbound slot: the first test run found
  a forgery's bytes granting a send to port 0.
- `Net` (the seeded pair) moved from `test_quic_connection.cpp` to its fixture so the new tests share it. `#browsers` anchor moved back onto its section.
