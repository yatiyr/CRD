## CEIR-2a + 2b — the op generator arc — ✅ CLOSED (one gate)

Advisor-settled architecture: a checked-in **Python generator** reads per-dialect TOML and emits **committed** C++ that
self-registers through the CEIR-1d `Dialect::register_op` path — so "add an op with ZERO central-enum/switch edits" is
true by construction (§7 open-world). The advisor's sequencing correction (a validator with no consumer has no real
gate) → 2a+2b implemented as ONE arc, closed together.

**Artifacts:**
- **`engine/ceir/ops/README.md`** — the `*.ceirop.toml` schema contract: ALL §8 fields + the ADR-0110 §2.1
  `[op.native]` native-binding fields (provider/determinism/thread-safety/hot-reload/lifetime/cost/capabilities).
- **`engine/ceir/ops/arith.ceirop.toml`** — the example dialect: `const`/`addi`/`muli`/`cmpi`.
- **`tools/ceir_opgen/ceir_opgen.py`** — validator + deterministic codegen; `--check` drift mode; stdlib `tomllib`, no
  third-party deps.
- **`engine/ceir/generated/crd/ceir/gen/arith_ops.{hpp,cpp}`** — GENERATED (kind interners, typed wrappers, builders,
  verifiers, `register_arith_ops`); collected into `crd-ceir` + on its PUBLIC include path (`engine/ceir/CMakeLists.txt`).
- **`tools/ceir_opgen/test_opgen.py`** — 20 validator unit tests.
- **`tests/ceir/test_arith_gen.cpp`** — 3 C++ tests exercising the generated dialect.
- **`tests/ceir/CMakeLists.txt`** — `find_package(Python3)`; the `crd-ceir-opgen-drift` + `crd-ceir-opgen-validator`
  ctests (⛔ fail-loud `crd-ceir-opgen-NEEDS-PYTHON3` branch if Python is absent — an ungated generator is the tidy-blind
  scar; both dev + CI toolchains have Python, so the branch is CI-verified-by-construction).

**2a — the validator knows every field (structure + vocabulary), not just its key** (the advisor's blocking catch: the
first cut admitted `effects`/`deprecation`/`[op.native]` fields without shape-checking them). Now: type-checks every
accepted field (string/array/table/bool), enum-checks `determinism` against the fixed **ADR-0098** tier set, requires
`[op.native]` to carry `provider` + `determinism`, shape-checks `deprecation{since,replaced_by,note}` — each a
`file:line: error:` cook-time diagnostic (raw-text line-index pointing). 20 unit tests cover the negatives.

**2b — codegen.** Per op: a kind interner, a typed wrapper (named operand/result/attr accessors over `Operation*`), a
builder (through the ordinary Context factories — no privileged construction), a verifier (arity + region count +
required-attr presence/kind) registered via `register_op`, and per-dialect `register_<dialect>_ops(Context&)`
self-registration. Output is DETERMINISTIC (ops sorted by name, `\n` newlines, no timestamp, schema-version header) so
a regen is byte-identical.

**Resolutions of advisor points:**
- **`arith`, not `func`** — the advisor's example-dialect suggestion (`func`) would collide with the hand-written
  `func.hpp/cpp` from CEIR-1b (duplicate `register_dialect("func")` / wrapper redefinition). Used a fresh real dialect
  `arith` instead; the advisor confirmed the override was better-informed. (Migrating `func` itself to the generated
  form is a later consideration, not this arc.)
- **CRLF drift trap** — `--check` now normalizes `\r\n`→`\n` on the read side, so a git/editor line-ending rewrite of a
  generated file can never fire a byte-invisible drift failure.

**Gate:** crd-ceir-tests **54/54** on **win-debug · win-asan · linux-gcc-debug · linux-gcc-asan** (49 band-1 + 3 arith
+ 2 opgen ctests; Python3 found on both OSes) + LLVM-20 tidy **clean on the generated C++** (templates emit clean, zero
NOLINT) + the drift + validator ctests green on both OSes. The 2a validator hardening was a Python-only, config-
independent delta → re-verified by re-running the two Python ctests on win-debug + linux-gcc-debug (no 4-config rebuild).

**⚠ 2z sequencing:** the 2z gate row asserts wrapper/builder/verifier/**reflection**/**docs** all appear for a new op —
reflection emission is 2c and doc emission is 2d, so **2z is closeable only AFTER 2c + 2d land**. Sequence: 2c → 2d → 2z.

## CEIR-2c — reflection record + editor-node metadata + CLI/MCP schema — ✅ CLOSED

Extended `ceir_opgen.py` to emit the op schema as **queryable data**, three ways from ONE model (the advisor's
"derive, don't co-author" rule — no artifact can drift from another):

- **Reflection (C++)** — a hand-written shared `engine/ceir/include/crd/ceir/op_schema.hpp`
  (`OpSchema`/`OperandInfo`/`ResultInfo`/`AttrInfo`); the generated `.cpp` populates `constexpr` static arrays and the
  `.hpp` declares `<dialect>_op_schemas() -> ConstSpan<OpSchema>`. `constexpr` is safe because `crd::StringView` is
  `std::string_view` (fully constexpr) — checked the header before writing the template (front-loaded per the advisor).
  The semantic-heavy fields (`effects`/`domain`) + the `[op.native]` binding are **reflected now as raw strings** —
  reflection is exactly where schema-known-but-codegen-scaffolded data should surface (an agent sees `effects` the
  moment a TOML declares it, zero generator change at CEIR-4).
- **Editor-node metadata (§161)** — **satisfied by derivation**: input pins ≡ operands, output pins ≡ results, widgets
  ≡ attributes. No separate artifact (§161 is auto-layout + lenses, not a per-attr widget vocabulary — that's editor-
  band work).
- **CLI/MCP schema (§122)** — a committed `engine/ceir/generated/crd/ceir/gen/<dialect>.ops.json`, **derived from the
  same model** the C++ emitters consume, so it cannot drift from the wrapper/verifier. Deterministic: fixed key order,
  `ensure_ascii=True` (the em-dash → `—`, encoding-stable), trailing newline, `schema_version`. A data file
  discoverable without linking the engine (the right shape for agent discovery — the runtime-serialize alternative
  would couple discovery to a built binary). It rides the SAME `outputs()` fan-out, so the existing `--check` drift
  ctest now covers **3 files/dialect** for free.

**Tests (advisor's additions):** `test_arith_gen.cpp` gains a reflection↔codegen coherence case — `arith_op_schemas()`
is sorted-by-name and sized to the op count, and a const built via the generated builder has operand/result/attr counts
EXACTLY matching its reflected `OpSchema` (the §8 "no parallel truth" property, tested). `test_opgen.py` gains a
JSON-parses-and-matches-model case (21 validator cases total).

**Gate:** crd-ceir-tests **55/55** on win-debug · win-asan · linux-gcc-debug · linux-gcc-asan + LLVM-20 tidy CLEAN on
`op_schema.hpp` + the generated C++ + the drift(hpp/cpp/json)+validator ctests green both OSes.

**⚠ 2z still gated on 2d:** 2z's "docs appear for a new op" needs the doc emission from 2d — sequence stays 2c → 2d → 2z.

## CEIR-2d — doc + test-skeleton generation — ✅ CLOSED

Two new emitters, both DERIVED from the same model the C++/JSON already are (no parallel truth), both drift-guarded —
`--check` now covers **5 files/dialect** (hpp, cpp, json, md, smoke).

- **Doc (§123)** — a committed per-dialect `engine/ceir/generated/crd/ceir/gen/<dialect>.ops.md` op-reference: dialect
  summary + per op the qualified name, summary, docs prose, version, traits, regions, and — WHEN DECLARED — domain /
  effects / type-shape-inference / fold markers, a **DEPRECATED** badge with since/replaced_by/note, and the native
  binding; operands/results/attributes render as markdown tables with **pipe-escaped** doc cells (a `|` in a doc string
  would otherwise silently break the table). A `<!-- -->` DO-NOT-EDIT header (not the `//` C++ one). Co-located with the
  other generated artifacts (the glob only collects `.cpp/.hpp/.h`, so `.md`/`.json` are inert there).
- **Test-skeleton (§8)** — a committed, GATED, generated Catch2 smoke test `tests/ceir/generated/test_<dialect>_gen_smoke.cpp`
  that **grows from a TOML edit alone**: it registers the dialect + walks `<dialect>_op_schemas()` (sorted-by-name,
  size==op-count, each reflected op interns idempotently and `dialect_of`==the dialect) AND builds EVERY op through its
  generated builder — dummy operands from an unregistered source op's results, required attrs synthesized by kind — then
  asserts `Context::verify` accepts the well-formed result. This is the artifact 2z cites ("test skeleton appears").

**The advisor's second catch (freeze the guard at 2d, not 2z):** the first cut tested only the ACCEPT direction — a
verifier that regressed to a vacuous `return true` would pass the entire generated suite silently for every FUTURE
dialect (arith's hand-written malformed tests would hide it). So the smoke now also emits a third `TEST_CASE` that
constructs a MALFORMED op (no operands/attrs/regions, correct result count) and asserts the verifier REJECTS it —
emitted only for ops an empty construct is actually malformed for (`min_operands>0 or a required attr or a region`; a
pure-variadic-operand op is well-formed when empty and gets none), and the whole case is omitted when no op qualifies
(an assertion-free `TEST_CASE` would pass vacuously — the exact failure mode this guards). This HAD to land at 2d: 2z's
proof is "TOML edit alone, generator frozen," so a generator change smuggled into 2z would pollute the very claim 2z
certifies. All 4 arith ops qualify → 57→58. A `test_opgen.py` case locks the emission condition (pure-variadic → no
`CHECK_FALSE`; required-attr → one).

**The advisor's blocking catch (model completeness):** `validate()`'s `ops.append` was DROPPING four validated fields
(`deprecation`/`type_inference`/`shape_inference`/`fold`) — the doc is the user-facing artifact and under the no-defer
rule must render every validated field, so the model now retains them. `emit_json` emits them **conditionally (key iff
declared)** — arith declares none, so its committed `.ops.json` stays **byte-identical to 2c** (verified: 0 new keys),
no churn; a dialect that declares them (test.dummy at 2z) gets them.

**Placement fork (advisor-confirmed):** the smoke test lives under the TEST tree, NOT `GEN_DIR` — `GEN_DIR` is globbed
into the crd-ceir LIBRARY, so a test TU there would wrongly compile into the engine. `tests/ceir/generated/` is globbed
into crd-ceir-tests via the house `crd_collect_sources` (CONFIGURE_DEPENDS) — the SAME mechanism 2b already uses for the
engine's generated `.cpp`, so **a new dialect's smoke test builds with ZERO CMake edit**. `main()` now makedirs
per-output dirname (both GEN_DIR and the test dir), so a fresh regen on a clean tree creates both.

**Tests:** `test_opgen.py` +3 (24 total) — an every-op-heading / deterministic / pipe-escape **md** case, and a
**declared-optional-fields render in BOTH md + json** case (deprecation/effects/domain/inference/native — the branches
arith cannot reach, so the new emitters aren't only ever proven against arith's narrow surface); and a
**negative-case-emitted-iff-empty-is-malformed** case (a pure-variadic-operand op emits no `CHECK_FALSE`; a required-attr
op emits one — locking the emission condition against a future regression).

**Gate:** crd-ceir-tests **58/58** (55 + 3 generated smoke) on **win-debug · win-asan · linux-gcc-debug · linux-gcc-asan**
+ LLVM-20 tidy CLEAN on the generated smoke `.cpp` + drift(5 files/dialect) + validator(24) green both OSes.

**⚠ 2z is now UNBLOCKED** (2c reflection + 2d docs/test-skeleton both landed): adding a `test.dummy` op by a TOML edit
alone must make wrapper/builder/verifier/reflection/**docs**/**test-skeleton**/JSON ALL appear + the dialect
self-register, zero central edits. To make the 2z gate prove more than arith's narrow surface, `test.dummy` will
exercise the FULL field surface (a variadic operand, several attr kinds, effects, domain, native, deprecation).

## CEIR-2z — the §7/§8 zero-central-edit gate — ✅ CLOSED → BAND 2 CLOSED

A new **full-surface reference dialect `test`** was added by writing **ONLY** `engine/ceir/ops/test.ceirop.toml` —
`git status` shows the new `.toml` plus its generated artifacts and nothing else (no central enum/switch, no generator
edit, no CMakeLists edit). One `python tools/ceir_opgen/ceir_opgen.py` produced **all seven** artifacts —
`test_ops.{hpp,cpp}` (kind interners, typed wrappers, builders, verifiers, `register_test_ops`, reflection),
`test.ops.json`, `test.ops.md`, and `tests/ceir/generated/test_test_gen_smoke.cpp` — and the smoke test **built and
passed with zero CMake edit** (the house CONFIGURE_DEPENDS glob). **The §7/§8 open-world property, proven end-to-end.**

`test.dummy` = fixed + variadic operands, required int/string + an **optional** bool attr (arith had no optional attr),
a region, **multi-trait** `Symbol|IsolatedFromAbove`, `effects=[read,write]`, `domain`, the declared-marker
`type_inference`/`shape_inference`/`fold`, a full `[op.native]` binding, `deprecation` — **every field the schema can
express** (the advisor's close catch: the first cut omitted the three inference/fold markers, so the "full-surface"
claim was false and the committed `.md`/`.json` never demonstrated those rendering branches; adding them reaches only
`emit_json`/`emit_md`, so the 3 generated C++ files are **byte-identical** — md5-verified — and the re-gate was the
Python drift+validator ctests on win-debug + linux-gcc-debug, the same config-independent-delta precedent as 2a).
`test.kinds` = a required attr of every remaining kind (float/bool/symbol/type). Together they
**first-ever-compiled** the effects `constexpr StringView[]` path, the multi-trait `OpTrait::A|OpTrait::B`
register+reflection path, the intrinsic-reflection path, and the float/bool/symbol/type builder + `_ATTR_FACTORY` paths —
none of which arith's narrow surface reached. (`Context::verify` calls only the registered verifier — no trait-driven
`Symbol ⇒ sym_name` rule — so the trait-carrying `dummy` verifies without a `sym_name`.)

**Pre-2z generator errata (the "phase-0 errata / phase-1 TOML-alone" split, so the zero-edit proof stays clean).** The
advisor flagged that `test.dummy` would be the first compile of several paths, and three carried latent defects the
narrow arith surface had hidden. All three were fixed with **arith byte-identical** (verified by `--check`), then the 2z
gate compiled the amended paths on all 4 configs:
1. **Lone-variadic tautology** — an op whose only operand is variadic emitted `if (op.num_operands() < 0U)` (always
   false; `-Wextra`/tidy bait). Guarded: no operand-count check when the fixed prefix is empty. (`test.dummy` is
   fixed+variadic, so it emits the correct `< 1U`.)
2. **`effects` element unvalidated** — `emit_cpp` did `_cstr(str(e))`, so a non-string element would embed a Python
   repr into C++. Added the element `isinstance(str)` check + a negative test (the 2a "validator knows every field's
   shape" doctrine).
3. **md rendered Python bools** — `thread_safe=True`/`False` instead of `true`/`false`. Added `_fmt_scalar` (bool →
   lowercase) + an assertion in the md/json optional-fields test.
   `_traits_expr`'s multi-trait branch was **investigated and found correct** — `OpTrait` is a bitmask enum
   (`1U<<n`) with `operator|(OpTrait,OpTrait)→u32` and `operator|(u32,OpTrait)→u32` overloads (dialect.hpp), so
   `OpTrait::A | OpTrait::B` compiles and ORs correctly. No fix; the advisor's conditional ("if no `operator|`
   exists") resolved to the no-op branch, and `test.dummy` compiling confirms it. `test_opgen.py` 24 → **26**.

**Gate:** crd-ceir-tests **61/61** (58 + 3 `test` smoke) on **win-debug · win-asan · linux-gcc-debug · linux-gcc-asan**
+ LLVM-20 tidy CLEAN on the 3 new generated C++ files + drift(**10 files** = 5 per dialect × 2) + validator(26) green
both OSes. **BAND 2 CLOSED.**
