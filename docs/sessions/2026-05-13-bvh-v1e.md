## What we built / changed

- **`bvh_closest_point(const BvhTree&, ConstSpan<AABB3<f32>> prims, const Vec3<f32>& query, f32 max_dist = ∞) → optional<BvhClosestPoint>`**
  in `crd/geometry/bvh/bvh_query.hpp` (decl + `BvhClosestPoint { u32 prim_index;
  Vec3<f32> point; f32 distance_squared; }`), impl in `src/bvh_query.cpp`.
  Branch-and-bound stack DFS: the per-node AABB squared distance to `query` is a
  lower bound on every leaf below it, so a node whose lower bound ≥ the current
  `best_d2` is pruned — *re-checked on pop* (the best may have tightened since
  this node was pushed). At an interior node both children's AABB distances are
  computed and the *nearer* child is pushed last (popped first) so the best
  tightens before the far subtree is reached; a child already known not to beat
  the best is skipped at push. All comparisons stay in squared space (`max_dist²`
  cutoff stored, no `sqrt` on the hot path). A small anon-namespace
  `aabb_dist2(box, q) = dot(closest_point(box, q) − q, …)` keeps this TU
  independent of `closest_point.hpp` (`closest_point(AABB3, Vec3)` lives in
  `primitives.hpp`). Returns `nullopt` for an empty tree or when nothing is
  within `max_dist`. Closest point on the primitive *AABB* — per-triangle
  closest-point inside a leaf is `crd-geometry-mesh` (v4); the `Bvh4Tree` /
  `DynamicBvh` closest-point land in the v1i query facade.
- **`tests/geometry-bvh/test_bvh_closest.cpp`** (new, 5 cases): empty tree →
  nullopt; matches a brute-force-over-all-AABBs reference on random corpora

## Plain-English explanation

"What's the nearest object to this point, and where on it?" — done with the BVH
the same way ray queries are: walk the tree, but instead of "does the ray hit
this box?" ask "how far is this box from the point?". If a box is already farther
than the best object found so far, skip its whole subtree (the box is a lower
bound on everything inside it). Descend the closer child first so the "best so
far" shrinks fast, which prunes the far side. There's an optional `max_dist`
cutoff (don't bother if nothing's within range). It returns the closest
primitive's AABB-point; refining to the actual triangle/surface inside a leaf is
a later sub-module (`-mesh`). This is exactly what the SDF baker needs (closest
point on a mesh, accelerated) and what a scene's spatial index exposes.

## Decisions made

- Closest point is on the primitive **AABB** in v1e — per-triangle / per-surface
  closest-point inside a leaf is `crd-geometry-mesh` (v4); the `Bvh4Tree` /
  `DynamicBvh` closest-point overloads are the v1i query facade's job.
- The `BvhClosestPoint` result carries `distance_squared` (not `distance`) — the
  query never needs a `sqrt`, and callers that want the linear distance take one
  `sqrt` themselves. Matches the "squared space on hot paths" idiom.
- `bvh_query.cpp` stays off `closest_point.hpp` via the local `aabb_dist2`
  helper (the only AABB↔point distance it needs) — `closest_point(AABB3,Vec3)`
  is already in `primitives.hpp`, so no extra header coupling.
- Roadmap: the §15 checklist additions slot **after `-bvh` v1g** (v1h/v1i/v1j),
  so the `-bvh` slices finish in order first (v1f next).
