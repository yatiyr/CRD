# Session — 2026-04-30 — `crd-shader` 2.3f hot reload

## Goal

Make shader reload real and safe: successful reload swaps atomically, failed
reload keeps last-good state, and consumers observe the outcome without losing
stable effect identity.

## What we built / changed

- **Runtime reload path**
  - compile/rebuild fresh data off to the side
  - swap into live state only after the full compile/reflection/cache path succeeds
- **Last-good fallback**
  - failed reload keeps the current live modules and effect metadata intact
- **Stable identity**
  - `EffectHandle` remains stable across reload
  - variant handles remain queryable after reload
  - module entries are refreshed in place where possible so live lookups stay coherent
- **Tests**
  - successful reload after source change
  - failed reload preserves last-good state
- **Smoke**
  - `smoke_shader` now performs one successful reload and one failing reload,
    logging `ReloadEvent` behavior cleanly

## Plain-English explanation

The shader system can now survive source changes at runtime without leaving the
engine in a half-updated state. Good source swaps in; bad source is rejected and
the last working version keeps running.

That is the minimum professional behavior needed before `crd-shader` can become
the real dependency boundary for renderer/material work.

## Decisions made

- Reload is atomic from the consumer point of view.
- Last-good state is preserved on failure.
- We kept the public API small: `ReloadEvent` is the observability surface,
  not a flood of backend-specific state.
