# Session — 2026-05-13 — Phase 3.1.7 v1c: `DynamicBvh` (incrementally-updatable AABB tree)

## Goal

Third `crd-geometry-bvh` slice: the dynamic AABB tree — insert / remove / update
with height-balanced tree rotations and a fat-AABB margin. The static `BvhTree`
(a packed array from a one-shot binned-SAH build) can't support arbitrary
insert/erase without a rebuild, so this is its own structure. Catto GDC 2019 /
Box2D v3 `b2DynamicTree` — the form `crd-eylem`'s broadphase (eylem v1c) wraps.

## What we built / changed

- **`include/crd/geometry/bvh/dynamic_bvh.hpp`** (new, public; added to the
  umbrella `bvh.hpp`): `DynamicBvhNodeId` (stable handle), `DynamicBvhConfig`
  (`fat_margin`, default 0.1), `inline constexpr usize k_max_dynamic_bvh_stack = 256`,
  and `class DynamicBvh`. Private 48-byte `Node` — `aabb` (fat) / `parent` /
  `child1` / `child2` / `user_data` / `next_free` (free-list link) / `height`
  (`-1` = free slot, `0` = leaf, `≥1` = interior = max-child-height + 1). The
  `query` / `raycast` templates are header-inline (fixed `u32 stack[256]` DFS
  visiting leaves by fat AABB — broadphase; `raycast` uses the v0f
  `precompute_ray_aabb` / `intersect_ray_aabb_robust`).
- **`src/dynamic_bvh.cpp`** (new): the node pool (`allocate_node` pops the free
  list or grows; `free_node` resets the slot to `Node{}` and chains it),
  `fit_node_to_children`, `balance` (Box2D's `b2DynamicTree::Balance` — if a
  child's height exceeds its sibling's by >1, rotate that child up, picking the
  taller of *its* children to keep; returns the new subtree root; mirror cases
  for child1/child2), `insert_leaf` (greedy best-sibling descent — Box2D-style
  cost: `2·halfArea(union)` to make a parent here vs.
  `halfArea(union(child,leaf)) − halfArea(child) + inherit` to descend, with a
  deterministic c1-on-tie; create the new internal parent; refit + `balance` up
  to the root), `remove_leaf` (promote the sibling into the grandparent — or
  make it the new root — free the old parent, refit + `balance` up), the public
  `insert` / `remove` / `update` (update: if the stored fat AABB still encloses
  `new_tight` ⇒ no-op + `false`; else `remove_leaf` + reset the slot's links +
  `m_nodes[leaf].aabb = inflate(new_tight, margin)` + `insert_leaf` ⇒ handle
  stays valid, returns `true`), `bounds` / `query(box, Array<u32>&)`, and the
  diagnostics `sah_cost` (Σ interior-node half-areas / root half-area), `max_depth`
  (iterative DFS over (idx, depth)), `validate` (debug — root parent is null;
  for each node: leaf ⇒ child2 null + height 0; interior ⇒ both children present,
  child→parent links consistent, height = 1 + max child height, AABB encloses
  children; leaf count matches; `[[maybe_unused]]` on the assert-only locals so
  the Release `/WX` build doesn't flag C4189).
- **`src/aabb_ops.hpp`** (from v1b) gains no new entries — `dynamic_bvh.cpp`'s
  anon namespace adds its own `aabb_union` / `aabb_inflate` / `aabb_contains`
  and reuses `detail::aabb_half_area`.
- **`bvh_update.hpp`**: the v1c forward-pointer reworded — incremental
  insert/erase is `dynamic_bvh.hpp`'s `DynamicBvh`, not `bvh_insert`/`bvh_remove`
  free functions on `BvhTree`.
- **`tests/geometry-bvh/test_dynamic_bvh.cpp`** (new, 7 cases): empty tree +
  single leaf (bounds, depth, `validate`); `query` overlap vs a brute-force
  reference over the leaves' *fat* AABBs (+ the `Array<u32>` overload);
  `raycast` vs brute force over fat AABBs; `update` is a no-op when the new tight
  box stays inside the margin and reinserts when it escapes (then found at the
  new location, not the old; the handle stays valid; the other leaf untouched);
  structural validity + query correctness across a 4000-op random
  insert/remove/update sequence (`validate()` every 250 steps, full query
  cross-check at the end, `leaf_count` consistency); after 2000 inserts the
  depth is `≤ 3·log₂(n) + slack` and `sah_cost` is finite; handles stay valid
  after operations on other leaves.

## Plain-English explanation

When objects move around, you don't want to rebuild the spatial index every
frame. The dynamic AABB tree solves this: each object gets a leaf with a box
slightly bigger than it actually needs (the "fat" margin). When the object moves
a little, it's still inside its fat box — nothing changes. When it moves enough
to poke out, you pull the leaf and re-insert it where it now belongs. To stop
the tree from degenerating into a linked list after lots of inserts/removes, it
does a small "rotation" at each affected node — swap a deep grandchild up — so
the tree stays roughly log-deep. Queries (which boxes overlap this box? which
boxes does this ray pass through?) walk the fat boxes and hand the consumer a
list of candidate primitive ids; the consumer does the precise test itself.
That's exactly what a physics engine's broadphase wants — and `crd-eylem` will
wrap this directly (eylem v1c). The static `BvhTree` from v1a/v1b is the other
half: a tightly-packed, high-quality tree for data that doesn't change (cooked
meshes, static geometry).

## Decisions made

- **`DynamicBvh` is its own type**, not free functions on `BvhTree` — the static
  packed array genuinely can't do incremental insert/erase. (`bvh_update.hpp`'s
  earlier promise of `bvh_insert`/`bvh_remove` on `BvhTree` is retracted; the
  comment now points at `dynamic_bvh.hpp`.)
- **Box2D `b2DynamicTree` shape**: greedy best-sibling insertion (the simpler
  cost-descent, not the full GDC branch-and-bound — the rotations recover most
  of the quality) + height-based single rotations + fat-AABB margin + a free
  list. Deterministic c1-on-tie in the sibling descent and the rotation.
- **Queries report by fat AABB** (broadphase semantics) — the caller refines.
  No nearest-hit ordering on the dynamic `raycast` (the static `bvh_raycast`
  already does nearest over tight boxes; the dynamic tree's nearest, if a
  consumer wants it, is a later concern).
- Allocator (standing directive): `DynamicBvh` takes `IAllocator*` and all node
  storage comes from it. (The static-build transient-scratch refinement noted in
  v1b still stands; nothing new here.)
- The `validate()` C4189 (assert-only locals unreferenced in Release) is the
  same gotcha the shipping-config-hardening session documented; fixed with
  `[[maybe_unused]]`.
