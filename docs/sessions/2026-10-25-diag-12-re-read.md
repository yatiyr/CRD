## Fixes in this batch

- **The log mutex (DIAG.2b, DIAG.5a/5b).** The acceptance says a crash while the ordinary log mutex is held still
  yields an emergency record. The `logger_lock` mode held only the CRT stdio lock, never crd::log's own sink mutex.
  It now faults inside a crd::log sink's `write`, while holding both locks. The specimen links `crd-log`. The Windows
  and Linux cases are renamed for what they prove.
  - Teeth: a crash hook that calls `CRD_LOG_CRITICAL` fails both cases with `verdict=Timeout`. On win-debug the
    handler thread blocks on the sink mutex. On linux-gcc-debug the faulting thread locks it a second time.
    Restored, rebuilt, both pass.
- **Stale text.** The DIAG.0 lead said "flip to Needs CI on the maintainer push", and the DIAG.1b lead said the TSan
  lane was never hosted; both rows are Done, so the phrases are removed. crd-perf's CMake header described the v0a
  substrate (two dependencies, GPU work "in crd-rhi-vulkan"). `Category`'s comment said "reserved for v0c ...
  rhi-cmd". Both comments now describe the module as it is.
