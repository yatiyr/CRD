# CEIR-6 — Async / task / runtime domains (§30/§31/§37/§38) — session log

Band 6 makes CONCURRENCY a first-class CEIR semantic (§30): tokens / async values / joins / race / cancellation
(`ceir.async`, §37), then the crd-jobs execution provider + `ceir.task` (§38) in the **`crd-ceir-host` bridge** (ADR-0109 —
crd-ceir stays host-only + jobs-free), then structured-concurrency scopes. Band gate (6z): a parallel map-reduce authored
as CEIR runs on the fiber pool, bit-identical across `{1..16}`.

## CEIR-6a — the `ceir.async` ops + the §116 use-once token-misuse verifier — CLOSED ✅ (BAND 6 OPENS)

**§37-text checked first.** §37 `ceir.async` owns tokens / async values / waits / groups / joins / race-select /
cancellation / dependencies; §116 "race detection" lists "async token misuse" as a static-analysis class; §30 wants
STRUCTURED concurrency (not detached spawns). 6a = the ops + the verifier, host-only (ADR-0109 — the jobs provider is 6b).
Read rows 6b..6z FIRST (the 5c §34-check lesson) so every deferral pins to a real row.

**The ops (a NEW `ceir.async` dialect via the 2a generator):** `launch { region } -> %token` (structured fork),
`await(%token) -> (%v…)`, `join(%t…) -> %token` (all-of), `race(%t…) -> %index` (any-of, index-only), `cancel(%token)`.

**Fork 1 — tokens are TRAIT-typed, not TYPE-typed (advisor).** Two NEW `OpTrait` bits: **`TokenProducer`** (`1<<6` —
convention: EVERY result is a token) + **`TokenConsumer`** (`1<<7` — convention: EVERY operand is a consumed token,
revisitable per the StateEdge-last-operand precedent when a mixed-operand op arrives). `join` carries BOTH; `race` is
consumer-only (its index result is NOT a token). Why trait not `!token` type: (a) a producer trait CAN'T be forgotten,
whereas TOML `type`s are doc-only + builders take a caller `result_type`, so a mistyped token is invisible to a type-keyed
verifier (the 3z construction hole); (b) `TypeKind::AsyncToken` would drag print/parse grammar + canonicalization + binary
decode bounds + the 3a fuzz "every kind" claim; (c) §37's async-VALUE type (`!async<T>`, a future holding a typed value)
genuinely needs the type system — routed within §37 to the slice that needs typed results, NAMED not silently subset.

**Forks 2+3 — use-once linear, on Context, trait-keyed.** `Context::find_token_misuse(Module&) -> {value, op, kind}`:
§116 is the taxonomy, but the MECHANISM is linear use-counting (4d compares read/write on resource classes and CANNOT
express "exactly once"). One pre-order walk (uses BEFORE defs — a token dominates its uses, so a producer is seen first;
producers before region-recursion). Kinds (no-default `-Werror=switch`): `Unconsumed` (0 consuming uses — a leaked async
op), `MultiplyConsumed` (>1 operand SLOTS — `join(t,t)` counts 2, tested), `ConsumedByNonConsumer` (a token operand of a
non-`TokenConsumer` op). Use-misuses caught at the offending use; the post-walk finds the first unconsumed producer.

**The rule's conscious edges (each pinned with a test):** exactly one static consuming use.
1. Consumed in BOTH `if`-branches = 2 static uses = flagged (no path-sensitivity substrate — named relaxation).
2. A token YIELDED out of a region / passed to a `func.call` / fed to arith = `ConsumedByNonConsumer` ⇒ **tokens are
   region- AND function-CONFINED — §30's structured discipline falls out FREE** (no separate escape verifier).
3. Produce-outside / consume-inside a LOOP = 1 static use = passes — a documented gap (dynamic multiplicity needs
   execution knowledge).
4. `cancel` consumes: every token is awaited XOR cancelled, no silent drops.

**⛔ Register-to-verify — the OPPOSITE failure direction from 5d (advisor).** 5d over-flags an unregistered module
(noisy, safe); here an unregistered async module has no `TokenProducer` traits ⇒ zero tokens tracked ⇒ a leak passes
VACUOUSLY (a false NEGATIVE — the perf-flag-measures-empty-frame shape). Can't fix structurally (traits are registry
state; name-sniffing breaks I6) — the consumer MUST register the dialect. Tested: print an Unconsumed module → parse into a
fresh ctx WITHOUT async → None (vacuous) → `register_async_ops` LATE (OpId is a content hash; `has_trait` binds at query
time) → Unconsumed.

**Catch #2 — async ops declare ambient `Synchronization`, NOT structured-zero-effects.** The 5a zero-effects rule ("the
block walk sees the contents in place") is WRONG for `launch`: its region runs at an UNSPECIFIED later time, so seeing its
contents at the launch point is a lie. Conservative-correct: all five ops declare ambient `Synchronization` (a Universe
barrier — 4d reorders nothing across them); token-mediated precise ordering is a named later refinement. Determinism:
`race` = `Nondeterministic`; others Unspecified. ⚠ **Finding (my "check whether" resolved):** Unspecified ALSO fails
Deterministic compiler mode ("you cannot certify what was never classified") — so the mode-composition test asserts
`find_mode_violation == l0` (the first async op, pre-order) + a DIRECT `op_determinism(race) == Nondeterministic`, rather
than forcing `race` to flag first.

**⭐ Catch #1 — the §32 Synchronization FLIP.** Band 6 introduces the engine's first BLOCKING waits. `effect_legal_in_
region` now forbids `Synchronization` in an audio-real-time region — a blocking `await` in an audio callback IS the
priority-inversion §32 exists to forbid; the flip lands WITH the waits (NOT a new "legal-for-now", the 5c ExternalCall
pattern). Blast radius checked (only test_effect/test_hazard reference Synchronization, neither in audio — nothing broke).
Both sides tested + the **5c×6a path**: a `func.call` to an async helper flags Synchronization in an audio region via
`effective_effects` (the EffectsFn machinery picking up the newly-forbidden family — free).

**Executor: a NAMED `NoSemantics` deferral.** Async reference semantics land with the crd-jobs provider at CEIR-6b (the
`foreach` precedent — an uninstalled op is a typed `NoSemantics`, tested). The TOML `docs` PIN the executor contract
(launch runs at an unspecified time; the sequential reference runs it at launch; race = the first ready) so 6b implements
written words.

**Layered verification (one sentence each):** a self-await (`launch { await(own token) }`) is rejected upstream by 5b's
capture-after-owner rule (the token isn't visible inside its own producer's region) — 5b + 6a compose. A launch body
awaiting a SIBLING token is 1 static use → passes — §37's "dependencies" line landing, not an oversight.

**Deferrals pinned to real rows:** `ceir.task` + the crd-jobs provider (the first `IExecutionProvider`, in the
`crd-ceir-host` bridge) + async EXECUTOR semantics → **6b**; structured-concurrency `group`/scopes + cancellation plumbing
→ **6c** (so 6a builds NO `group` op — its discipline already falls out of use-once + no-escape); `!async<T>` async-value
types → within §37 to the slice needing typed results.

`test_async.cpp` — 13 `[async]` cases (71 assertions): well-formed launch→await / launch→cancel / join-chain / race;
Unconsumed; double-await + `join(t,t)` slot-count; token→arith / token-yielded / token→func.call (the three confinements);
both-if-branches; open-world hand producer/consumer; the Synchronization barrier (`ops_hazard` Waw); the audio flip both
sides + the 5c call path; the loop-edge gap; register-to-verify vacuous-None; race-nondeterminism + Deterministic-mode; the
`NoSemantics` deferral.

## CEIR-6c — structured-concurrency scopes + cooperative cancellation (2026-08-09)

**Delivered.** `async.scope { region } -> (%results…)` (via the 2a generator): a structured-concurrency
boundary — `Synchronization` effect, a graph region, variadic results (the join-at-exit surface). Cooperative
cancellation and the RealtimeClass→Priority dispatch map plumbed through the provider.

**The design decision — scope-confinement is LAYERED, not new verifier code (advisor, on the design fork).**
§30's structured-concurrency discipline for scopes does NOT need a new verifier: a token launched inside a
scope and consumed *outside* it is already `UseBeforeDef` (5b def-before-use), and a scope token never awaited
is already `Unconsumed` (6a linear token-misuse). So scope confinement falls out of the 5b+6a substrate FREE —
exactly as 6a's region/function confinement fell out of `ConsumedByNonConsumer`. This is PROVEN by tests, not
asserted: (a) a scope-launched token used after the scope → `UseBeforeDef`; (b) scope-launched, never awaited →
`Unconsumed`; (c) a `Synchronization` scope inside an audio-real-time region → `find_domain_violation` flags it
via the 6a §32 flip. The `async.scope` TOML `docs` pin this ("scope-confinement is LAYERED verification (5b+6a),
not new code"; "SEQUENTIAL reference is a no-op boundary; jobs-backed joins at exit").

**Cooperative cancellation (§30).** A new `ExecError::Cancelled` + a `const std::atomic<bool>*` cancel flag on
the Interpreter (`set_cancel_flag`/`cancelled()`, NOT proto-copied — each per-item clone gets its own pointer),
checked at the top of `eval_block`/`eval_for`/`eval_while` (op- and loop-iteration granularity) BEFORE the fuel
spend. ⛔ crd-jobs has NO cancel primitive — cancellation is COOPERATIVE by construction: a running op finishes;
the loop observes the flag next iteration. `HostProvider::request_cancel()` sets a provider-owned
`std::atomic<bool>` threaded into the prototype AND every per-item sub-interpreter (`RangeJob.cancel`), so a
mid-flight parallel map stops at op granularity. The test uses a PRE-SET flag (a mid-flight cancel is inherently
racy) — the deterministic assertion is Cancelled-beats-Fuel with a huge `sub_fuel = 1<<40`.

**RealtimeClass→Priority map in the BRIDGE (I4).** `priority_for(RealtimeClass) -> crd::jobs::Priority`: a
region's §32 RealtimeClass tag drives the `parallel_for` dispatch Priority (AudioRealTime/FrameCritical→High ·
Background/Offline→Low · rest→Normal) — a TOTAL no-default switch (a new §32 class is a `-Werror=switch` compile
error). ⛔ It maps crd-ceir vocabulary to a jobs TYPE, so it CANNOT live in crd-ceir without breaking I4
(crd-ceir names no jobs type) — it lives in `crd-ceir-host`, and `crd-ceir-invariants` stays green. ⚠ The map arm
is NOT dead code: the provider runs no verifier before `execute`, so the `AudioRealTime→High` arm is reachable on
an unverified module even though `find_domain_violation` would flag a Synchronization-in-audio region — the
provider does not gate on verification (that is the caller's contract).

**Deferrals — pinned to real rows (advisor ledger; no vague "routed forward").**
- The row title's **DEADLINE** attr: DECLINED-WITH-REASON. crd-jobs has no deadline primitive, so an attr no
  scheduler reads is the cook-only-gate anti-pattern → **CEIR-21/26** (§69 provider planning, where a
  deadline-aware scheduler is decided). Priority DID land (the map above).
- **Jobs-backed parallel async** (`launch`/`await` on the pool vs. today's sequential-reference) → **CEIR-6z**:

## CEIR-6z — the BAND-6 GATE: a fixed-order map-reduce, bit-identical across {1..16} (2026-08-09)

**The gate.** Band 6 is proven by AUTHORING a real program: a parallel map-reduce that runs on the fiber pool and
whose scalar result is bit-identical for every `num_jobs` in {1..16}. This is the in-IR reduction the
`task.parallel_for` docs pinned to 6z ("the in-IR reduction is authored separately -- CEIR-6z").

**Delivered.** A NEW `task.map_reduce(%lo, %hi, %step, %init) map { ^m(%iv): … } combine { ^c(%acc, %elem): … } ->
%result` op (via the 2a generator). Operand order **(lower, upper, step, init)** so the shared `run_parallel_map`
helper reads operands 0..2 identically for both task ops (advisor). The provider (`HostProvider`) runs the MAP in
parallel (`crd::jobs::parallel_for`, disjoint index-order slots -- the 6b machinery, refactored into
`run_parallel_map` shared with `parallel_for`), then folds the results SEQUENTIALLY in INDEX ORDER
(`acc = init; acc = combine(acc, out[i])`, i = 0..count). The result is num_jobs-INDEPENDENT and bit-identical
across all {1..16} even for a NON-associative combine: the map output is index-order-disjoint (split-independent)
and the fold order is FIXED. `map_reduce` has an SSA result (unlike statement `parallel_for`), so it composes
inside `async.scope` -- the gate wraps the map-reduce in a scope, `async.scope`'s FIRST run through HostProvider
(6c could only test it in-core -- the scope×provider composition seam).

**The design fork (advisor first).** Options were: (A) `task.map_reduce` with a provider-folded combine region;
(B) host-side reduce (rejected -- not "authored as CEIR", a shortcut); (C) an array VALUE domain so a `core.for`
reduces the map output (rejected -- big feature, `map_output` exists precisely BECAUSE there is no array value
domain). (A) is the substrate-respecting gold standard and is exactly what the parallel_for TOML pinned to 6z.

**Landmines the advisor flagged, each closed.**
- **Fold re-entrancy:** `eval_map_reduce` runs ON the proto mid-`invoke` (its frame is live). The fold does NOT
  call `invoke_region` re-entrantly on `in`; it clones ONE fresh sub-interpreter from the prototype (own
  MallocAllocator, `sub_fuel`, `set_cancel_flag`) and runs every fold step on it.
- **Bit-exact-blind scar:** cross-num_jobs identity alone would pass 16 identical WRONGS. The gate pairs it with an
  INDEPENDENT wrapping-u64 reference fold. The combine is NON-associative (`acc*31 + elem`) so identity actually
  proves the fold order is fixed. The reference wraps in u64 (mirrors the executor's i64) -- else the test itself
  is signed-overflow UB.
- **`invoke_region` block-arg bind:** it already guards `block_args.size() != num_args` with `BadArity` (no OOB);
  the pre-flight arg-count check (`check_parallel_region`: map=1, combine=2) is defense-in-depth on the submit
  thread, reusing `BadArity` (no new `ExecError`, no `-Werror=switch` ripple). It also hardens the latent
  parallel_for map-arity gap.
- **N = 37 (prime >= 16)** so every num_jobs in {1..16} splits the range raggedly; **empty-range identity**
  (`map_reduce(0,0,1,init=42) -> 42`) tested BARE outside any scope (the happy path off the scope seam);
  **`advertises(task.map_reduce)`** extended.

**crd-ceir stays jobs-free.** The whole reduction lives in the bridge (`host_provider.cpp`); exec.hpp/cpp are
untouched. `crd-ceir-invariants` green.

**Deferrals routed (advisor ledger, real rows).** jobs-backed launch/await-ON-POOL (today's async is
sequential-reference) + §38's six residual task ops (spawn/continuation/main-thread/worker/fiber-wait/task-group)
-> **CEIR-8a** (§84 async-host subset; inbound noted at the 8a row). deadline attr -> CEIR-21/26 (6c). The band
contract paragraph + the 6a/6b/6c rows were struck in place to record all of this. Band 6 is CLOSED.

**Build note (win-asan / the ASan DLL PATH scar).** A backgrounded or fresh-shell `ctest` on win-asan HANGS on a
missing-DLL modal dialog (`clang_rt.asan_dynamic-x86_64.dll`) -- prepend the MSVC `Hostx64\x64` bin (where the ASan
runtime lives) to PATH before invoking ctest. BUILDING.md already records the ASan DLL PATH scar for running the

**Gate.** crd-ceir-tests **209/209 ctest** (207 + 2 `[host]`) on **win-debug + win-asan + linux-gcc-debug +
linux-gcc-asan** -- the {1..16} bit-identity proven ASan-clean under 4 threads on linux-gcc-asan (the money config
this gate existed to reach) -- + LLVM-20 tidy (2 files) + GCC `-Werror=switch` (no new switch) + opgen
drift/validator (the new op) + `crd-ceir-invariants` (crd-ceir STILL jobs-free) + invariants. No binary version
