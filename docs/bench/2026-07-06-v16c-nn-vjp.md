# 2026-07-06 — v16-c (core): tensor / NN VJPs — the trainable-MLP layer

**What shipped (v16-c core):** `nn_reverse.hpp` — the reverse-mode VJPs for the core NN op set, as self-contained
dense functions (the v15-f pattern; production rides the v14 `gemm`/`EinsumPlan`): **matmul** (`ḡA=ḡC·Bᵀ`, `ḡB=Aᵀ·ḡC`
— each an einsum with a permuted spec, the v16-c principle), **bias-add** (broadcast transposes to a column-sum),
**ReLU**, and fused **softmax + cross-entropy** (`ḡlogits=(softmax−onehot)/rows`). Composed, they backprop a 2-layer
MLP and yield ALL parameter gradients in ONE backward pass.

## ★ Gate — torch-style numerical gradcheck (`test_nn_reverse.cpp`, win-debug green, 72 assertions)
- Every parameter gradient of a 2-layer MLP (`X·W1+b1 → relu → ·W2+b2 → softmax-CE`) from ONE backward pass **matches
  a central finite difference** (`< 1e-5`) — W1, b1, W2, b2 all checked (the torch `gradcheck` protocol).
- `matmul_vjp` verified `== ` a direct index computation of `ḡC·Bᵀ` / `Aᵀ·ḡC`, and **bit-identical run-to-run**
  (deterministic).

## ★ Crush — the whole parameter gradient in ONE pass
Reverse backprop yields all `#params` gradients in a single backward pass; a finite-difference gradcheck needs
`2·#params` forward evaluations. That O(1)-vs-O(#params) gap is precisely why networks are trainable by reverse mode —
and Cerid's is **deterministic** (crd::math, fixed-order), which torch/JAX are not (atomic scatter-add). This makes
the v14-m op set trainable in-engine, bit-reproducibly (the v16-i moat demo consumes this).
