## Correctness — the 3-oracle gate (`gradient_check.hpp`)
Every rule / functor differentiated THREE independent ways and cross-checked (`test_jvp_rules.cpp`):
1. **analytic** — one `Jet<double,N>` pass (the rules under test);
2. **complex-step** — `f(x+ih)/h` imag part, h=1e-30 (exact, no cancellation — the gold oracle for holomorphic f);
3. **FD (central)** — independent implementation, ~1e-6.

Result: analytic ≡ complex-step to **< 1e-10**, analytic ≡ FD to **< 1e-5**, on holomorphic functors; inverse-func
functors gated analytic ≡ FD. Per-rule slopes checked vs an independent `std::` reference to ≤ 1e-12.

## Hardening (Ceres-faithful edge table, pinned by tests)
- `pow` (branchless Ceres slope `p·x^(p-1)`): `x≠0,p=0` → slope 0; `0^p` (p>1 → 0, p=1 → 1, 0<p<1 → +∞); the exact
  `(0,0)` point is a genuine 0·∞ singularity → **slope NaN (Ceres-faithful — Ceres returns NaN here too)**; negative
  base integer exponent keeps the base-slope, exponent-slope NaN; `sqrt'(0)=+∞`; `abs'(0)=+1` (subgradient).
- Complex-step is NOT authority at kinks — those edges use FD + curated singular inputs (fed through a runtime
  helper). **Scar:** an earlier *branched* `pow` let MSVC /O2 mis-select the not-taken `0/0`=NaN path; the branchless
  Ceres form (correct everywhere, singular only at the true singularity) has nothing to miscompile.
