## The tt_svd loss that got FIXED (rule #9: solve, don't record)

First cut: smooth 32^4 measured **0.53x vs tntorch (378.66 vs 199.14 ms)** and the small
tt_svd rows were only thin ties (1.02x/1.05x). The lever (measured, not guessed): the WIDE
first unfoldings (32 x 32768) — hesap-dense `svd()` bidiagonalizes the full tall transpose
and accumulates Demmel-Kahan rotations into a 32768-row U; MKL gesdd takes a QR-first path.
Fix at the consumer (tt.hpp, `rest >= 2m` unfoldings): **QR of C^T (tall, SIMD panel), SVD of
the small m x m R^T (its left vectors ARE C's left vectors), carry = U_r^T @ C by one gemm —
no Q formation at all** (U_r^T C = S_r V_r^T exactly). 378.66 -> **31.92 ms**; every tt_svd
row flipped from tie/loss to 2.8-6.3x WIN. Accuracy unchanged (backward-stable QR; all 280
oracle-gated assertions green, per-point gates at 1e-10 still pass).

## The 6D kernel probe (an honest wall, jointly measured)

The first demo kernel (softened overlapping two-body, `1/sqrt(0.05+|r1-r2|^2)` on [-1,1]^6)
is NOT rank-12-compressible: ours val_err 4.35e-1, **tntorch val_err 4.42e-1 on the identical
budget** — the same failure, so it is the KERNEL's TT-rank across the r1|r2 edge, not an
implementation gap. Demo switched to the true ephemeris regime: separated bodies
(r1 in [-1,-0.2]^3, r2 in [0.2,1]^3, exact `1/|r1-r2|`, no softening) — analytic on the
domain, rank-12 reaches 1.1-1.9e-4, BELOW the 16-point grid's own multilinear interpolation
error (~4e-3), i.e. the compression is free at LUT accuracy.

## The flagship LUT demo (v13-interp regime): 16^6 two-body potential

TT built from **19,008 function evaluations** (0.69 ms, one sweep pair) — the 16.7M-point
tensor is never materialized during the build.

| metric | TT (ours) | dense LUT (materialized grid) |
|---|---|---|
| storage | **75.0 KB** (9,600 params) | 128.0 MB (16,777,216 f64) |
| compression | **1748x** | 1x |
| build | 0.69 ms + 19K evals | 16.7M evals |
| accuracy vs truth (100k grid pts, max rel) | 1.45e-3 | exact at nodes; ~4e-3 multilinear between nodes |
| 1M CONTINUOUS interpolated evals (the hot path) | **226.1 ns/pt** (tt_eval_lerp) | 338.2 ns/pt (64-corner gather-blend) | 
| 1M raw grid-index reads (honesty row) | 143.5 ns/pt | **10.7 ns/pt** |

Reading: in the real v13-interp hot path (continuous points -> multilinear interpolation),
the TT is **1.50x FASTER than the dense table it replaces** while being 1748x smaller — the
64 scattered gathers from a 128 MB table (TLB-hostile, the 2026-07-04 scar in reverse) cost
more than d=6 rank-12 slice-blend matvecs on 75 KB of L2-resident cores. The raw
integer-index read is the dense table's one remaining win (10.7 ns single gather) — stated
plainly; if a consumer only ever reads exact grid nodes and can afford 128 MB, a flat table
wins that access pattern. `tt_eval_lerp` == dense multilinear interpolation exactly (the
tensor-product linear functional factors through the cores — gate-enforced at 1e-12).
