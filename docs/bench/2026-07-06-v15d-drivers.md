# 2026-07-06 — v15-d: forward-mode drivers + runtime-n tiling — crush + determinism

**What shipped (`drivers.hpp`):** the agent-facing forward-mode entry points over the SIMD vector-forward carrier —
`gradient` (∇f), `jacobian` (m×n), `jvp` (J·v, one Dual pass), `directional` (∇f·v). **Runtime-n tiling:** an
arbitrary-length gradient is strip-mined into ceil(n/W) SIMD passes of `JetPackD<W>` (W a compile-time tile width,
default 8; n a runtime arg — separating the two things Ceres conflates), ragged final tile seeds only its valid
directions. **Allocation-free** (the caller owns the `Span<JetPackD<W>>` jet workspace — no hidden malloc). No Eigen.

## Determinism moat (`test_drivers.cpp`)
Each output partial ∂f/∂x_k is computed in its OWN SIMD lane by a per-direction chain that never mixes with other
lanes (forward mode is per-direction independent). Consequence, tested exactly:
- **BIT-IDENTICAL across tile widths** W=4 vs 8 vs 16 (including ragged tiles at n=13) — `WithinAbs(…, 0.0)`.
- This is the SAME per-lane / per-direction independence that makes it **bit-identical across {1..16} parallel
  workers** (a batched driver over crd-jobs writes each point's gradient to its own slot — no reduction order); the
  explicit {1..16} worker sweep lands in v15-z's conformance close.
- Matches the scalar `Jet<T,N>` driver to ≤1 ulp (single-rounded fma vs mul+add — the correctness oracle) + analytic.
