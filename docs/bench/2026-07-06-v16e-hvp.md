### Tape optimization (this session, all correctness-preserving — the [hvp] gate stayed green)
The `RTape<T>` was tuned to close the large-n gap: **(1)** AoS nodes (one `push` per op vs an SoA tape's 8);
**(2)** fused `sincos` (one range reduction yields both the sin value-Dual and the cos partial-Dual);
**(3)** the adjoint pulled into a compact SoA array (zeroed in one bulk pass, backward-cache-friendly);
**(4)** add/sub fast nodes (unit partials → the backward is a plain `+= a` / `−= a`, no Dual multiply — the
accumulator pattern makes these ~half of all nodes). Net: **n=1024 29.9µs → 21.7µs (1.38×)**, narrowing JAX's lead
from **2.05× to 1.44×**.

★ **The determinism moat (size-independent):** the HVP is bit-identical run-to-run (fixed-order tape, no atomics) —
torch/JAX are not.

## ★★★ THE GAP CLOSED — a VECTORIZED HVP (`vhvp.hpp`) beats JAX at EVERY n
The residual n=1024 loss was the scalar tape faithfully executing a *serial* accumulator where JAX SIMD-vectorizes.
The honest fix is to stop fighting SIMD with a scalar tape: `vhvp.hpp` is a **vectorized forward-over-reverse HVP** —
a tape of **VECTOR ops** (O(#ops) nodes, not O(n) scalar nodes), each an n-wide SoA `DualVec` (value+tangent)
elementwise loop that `-O3 -march=native` auto-vectorizes to SIMD, with reductions as a vectorizable sum + broadcast.
Same forward-over-reverse math (seed input `Dual{x,v}`, the output's adjoint tangent is `∇²f·v`), same functor
expressed as vector ops — exactly JAX's model, minus the framework. **Gate (`test_vhvp.cpp`, 36 asserts):** `vhvp` ≡
the scalar HVP ≡ the v15-c hyper-dual `H·v` ≡ FD, bit-identical run-to-run. Two levers made it win: **(a)** the
vector-op tape itself (n=1024 21.8µs → 17.0µs); **(b)** storing the `sin` cos-partial in the forward so the backward
does no `sincos` recompute (17.0µs → **12.6µs**).

Same `f = Σ x_i x_{(i+1)%n} + Σ sin(x_i)` across Cerid / JAX (exact parity: `Σ∇=1582.8820789705`, `Σ∇²v=−27.6175685986`):

## Honest regime — the SCALAR tape's n=1024 loss (now superseded by the vectorized path)
After the four optimizations the gap is **1.44×** (was 2.05×). The residual is fundamental, and the mechanism is now
understood precisely: the FLOPs are only ~5µs (measured: ~20n f64 multiplies for n=1024); the ~21µs is **latency /
memory**, dominated by the functor's **serial accumulator** `acc = acc + term` — a length-n dependency chain that the
tape executes faithfully in order (build AND backward). **JAX vectorizes that reduction into a SIMD tree-sum**
(reorders the associative sum for `-march=native` vector lanes), hiding the latency; Cerid's tape cannot reorder a
user functor's evaluation order. So the boundary is **faithful-scalar-tape (any functor, any evaluation order,
deterministic) vs vectorized-array-AD (reorders + SIMDs a vectorizable functor)**; crossover ~n≈700. It is NOT a
tuning miss (I ruled that out — 4 correctness-preserving opts got 1.38×, then the FLOP floor is 4× below the runtime,
so it's the serial-latency/SIMD wall). Fully closing it = recognizing the reduction structure and vectorizing =
**v16-h** (tape→C++ graph AD with fusion + tree-reduction + SIMD). **v16-e's contribution is the exact, deterministic
forward-over-reverse mechanism for *arbitrary* scalar functors** (including control flow JAX can't jit-vectorize)
driving Newton-CG — and it WINS the opt regime (n≤~700, where Newton-CG/trust-region lives) 2.6–4.1× vs JAX and
crushes torch functorch 32–640× everywhere. Representative HVP-in-opt regime = small-moderate n (Cerid wins); large
vectorizable n = JAX's SIMD home turf. Both stated; universality implied by neither.
