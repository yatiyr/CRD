# Contributing to Cerid — four routes and one handoff

<!-- doc-role: reference -->
> Contract for REPO.DEV.10. Status lives only in [ROADMAP](ROADMAP.md#slice-repo.dev.10); rules in
> [AGENTS](../AGENTS.md); commands and the local decision table in [BUILDING](BUILDING.md); the close-out procedure in
> [docs/README](README.md#close-and-hand-off). This page adds the routes, the ownership path and the publication boundary.

## Before any route

Orient through [START_HERE](../START_HERE.md): [context](../context.md) names the row, the row names its contract, and
the [systems map](systems/README.md) names the module's public source, its `crd_module()` row in the root
[CMakeLists](../CMakeLists.txt) and its tests. Every change is a reviewable diff plus a proposed Conventional Commits
message; nobody but the maintainer commits or pushes ([publication handoff](#publication-handoff-human-only)).
Local verification follows BUILDING's decision table, one primary configuration for the changed modules and their
consumers; the hosted lanes own the matrix.

## Route 1: a module

1. Add or change the registry row (`crd_module(<dir> [<bin>] DEPENDS ... TESTS ... TEST_DEPENDS ...)`); the
   [module registry](design/module-registry.md) contract explains selection, closure and the verification pass.
2. Give the module a row in the [systems map](systems/README.md); the validator holds the map and the registry to
   one set of names.
3. Public headers compile alone through the consumer view: `check-headers.py --build <dir> --changed`
   ([public consumption](design/public-consumption.md)); a header that cannot needs `crd_public_header_exclude()`
   with a reason, not silence.
4. Tests live under `tests/<family>/<module>` and are declared in the row's `TESTS`; a loader that ingests bytes
   gets a fuzz target with a committed corpus ([test instruments](design/test-instruments.md)).
5. Run `test-module-selection.py`, the module's suite and the affected consumers; write the session record and
   the owning ROADMAP row's evidence.

## Route 2: a bug fix

1. Reproduce first ([SANITY](SANITY.md)); a source concern is not a defect until it runs. Find the owner with
   `python scripts/check-master-plan.py --find <symptom>`; a third-party defect goes through the
   [register](third-party-defects.md) and its two-sided gate, never a skip.
2. Fix in the owning module, add the regression to the owning suite, keep every oracle and count.
3. Verify with the decision-table row that matches the change; record the reproduction, the fix and the
   verification in the session; update the owning row.

## Route 3: an asset or program

CEIR, CKIR and CHIR assets and demo content are canonical UTF-8 text checked by `check-repository.py`; an
operation definition is TOML under `engine/execution/ceir/ops/` and its C++ is regenerated with
`tools/ceir_opgen/ceir_opgen.py` (`--check` proves the committed output). A shipping algorithm is an editable asset
with a replacement path, never a demo that bypasses the asset. New demo assets record their license in
[assets/source/LICENSES.md](../assets/source/LICENSES.md). Loader-facing formats add corpus inputs to their fuzz targets.

## Route 4: a build-system change

`cmake/**`, the presets, the tier map, the pins and the generated sources each have a guard that runs on every
lane: `check-ci-tiers.py` ([CI tiers](design/ci-tiers.md); a preset without a tier fails), `check-pins.py`
([pinned inputs](design/pinned-inputs.md); a new dependency is a registry entry with version, source, SHA-256 and
license, then two steps: `gen_license_manifest.py` re-renders the [license manifest](generated/dependency-licenses.md)
and `check-generated.py --refresh docs/generated/dependency-licenses.md` records its bytes),
`check-generated.py` (below), `test-module-selection.py`, `test-native-build-profiles.py` and the
[project-structure synchronizer](design/project-structure-sync.md) for moved sources. A push that touches these
paths resolves to the complete tier, so every owned preset runs hosted.

## Generated sources and provenance

Every committed generated file is named once in [scripts/generated-sources.json](../scripts/generated-sources.json)
with its generator, its status and the SHA-256 of its bytes; [check-generated.py](../scripts/check-generated.py)
fails a lane when a listed file changed without a refresh, when a file carrying a generation marker is unlisted, or
when a generator named by a non-absent entry is missing. Statuses: `reproducible` (regenerated byte-for-byte on the
reference host, Linux glibc with Python 3.12), `formatted` (the generator's output through the repository's
clang-format reproduces the bytes: the ERK tableaus), `host-dependent` (the FFT codelet twiddles come from the
host's `cmath`, so Windows renders them one ulp apart), `network-sourced` (the ARK tableaus are read from upstream),
`hand-maintained` (the generator was the origin, the file is the truth: the AoS codelets), `drifted` (the generator
no longer emits the bytes and no decision has been taken; the entry names the owning row), `generator-absent` (a
scratch script that was never committed; the bytes are the artifact) and `measured` (a GPU tuning database). Every
status but `drifted` is a declared property that needs no owner. Regenerate deliberately, in this order: run the
generator on the reference host, inspect the diff, run the owning suite, then `check-generated.py --refresh
<path-or-directory>` (a directory refreshes every entry beneath it, so a regenerated CEIR dialect or a re-rendered
document is one command) and say why in the session. `--regenerate` reruns the stdout generators, applies the
formatter of a `formatted` entry when clang-format is on the host, and runs the `--check` commands; `--scan` lists
unlisted markers. Never hand-edit a `reproducible` or `formatted` file; a `hand-maintained`, `drifted` or
`generator-absent` file changes only with a decision recorded against the row that owns the module.

## Ownership and review route

Ownership is a public module, its contract and a human review route: module → registry row → systems-map row →
owning ROADMAP row → the maintainer. There are no teams, no CODEOWNERS file and no pull-request templates, because
there is one maintainer and no pull-request review flow: the maintainer pushes to `main` (the workflow also runs on
pull requests that target it). An agent, a helper script, a bot or a delegated worker never holds merge rights, and
a machine-recorded content hash or patch bundle is provenance, not a commit.

## Publication handoff (human-only)

An agent hands over the working tree as a reviewable diff, a Conventional Commits message without any co-author
trailer, the dated session record with its evidence and limitations, and the updated owning row. The maintainer
reviews, commits and pushes to `main`; the workflow's tier resolver decides from the changed paths whether the push
runs the change tier or the complete tier, and `Needs CI` rows carry the local evidence until the published run is
green, after which they become Done or Recorded with that run as evidence. A red lane preempts slice work: its
diagnosis and repair come first, on a new push by the maintainer. No purchase, runner registration or publication
setting is inferred from a quality goal ([research](research/2026-09-12-large-cpp-development-and-ci.md#documentation-and-ownership)).
