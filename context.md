**2026-05-18 — Phase 3.1.7 v9a-c-followon "Track A elite rewrite" (fat-node 64 B + dual-output paths) ✅**. The v9a-close cluster had pinned 53.7 ms / 1M end-to-end as honest baseline; advisor + user push surfaced that this was 30× slower than KittenGpuLBVH (~1.5 ms / 1M on RTX 3090) and the published target was reachable. Elite rewrite swaps the compact 32 B `BvhNode` + canonical-reorder layout for the **KittenGpuLBVH fat-node 64 B `LbvhFatNode`** layout — both children's bounds inline in the parent's struct (one cache line per internal node), siblings NOT consecutive. Carry-register upsweep replaces the per-level barrier walk: each leaf-thread holds its bounds in a register, walks up via `parent_idx`, writes into `parent.bounds[isRight]`, atomicAdd on `done[parent]` for sibling-rendezvous, unions and continues. **Two output paths**: (a) `dispatch_build_lbvh` → CPU `LbvhTree` (with 64 MB readback); (b) `dispatch_build_lbvh_gpu_resident` → handle referencing pipeline-owned GPU buffers (no readback, intended for eylem broadphase / GPU traversal / occlusion culling). **Perf at 1M / RTX 4070 Ti SUPER (win-shipping, median-of-5) — full v9a-c stack + v9b refit:** CPU-output **~20.0 ms** (28% gain); GPU-resident **~6.7 ms** (76% gain); **GPU-inputs `dispatch_build_lbvh_from_gpu`: 1.45 ms** — **MATCHES KittenGpuLBVH's published 1.5 ms on RTX 3090 despite our card having ~40% LESS memory bandwidth**. **🎯 v9b GPU REFIT: 0.98-1.09 ms** — sub-1ms per-frame refit cost (rebuilds bounds only, topology preserved); ideal for eylem dynamic-body broadphase at 60 FPS (<6% frame budget for 1M bodies). 16 test cases / 402K assertions / 5-config DoD PASS. v9a-c-persistent-threads kernel kept compiled as documented future-option (bandwidth-floor proven; same scheduling pattern as flat dispatch on random scenes).
