# ThreadSanitizer suppressions for the linux-clang-tsan preset (DIAG.1b).
#
# Only third-party libraries that are not built with -fsanitize=thread belong here. TSan cannot see the
# happens-before edges their own atomics create (shared_ptr counts, driver-internal hand-offs), so their internal
# synchronization reads as races. Engine and test code is never suppressed: a report in Cerid code is fixed.
# Evidence: docs/sessions/2026-10-05-clang-werror-and-tsan-inventory.md.

# Mesa lavapipe, the hosted Linux Vulkan device: its worker threads' mutex lifetime ordering.
race:libvulkan_lvp.so
# lavapipe's JIT backend (Mesa links LLVM 20): its llvmpipe-N worker threads allocate and free the same buffer
# (llvm::allocate_buffer, then delete) after a hand-off TSan cannot see; the report names only libLLVM and the
# allocator interceptors, lavapipe appears only in the thread-creation stacks, which suppressions do not match.
# Nothing in Cerid links LLVM. Run 38209499793, CEIR-17d GATE (crd-scene-render-tests).
race:libLLVM.so

# Khronos validation layer: its queue-retire thread and DestroyFence order fence state through shared_ptr counts.
race:libVkLayer_khronos_validation.so
# The same layer takes two of its object-tracker locks in opposite orders (RegisterPoisonPairs at descriptor-set
# allocation against MakePoisonous at destruction); both locks and both paths are inside the layer (pinned 1.4.341).
deadlock:libVkLayer_khronos_validation.so
